## 1. 目标与已确认边界

Studio 从“LLM 分析 → 生图 → 视频”转为“项目配置与契约 → Codex 材料编译 → 本机文件就绪 → Studio 生产”。用户不再把 Codex 的输出搬回 Studio 猜格式、导入解析。

- 项目列表增加搜索、筛选、排序。
- 新建项目以分步向导完成；选项有可见默认值，最终确认后生成 Codex 任务模板、项目锁和契约。
- 模板写入**本机绝对项目路径、完整技能包路径、输入路径、材料路径和媒体输出路径**。
- Studio 界面和运行链路移除 LLM 分析、提示词改写等文字模型调用；图片、视频服务商保留。
- 资产和集使用可展开的树、复选框、搜索、筛选，默认全选。共享资产按唯一 ID 复用，不按集重复生成。
- 用户已确认：第一版按功能包隐藏页面和入口，**不做多人账号与权限认证**。
- 本轮交付架构与可点击原型；不修改正式运行逻辑，不创建真实生产项目，不提交付费生成。

评审暂按以下假设呈现，尚未获得确认：模板由用户交给 Codex；旧项目可继续查看和生产，新项目统一采用 v7.0。若后续选择 Studio 自动启动 Codex，另增加可选连接器，不让它成为项目文件契约的前提。

## 3. 页面和主要使用路径

全局导航：**项目 / 生产 / 产物 / 设置**。当前项目切换器位于全局顶部，切换时携带各自的技能版本、筛选与生产范围。

### 项目

- 搜索项目名、编号、标签、目录；筛选进度、技能版本、是否存在阻塞、归档状态；按最近活动/名称排序。
- 行显示项目名、所在路径、技能锁版本、材料状态、生产进度、最近活动与下一步动作。
- “创建项目”打开五步向导；批量创建可作为功能包开启，复用同一配置，不新增另一套隐蔽默认值。
- 状态有明确来源：待 Codex / 材料写入中 / 材料待修订 / 可生产 / 生产中 / 有失败 / 已交付。不能把 Codex 留下一段说明文字当作完成。

### 创建向导

1. **项目与输入**：名称、自动编号、生产根目录、来源类型、剧本、集数策略。
2. **画面与创作边界**：媒介、风格、文化背景、改编权限、补充要求。
3. **视频与声音**：生产预设、模型/平台、比例、目标 SEG 时长、语言、声音、字幕。
4. **技能与范围**：锁定完整 v7.0 包，必要资产按剧情决定，已有资产复用，Codex 可选交付物和全选生产策略。
5. **确认与创建**：汇总显式值、继承值和待核实能力；确认实际绝对路径。创建成功即提供 Codex 模板及“等待材料”的项目状态。

所有选项有默认值，但**必须提供的业务内容不伪造**：项目名可自动编号；剧本可现在提供或“稍后补充”，后者能建项目，Codex 编译前仍须补原文；未知服务商能力允许建项目，不允许未经核实就提交不匹配的生产参数。

### 生产

树形选取 + 搜索筛选 + 选中项详情 + 生产计划。默认勾选全部合法生产任务，已完成且版本匹配的资源复用；新建空项目等 Codex 发布材料后才出现资产条目。

### 产物

沿用同一棵资源树查看图片、视频、失败、依赖、版本、输出路径及验收状态。可以定位文件、用已有合格文件补回任务、重试取回结果、生成 Codex 修订请求。预览时检查文件可读，不能仅凭存在或大小算完成。

### 设置

项目默认值、完整技能包管理、图片/视频服务商和凭据、生产并发、功能包。普通生产页面只显示本次所需选项。功能包是展示和能力开关，不叫“账号权限”。

## 4. 默认值与完整技能包的关系

优先级：**用户本次显式设置 > 项目已锁定值 > 保存的用户预设 > Studio 建议值**。创建时展示来源；一经确认写成具体值和 options hash，不在 Codex 运行时偷偷变化。

| 选项 | 初始建议/来源 | 约束 |
|---|---|---|
| 技能 | 完整 v7.0老李，锁 ZIP 摘要 | 升级须创建新计划版本，运行中的批次保持原锁 |
| 来源 | 剧本；集边界按原文识别 | 可覆盖总集数与目标单集时长；不得从例子伪造集数 |
| 媒介 | 沿用现有默认“真人短剧” | 3D 漫剧、二维、混合及自定义可选 |
| 风格、文化背景 | 按原文判断 | 六种美学预设是可选，不强迫选“港派/国漫”等 |
| 改编 | 保留事实、关系、动机和结局，允许优化节奏/镜头 | 实质改编须用户选择授权 |
| 平台/模型 | 沿用已保存的图片/视频预设 | 没配置时显示待设置，不内置虚假“可用账号” |
| 视频比例、SEG 时长 | 优先沿用预设；原型起始值为 16:9、30 秒 | 这是待确认的产品建议，不是 skill 强制值；不支持时明确冲突，不静默换比例/拆段 |
| 人物 4 View | 16:9 | 不跟随视频比例一刀切；其他资产按用途决定 |
| 参考路线 | 已选路线优先，否则建议全能参考 | 能力待核实时阻止实际投喂，保留必要参考 |
| 提示词/对白语言 | 中文 | 自定义可选；不默认生成中英双份 |
| 声音 | 视频模型原生音频 | 能力不支持时待用户选择路线；不自动追加独立配音任务 |
| 字幕、额外旁白 | 字幕关闭；旁白不额外新增，原文已有内容按原文 | 不把“无字幕”解释为画面不能出现环境文字 |
| 衣服独立资产 | 按剧情/复用需要自动判断 | 可选独立 COST 或完整 LOOK |
| LOC/SCSTATE、ABC、顶视图 | 按 skill 的复用、空间和关联规则自动规划 | 不每 SEG 造母图，不所有边界强制 ABC；必要项不能因 UI 精简省略 |
| 既有资产 | 优先使用登记且版本/用途匹配的资产 | 不拿任意同名文件直接充当完成 |
| Codex 任务深度 | 可生产材料（planned） | 绝不把 planned 标成已有实图 |
| 图册/离线看板/情绪曲线/报告 | 默认不额外交付 | 仅选中才生成；内部必要审计照常做 |
| 生产选择 | 默认全选，已完成项复用 | 全选不等于全部重新计费生成 |

完整规则包还包括：剧情/台词/表演、动作/术法/兵器、运镜/光线/美学、模型/投喂/质量等规则族。Codex 依据剧情读取适用 references；Studio 只提供输入选项、记录所用版本和消费输出，不复刻一套语言推理引擎。

## 5. 资产树：逻辑树与磁盘目录分别负责什么

推荐默认以“资源用途与实体”组织，另提供“按集”和“按磁盘目录”视图。同一资源可以出现在多个视图中，但只对应一个资源 ID、一项勾选状态和一个输出文件。

```text
项目
├─ 全剧共享
│  ├─ 人物
│  │  └─ 角色名 → 身份 CHAR/PH → 造型 LOOK/LK / 服装 COST / 连续状态 CT
│  ├─ 场景
│  │  └─ 地点 LOC → 当前状态 SCSTATE（适用 EP/SEG 可多选）
│  ├─ 道具 PROP（skill PRP）
│  ├─ 生物 CRE / 群体 GRP / 载具 VEH / 特效 VFX（仅有实际任务时显示）
│  └─ 声音身份 AUD（原生音频时是说明记录，不是自动生成音频的任务）
└─ 分集生产
   ├─ EP01
   │  ├─ 交接边界 SEG01 → SEG02 → ABC 整板 → A / B / C 独立图
   │  ├─ 分段视频 → SEG01 / SEG02 / SEG03
   │  └─ 成片（有选择才执行）
   └─ EP02 → …
```

skill 的 CHR/PRP/SCN 是语义分类；现有执行器的 CHAR/PROP/LOC 等是 ID 家族映射。映射表由版本化契约声明，不能直接猜字符串。声音身份不伪装成 image；板块内部 A/B/C 的语义不能用同名字母的角色等级代替。

磁盘继续复用 `02_固定资产/<家族>/`、`03b_场景状态图/`、`04_交接板/区域图/`、`05_分段视频/`、`06_成片/`，避免把旧图片搬进新层级后断引用。树上的折叠/筛选不是移动文件。

勾选与筛选规则：

- 父节点全选/部分选择/未选三态；列表隐藏节点不改变其勾选状态。
- 搜索名称、ID、人物、场景、文件名；筛选类型、集、状态、是否阻塞、待生产/已生成。
- “选中当前结果”只作用于当前筛选结果；显示“全项目已选 X / 当前显示 Y”。另设明确的“全项目全选”。
- 选择 EP 时展示该集引用的共享资产视图，不复制资产；多集引用同一资产只生成一次。
- 取消未完成的必需父资产而仍选择下游：下游标阻塞。用户可“补选必要依赖”，或取消受影响下游；不能静默补选、少传参考或偷偷付费。
- 取消已完成父资产只是不重做，仍可复用经校验的匹配版本。
- 发布新计划出现新任务时，未启动的选择草稿默认选中新任务并显示新增数；已运行批次保持冻结快照，不自动扩大。
- 所选任务与“可立即提交”的数量分开。派生、视频和跨段实际尾帧核验必须按依赖和验收状态推进。

### 字段职责

新 `tasks.json` 的 schema 建议为 `studio.production-plan/v1`，复用现有 worker 需要的 `key / output / prompt_ref / params / reference_images / handoff_refs / board / region`，保留 `asset_tasks / scstate_tasks / board_tasks / region_tasks / video_tasks` 分类。增加明确的项目、计划版本、配置摘要、资源索引和分集关系。新项目不生成 storyboard_tasks；旧项目由兼容读取器处理。

资源索引最少包含 `asset_id、display_name、semantic_type、entity_id、parent_id、episode_ids、task_key、version`；任务引用仍是权威，不让目录层级替代依赖边。声音说明等非生产记录明确 `task_key=null`。

权责：Studio 写设置/契约、执行状态和媒体；Codex 写新材料版本、提示词及完整性回执。双方不同时改一份状态文件。Codex 不覆盖旧计划或运行中提示词，新修订写 r0002；运行中的批次继续使用 r0001。

### 自动发现不等于自动计费

1. 创建项目：先检查同名目录、路径和写权限，成功后才发布项目索引和 Codex 模板。
2. Codex 按 P0～P4 编译 planned 材料，在唯一发布版本内暂存、校验，最后写 READY。
3. Studio 监听 READY，并在启动/手动刷新时补扫；只有半写文件、没有 READY 时显示“材料写入中”，不加载生产。
4. 严格检查 schema、项目 ID、参数/技能摘要、引用闭合、ID 和输出路径唯一、无环、文件哈希、ABC 同源、参考编号。不做自然语言排版猜测或静默字段修正。实际接口能力单独核验：未知或不匹配时可查看材料和任务树，相关生成任务保持阻塞。
5. 材料结构与引用验收通过，原子更新 active-plan；界面自动出现任务树。接口能力、实图、视觉和成片分别显示各自验证状态，材料激活不表示所有生产门禁已通过。
6. 用户审阅选择和依赖计划后点击“开始生产”。默认全选不代表发布材料立即花钱。
7. 失败修订包定位具体任务、父依赖、原因和文件；Codex 直接在该项目写下一版。未变化的已验证资产继续复用；变化的输出升版或明确提示需重做，不覆盖已核准结果。

模型能力、空间语义、ABC 首尾与成片声音不能仅靠 JSON schema 证明。可自动验证的部分自动验证；需要语义/视觉核验的层标“待验收”，由人工或 Codex 检查结果驱动，不能虚构通行证。

## 8. LLM 移除清单与功能包

- 自动软化/重写提示词、LLM 诊断重写、语言模型驱动的字幕优化和翻译。
- 旧提示词模板编辑器中专供 Studio LLM 的模板，不再作为新产品页面。
- 图片/视频模型配置、请求重试、结果重取、上传压缩、引用校验、并发、拼接、日志继续保留。
- 字幕如启用，可保留转写、SRT/ASS 导入、样式与烧录；文案修改/LLM 翻译交给 Codex。后期音频路线如果暂无实际执行能力，必须显示为外部交付或待实现，不给假“开始”按钮。
- 构建配置 codex-only：服务端不注册 LLM 执行路由，生产服务不实例化 LLM。旧源码模块可暂保留用于回滚，但不通过功能包开关悄悄恢复。

| 阶段 | 交付与验收 |

| D 资源树与依赖 | 全选/半选/筛选/跨集共享不丢选择；取消父项产生具体阻塞；完成资源不重复收费；ABC 与视频按 skill 执行 |
