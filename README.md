# 剧本 → AI视频 自动化生产台

skill《AI短剧自动化生产体系 V6.1》的**可执行具象化**：本地 Web 程序，编排逻辑是确定性代码，
只有剧情分析走 LLM API。前端选服务商 / 设并发，后端多线程跑，产物落盘成标准生产包。

```
Claude Code / Codex（skill 迭代设计）
        │  升级后把规则编译进 prompts/
        ▼
   本地生产台（本程序）───▶ 标准生产包
        ▲                        │
        └──── 拉回目录做验收优化 ◀┘
```

## 启动

```bash
pip install -r requirements.txt      # 只有 requests；Pillow/imageio-ffmpeg 可选
python run.py                        # 浏览器自动打开 http://127.0.0.1:8770
```

首次使用：**设置**页填服务商 key → 点「运行自检」（只拉模型列表，零生成费用）→ 四项全绿即可开工。

## 五个页签

| 页签 | 做什么 |
| --- | --- |
| **项目** | 项目列表 / **批量建剧**（一次拖入多个剧本 = 一次建多个项目）/ 单个粘贴正文 |
| **流程** | 项目参数 + 十二环节。环节 1-8 点「执行」调 LLM 分析，产物落 `01_剧本与分段/*.json` |
| **生产** | 资产图 / 故事板 / 分段视频三类任务。**每类独立选服务商、模型、并发数**；下方是**全局任务面板**，含其它项目的运行中任务 |
| **产物** | 图片视频缩略图预览；一键生成人工复核清单、硬切拼接成片 |
| **设置** | 服务商凭据、LLM 分析引擎、**并发闸门**、默认参数、自检 |

## 多剧并行

**批量建剧**：把 N 个剧本文件一次拖进「项目」页 → 逐个解析并列出（可改项目名、剔除某个）→ 点一次创建 N 个项目，编号自动排 `BT-001 / BT-002 …`。某个文件解析失败只影响它自己，其余照常创建。

多个项目可**同时开工**，互不影响：

- 每次「开始」创建一个独立 job，在自己的线程池里跑；切换项目、关闭页面都不会中断
- 「生产」页的任务面板是**全局视图**，列出所有项目的运行中任务（可勾选「只看当前项目」）
- 顶栏常驻**并发仪表**：`并发 3/8 · 运行 2` = 当前 3 个 API 调用在途、上限 8、2 个 job 在跑

## 并发怎么控制（三层闸门）

```
① 批内并发    每批任务自己的线程池       生产页每行的「并发」输入框
② 服务商配额  同一服务商的跨项目总量     设置页 · 每家一个数
③ 全局总闸    所有在途 API 调用的总量    设置页 · 一个数
```

任务真正发请求前，依次获取 **服务商配额 → 全局总闸**，拿不到就排队（状态显示 `queued`）。

举例：三个项目各设批内并发 5（共 15），服务商配额 paisio=6、全局=8 → 同时在途最多 **6 个** paisio 请求，且全部服务商加起来不超过 8。改上限对新任务立即生效，在途任务不受影响。

重试不额外占槽——同一任务的重试在已获取的槽位里串行完成。

## 停下来之后怎么继续（核心机制）

**磁盘是唯一真相源。** 关浏览器、重启服务、换电脑，进度和失败记录都不丢。

### 「流程」页顶部的续跑面板

打开任意项目就能看到三样东西：

```
下一步：环节10「视频执行生成」（还差 6/17） —— 生产页 → 开始

 1 整剧全局解析          完成      1/1
 …
10 视频执行生成          部分完成  11/17   ← 卡在这
```

底下列出**还没处理的问题**，同一个毛病影响 20 条也只显示一张卡：

```
⛔ 这家服务商的账户没钱了     这些没做出来：共 6 条 —— EP01-SEG12、EP01-SEG13 等
   怎么回事：服务商说你的余额或套餐额度不够了。程序已经自己停下来，
             后面还没做的任务一个都没发出去，不会继续扣钱。
   去哪改  ：先去服务商网站充值，再回「设置 → 服务商」看一眼 key 没被改过
   怎么改  ：1. 打开这家服务商的网站，登录进去看余额还剩多少
             2. 充值；不想充的话，去「生产」页把这批任务改成用另一家来做
             3. 如果用的是别人分给你的 key，可能是这个 key 自己的额度用完了，换一个
   改完怎么接着跑：充完钱回「生产」页，点这一行的「开始」。
                   已经做好的会自动跳过，只补没做完的，不会重复花钱。
   ▸ 原始报错（看不懂可以忽略，排查时用）
```

写这些文案有条硬规矩：**不许出现「熔断」「鉴权」「上游」「轮询」这类词**。
读的人可能第一次接触这些概念，看不懂就等于没提示。测试里有一条专门扫黑话，
往 `CATALOG` 里加错误码时会被一起检查。

### 续跑的三种粒度

| 想做什么 | 怎么操作 |
| --- | --- |
| 补全所有未完成的 | 生产页 → 对应行「开始」（已存在的输出自动跳过） |
| **只重跑失败的** | 生产页 → 对应行「补失败」（读 failures.json，只跑记录在案的） |
| 重跑某一段 | 改完提示词后点「补失败」，或删掉该段输出文件再点「开始」 |

任务做成了会**自动把旧记录清掉**，面板上就不再显示，不用手动点「已处理」。

### 环节 1-8 也能续跑

环节 8（提示词编译）改成了**逐段调用**：17 段就是 17 次独立 LLM 调用，每段编完立刻存盘。第 10 段失败时，前 9 段的成果保留，重跑环节 8 只补失败的那些段。

其余 LLM 环节是单次调用，失败重跑即可（产物是单个 JSON，没有中间态）。前置产物缺失时会明确告诉你**先跑哪个环节**，而不是抛一句 KeyError。

## 错误提示长什么样

每条错误都翻译成一份结构化说明，而不是甩一串原始报错：

| 字段 | 内容 |
| --- | --- |
| `title` | 一句话说清出了什么事 |
| `why` | 为什么会这样、现在影响到哪些 |
| `where` | **去哪改**（精确到页面上的按钮名、或具体文件夹） |
| `fix` | **怎么改**（有先后顺序的动作，一步一句） |
| `resume` | **改完怎么接着跑**，以及会不会重复花钱 |
| `raw` | 原始报错，默认折叠 |
| `level` | `error` 没做出来 ／ `warn` 做出来了但可能不对 |
| `code` | 给程序用的错误码，**不显示给用户** |

16 类：`QUOTA_EXHAUSTED` `AUTH_INVALID` `ACCOUNT_BANNED` `RATE_LIMITED` `CONTENT_REJECTED` `PROMPT_INVALID` `MODEL_NOT_FOUND` `REF_MISSING` `PREREQ_MISSING` `LLM_SCHEMA_FAIL` `LLM_EMPTY` `NETWORK` `TIMEOUT` `DISK` `WRONG_RATIO` `UNKNOWN`

存放位置：`07_检查与记录/failures.json`（结构化）+ `execution_log.jsonl`（流水）。

### 「做出来了但可能不对」——出图后量一遍尺寸

有一类问题**不会报错**：接口返回 200、文件正常下载，只是画面躺倒了。
各家服务商对画面比例的处理不一样——有的按你给的像素尺寸出，有的要你显式发 `ratio`
字段，不发就用它自己的默认值（最常见是回落成横屏 16:9）。竖屏短剧拿到横屏视频，
不主动检查的话要等人工验收才发现，那时钱已经花完了。

所以每张图、每段视频出来后都量一次真实宽高，和你选的比例对不上就挂一条提醒：

```
⚠️ 做出来的画面比例，跟你要的不一样    东西做出来了，但可能不对：共 1 条 —— EP01-SEG03
   要的是 9:16，实际出来 1920x1080（约 16:9）。你要的是竖屏，出来的是横屏。
```

几个刻意的设计：

- **只提醒，不算失败**。文件保留，后面的环节照跑，你自己看了决定要不要重做。
- **允许 6% 偏差**。服务商常把 1024x1536 出成 1024x1520，这种几像素的出入不报。
- **重跑跳过时会重新量**。不然「跳过」会把提醒悄悄清掉，而文件其实还是那个躺倒的。
- **量不到就放行**。缺 ffprobe、格式不认识、文件损坏 —— 一律当没这回事，
  这只是加保险，不能反过来把主流程卡住。

图片直接读文件头（PNG/JPEG/WebP/GIF，不依赖 Pillow）；视频优先 `ffprobe`，
没有就退回解析 `ffmpeg -i` 的输出（`imageio-ffmpeg` 只带 ffmpeg 不带 ffprobe，
这条退路是必需的）。

## API 报错 / 额度不足怎么办

**不会一路失败到底。** 错误分三级，处理方式完全不同：

| 级别 | 典型情况 | 处理 |
| --- | --- | --- |
| `retryable` | 429 限流、5xx 网关、网络超时 | 同参重试 ≤2 次，429 尊重 `Retry-After` 头 |
| `task_fatal` | 400 内容违规、提示词超长、参数非法 | **不重试**（重试也没用），标记该任务失败，**其它任务继续跑** |
| `batch_fatal` | **余额不足**、密钥失效、账号封禁（401/402/403，或 200 响应体里带 `insufficient` / `quota` / `余额` / `额度` 等） | **立刻停掉整批**，剩下的任务一个都不发 |

### 为什么余额不足要停掉整批

不停的话，17 个任务会挨个撞同一堵墙，每个再重试 3 次 = **51 次注定失败的请求**，
既慢，又可能触发服务商的风控，有些服务商失败也照样计费。

停在第一个之后实测只发了 1 次（离线验证：10 个任务在第 3 个碰到余额错误，
总共只发了 3 次请求，而不是 12 次）。

### 断点续跑

程序遵守「输出已存在 → 跳过」，所以**修好问题后重新点「开始」即可**：

```
第一次：SEG01-05 成功，SEG06 余额不足 → 立刻停下，SEG07-17 一个都没发
充值后再点开始：SEG01-05 自动跳过（已经有了），从 SEG06 接着做
```

不会重复扣费，也不用手动挑哪些没做。失败的任务同理——修复后重跑只补失败的那些。

## 剧本文件支持

| 格式 | 方案 | 依赖 |
| --- | --- | --- |
| `.txt` `.md` | 多编码探测（utf-8-sig → utf-8 → gbk → gb18030 → big5） | 无 |
| `.docx` | stdlib zipfile 解 `word/document.xml`，按 `<w:p>` 切段 | **无** |
| `.pdf` | pypdf 优先，PyMuPDF 兜底 | `pip install pypdf` |
| `.doc` | 不支持，提示另存为 docx | — |

无扩展名的文件按魔术字节嗅探（`PK` → docx，`%PDF-` → pdf）。扫描件 PDF 提取为空时会明确报错提示需要 OCR，不会静默产出空剧本。

## 十二环节

| 环节 | 名称 | 类型 | 产物 |
| --- | --- | --- | --- |
| 1 | 整剧全局解析 | LLM | 全局剧情地图 + 视觉基调（含压缩版） |
| 2 | 节奏驱动段落划分 | LLM | 段落表（进入/退出状态、连接锚点、防剧透项） |
| 3 | 状态时间线管理 | LLM | 状态包 + 相邻段 exit/entry 一致性校验 |
| 4 | 资产提取与生产判断 | LLM | 五类资产 + must/conditional/skip 三分类 |
| 5 | 资产生产提示词编译 | LLM | 每资产一份完整提示词 |
| 5b | 资产图生产 | **出图** | `02_固定资产/` |
| 6 | 段落资产绑定 | LLM | 参考图映射表（每段从 Image 1 重新编号） |
| 7 | 高密度正式分镜 | LLM | 5-8 镜 / 180度轴线 / 七类硬切锚点 |
| 8 | 故事板与视频提示词编译 | LLM | 两类提示词 + **自动装配 tasks.json** |
| 9 | 故事板生成与固定 | **出图** | `04_故事板/` |
| 10 | 视频执行生成 | **出片** | `05_分段视频/` |
| 11 | 结果检查清单 | 本地 | 八层检查 + L1/L2/L3 分级，人工填结论 |
| 12 | 排序拼接与交付 | 本地 | `06_成片/` + concat 清单 |

## 执行纪律（与 skill 一致）

- 输出已存在 → **跳过不覆盖**（生成即固定）；要出修订版就改 tasks.json 的 output 为 `_V02`
- 技术失败**同参重试 ≤ 2**（可配）；内容质量不自动判定，只落记录
- 环节 10 是**纯执行节点**：不重新分析、不改写提示词
- 审美问题不重做；只对技术失败、结构性错误、连续性错误定向修订

## 新增服务商（不用改前端）

1. `core/providers/` 下新建 `xxx.py`，继承 `Provider`，实现 `capabilities()` 和 `generate_image/generate_video`
2. `core/providers/__init__.py` 的 `_CLASSES` 加一行

`capabilities()` 返回的模型列表、时长、画幅、备注会**自动出现在前端下拉框**。已内置：

| 服务商 | 出图 | 出片 | 实测备注 |
| --- | --- | --- | --- |
| 灵感鸭 lingganyaapi.com | ✅ gpt-image-2 | ⚠️ sora-2 通道随机失败 | 图片稳定，视频建议换家 |
| 派系 api.paisio.online | ✅ | ✅ sd2-pro-720p | 视频首选（实测 17/17 一次过）；也提供 claude/gpt 系 chat 模型 |

参考图统一用**压缩 data URI**（1024px JPEG q80）直传，绕开图床白名单问题。

## skill ↔ 程序 的同步方式

skill 在 Claude Code 里迭代成熟后，把变化编译到两处：

- **规则/schema 变化** → 改 `prompts/sN_*.md`（程序无需改代码）
- **流程/字段变化** → 改 `core/stages.py` 的 `STAGES` 与 `build_tasks()`

反向：程序跑完把项目目录交给 Claude Code，用 skill 做环节 11 的验收与优化建议。

## 迁移到其他电脑

拷走整个 `production_runner/`（`config.json` 含 key，按需决定带不带）。目标机只需
Python 3.9+ 和 `pip install requests`。`projects/` 默认在上级目录，可在设置里改。
