# 巨轮旧版热修复补丁

版本：20260921.1

这是 Studio 服务商外挂，不是密钥配置。适用于已内置巨轮、支持数据目录 `providers/` 外挂的旧版 Studio。无需替换 EXE，也无需安装 Python。

## 安装

1. 停止生产并退出旧程序，避免运行中的任务继续使用旧实现。
2. 在旧程序启动窗口查看“数据目录”。将补丁包中的 `providers/julun_result_hotfix.py` 放进该数据目录的 `providers` 文件夹；没有文件夹就新建。
3. 重新打开旧程序。仍选择原来的“巨轮 julun.cc”，沿用原来的 Key、模型和参数。

例如，数据目录显示 `D:\stv-data` 时，最终文件位置应为：

```text
D:\stv-data\
├─ config.json
├─ projects\
└─ providers\
   └─ julun_result_hotfix.py
```

只有当启动窗口的“数据目录”就是 EXE 所在目录时，才放在 EXE 旁的 `providers` 中。使用 `--data` 的要按实际指定目录安装；不要放进项目文件夹或 EXE 解压产生的临时目录。

不要将现有 `config.json` 替换掉，也不需要将 Key 填进补丁。若已经装了其他巨轮外挂，请先将旧巨轮外挂移到 `providers` 外备份，避免多个 `id=julun` 的插件相互覆盖；其他服务商插件保留。

## 如何确认生效

旧版设置页若提供“服务商插件/扫描结果”，巨轮来源应显示 `julun_result_hotfix.py` 的完整路径。扫描提示“覆盖了已有的同名服务商”是本补丁的预期结果；不应出现插件加载错误。

插件保持服务商 ID 为 `julun`，不会多出一个需要重新配置的服务商，也不会更换模型列表或改动提交、上传、下载实现。它继承旧 EXE 内置的巨轮实现，仅替换结果查询方法。

## 修复内容与边界

- 同时识别顶层返回的 `status/result_url/error` 和旧的 `data` 包装。
- 完成状态立即返回视频地址，交给旧程序下载；不再因为读不到状态而一直等到超时。进度为 95 但状态为 completed 时也能取回。
- 真正失败立即结束轮询，保留服务商错误原文、机器码和任务 ID。
- 一般生成失败沿用旧程序的重试设置；肖像保护拒绝停止原样重试，只失败当前任务，不影响无关任务。
- 不修改密钥、模型、素材、提示词、项目文件、其他服务商或程序 UI。
- 不自动下载历史任务，不自动重新生成旧失败任务；已启动的任务需要结束后才会使用新加载的实例。
- 不修复旧程序本身可能存在的其他下载问题。本次已完成视频用现有下载方法可正常取回，确认的根因是查询响应层级变化。
- 是否退款以巨轮后台记录为准，补丁不承诺或操作退款。

## 卸载与后续升级

关闭程序，将 `julun_result_hotfix.py` 移到 `providers` 文件夹之外，再重启即可恢复内置巨轮。只要文件仍是该目录中的 `.py`，改名字仍可能继续被加载。

升级到已经包含此修复的新版 EXE 后，建议移除补丁，让后续内置巨轮更新正常生效；旧补丁留在目录中会继续覆盖新版内置实现。
