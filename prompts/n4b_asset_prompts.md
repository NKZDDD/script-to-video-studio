# 第四环节（下）｜资产生产提示词编译

> **资产提示词是全剧共用的**，每个资产只写一份 ——
> 同一个角色只出一张图，跨集人脸才一致。

## 待写清单怎么读

输入里的资产表分成两块，**含义完全不同**：

| 字段 | 是什么 | 你要做什么 |
|---|---|---|
| `assets[]` | **这一次要写的** | 逐个写完整提示词 |
| `assets_already_done[]` | 不属于这一批的 | **不要重写。** 它在这儿只是让你引用得到 |

`assets_already_done[]` 里的条目详略不一，这是有意的：
**被这一批引用到的**（父资产、`reference_assets` 指到的）留了全量外观 ——
写 LOOK 得看得见它引的那个 PH 长什么样，不然只能自己编一个，
而编出来的和定稿那张不是同一个人，**跨集人脸就崩了，且不报错**。
其余的只留 `asset_id / family / name`，够你引用即可。

**只为 `assets[]` 里的每一条输出一份提示词。**
`assets_already_done` 里的一条都不要写 —— 重写会覆盖已经定稿的资产，
同一个角色前后两版长得不一样，跨集人脸就崩了。

但**引用它们是正常的**：写 LOOK 要引 PH 的 ID、写 CT 要引 LOOK 的 ID，
那些 ID 就在 `assets_already_done` 里。**绝对不要因为它不在 `assets[]` 里
就重新发明一个 ID** —— 出图那一层会报「查不到这个资产」。

按 `production_order` 的顺序写，**不要为了省事合并几个资产**：
合并出来的图一张也用不了。

为每个待写资产输出一份**完整、独立、可直接复制投喂出图模型**的提示词。

## 一、每份提示词的固定结构

```
资产名称 / 输出结构 / 参考图角色映射（没有参考图就整段省略）/
身份绑定 / 外观与结构 / 材质 / 当前状态 / 允许改变 / 禁止改变 /
使用场景 / 输出限制
```

**风格词只认输入里【视频类型与视觉风格】那两样的原词。**
每份提示词的「外观与结构 / 材质」必须体现这两项（例：视觉风格是
「2.5D动漫风格」，就要写 2.5D 的画面特征，不许归并成「3D漫剧电影感」
了事）。视觉基调里就算出现了别的说法，也以这两样的原词为准 ——
基调是第一环节转述的，转述丢了词的话在这里补回来。

## 二、输出结构模板

| `output_spec` | 画成什么样 |
|---|---|
| `four_view` | 一张竖版图 2行2列 四视图：左上正面全身、右上侧面全身、左下背面全身、右下正面半身特写；纯浅灰摄影棚背景、均匀柔光、站姿自然；四视图脸型发型服装体态完全一致 |
| `look_multiview` | 完整造型多视图：正面、45°、侧面、背面，**头手脚必须完整在画面里**，鞋履必须画出来 |
| `scene_wide` | 空镜定场图，无人物 |
| `prop_multi` | 正 / 侧 / 45° 三视图，纯色背景 |
| `closeup` | 特写 + 位置示意 |
| `state_asset` | 以父资产为首张参考，只表现本状态相对父资产的变化 |

`look_multiview` 的「头手脚完整」不是可选项：**LOOK 裁掉脚，鞋子就要等到
视频里第一次生成** —— 那时候模型只能自己编一双。

## 三、参考图身份映射（六字段，缺一项就阻断）

**出图模型收到的是 N 张没有标签的图，它只知道第 1 张、第 2 张。**
它不认识 `C001` 这个编号，也不知道哪张图是 C001。

只写「参考资产C001，严格沿用同一人物」等于让它猜：
一张时勉强蒙对，两张必然错位 —— 拿病房的图去沿用人脸。

**只写「控制什么、不控制什么」也不够。** 这是实跑撞过的坑：
提示词写清了 Image 1 有权决定服饰、无权决定姿态，但**没说 Image 1 是谁**，
模型把另一个角色的脸套了上去。它知道这张图管哪些维度，
不知道这张图是哪个人。

**`decision` 是 `logical_only` / `defer_to_video` / `existing_canonical` /
`skip` 的资产不出图**（第七章那张表写着「出图：否」），所以不要把它写进
`reference_assets` —— 它没有图可传。它的约束本来就是文字形式的
（服装看 `costume_contracts`），需要就把那段文字写进正文。

所以每个槽位写全六项，编号顺序**严格等于 `reference_assets` 的顺序**
（程序按这个顺序上传）：

```
Image 1 = C002 Rizky Adhitama
  是谁/是什么 + 画面可见内容：成年男性正面半身，中性表情，纯色背景，
    可见范围到腰部，手部完整可见
  故事时间 / 当前状态：全剧基准身份，Clean LOOK，未受伤，事件发生之前
  有权控制：脸型、五官、肤色、体型比例、发型
  无权控制：这张图的姿势、机位、构图、背景；病床、床品、医疗设备、光线
  适用范围：本次生成 ST012 这一张，仅用于身份继承
  MUST TRANSFORM：只画手背局部，不出现完整人物
Image 2 = ST008 医院重症监护室夜间状态
  是谁/是什么 + 画面可见内容：重症监护病房夜间环境，可见病床、监护仪、
    输液架，冷白顶光，无人物
  故事时间 / 当前状态：EP01 入院之后的持续环境状态
  有权控制：床品材质、冷白灯光、医疗设备外观
  无权控制：人物身份、肤色、手部结构；这张图的空间构图和取景
  适用范围：本次生成 ST012 这一张，仅作为承托环境
  MUST TRANSFORM：只取床面局部作为承托
```

六项各有各的坏法，缺哪一项都不报错、只是出错：

- **是谁/是什么 + 画面可见内容** —— **V5.6 新增，也是最要命的一项**。
  不写，模型不知道这张图是哪个人／哪个场景，多人场景必然张冠李戴
- **故事时间 / 当前状态** 不写 → 未来状态被提前用上（伤口在受伤前就出现）
- **有权控制** 不写 → 模型重新设计父资产，脸变了
- **无权控制** —— **最常漏的一段**。参考图给的是「身份权威」不是像素目标；
  不明确禁止，模型会把姿势、机位、构图、背景一起搬过来，
  于是每张状态图都长得像父资产那张四视图
- **适用范围** 不写 → 一张图的权威被无限扩张到整段
- **MUST TRANSFORM**（不属于六项，但该写就写）不写 → 照抄整张图，特写变成全身

**一张图里有多个人物、多个分格或多个时间状态时**，
`是谁/是什么` 必须按区域/分格逐项写清并各自带完整 ID。
写不清就阻断，**不许把整张图概括成一个身份**。

硬规矩：有几张写几条、不许跳号、不许合并成一句、
`Image N = <asset_id> <名称>` 两样都要写。没有参考图的资产整段省略。

【本次参考图上限】{{REF_LIMIT}}

## 四、状态资产额外要求

先**原样复述**父资产的 `identity_anchors`，再单独用「状态差异」写本状态
相对父资产变了什么。**不得重新设计父资产**的五官、体型或服装基础形制。

## 五、自相矛盾的输入怎么办

拿到的资产定义可能自己打架 —— 典型是声明空镜无人物，
`appearance` 里却写着「某某在画面左侧、某某在右侧递东西」。

**以 `output_spec` 为准，把不属于这条资产的内容删掉，不要照抄。**
空镜就只写空间、光线、陈设、痕迹，一个角色名都不出现；
人物站位和动作是分镜的事，写进资产图只会让模型二选一，另一半白写。

## 六、强制收尾句

每份提示词末尾必须带：

```
超高清，细节清晰，避免手部畸形、多余手指、多余肢体、模糊面部。
```

再加一句**画面文字规则**——**逐字转述下方【画面文字规则】那一段**，
不许自己缩写、也不许扩写成无差别禁令。这条规则是有口径的：
剧情本身要求的文字（招牌、屏幕、道具上的字）一律允许，禁的只有
字幕〔若设定要字幕则改成要求〕、水印、UI 面板和不属于剧情的叠加文字。
资产图经常就是道具、招牌、文件本身 —— 无差别禁令会把药瓶标签、
店铺招牌直接抹成空白，而且不报错。

### 关于换行（很重要，漏了下游没法逐项校验）

上面那些 `Image N = …` 和它下面的六项，**必须逐项分行**，
在 JSON 字符串里用 `\n` 表示换行。像这样：

```
"prompt": "…前面的内容…\nImage 1 = C002 甲\n  是谁/是什么 + 画面可见内容：成年男性正面半身\n  故事时间 / 当前状态：基准身份，未受伤\n  有权控制：脸型、五官、肤色、发型\n  无权控制：这张图的姿势、机位、构图、背景\n  适用范围：本次生成这一张\n…后面的内容…"
```

**不许把六项合并成一段连续文字。** 合并之后：
· 两张以上参考图时，分不清哪一项归哪张图 —— 模型会把几张平均融合
· 程序没法逐项校验，会把这一条拦下来重做

实测踩过：64 份提示词全写成了单段文字，一个 `\n` 都没有，
结果 41 条在出图那一步被拦住。
