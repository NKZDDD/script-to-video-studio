# 第四环节（下）｜资产生产提示词编译

> **本次只处理 {{EPISODE}} 这一集**，而且下面【待写清单】里已经**只剩还没写过
> 提示词的资产** —— 前面几集写过的不会再给你，别去操心它们。
> 资产提示词是全剧共用一份的：同一个角色只出一张图，跨集人脸才一致。

为每个待写资产输出一份**完整、独立、可直接复制投喂出图模型**的提示词。

## 一、每份提示词的固定结构

```
资产名称 / 输出结构 / 参考图角色映射（没有参考图就整段省略）/
身份绑定 / 外观与结构 / 材质 / 当前状态 / 允许改变 / 禁止改变 /
使用场景 / 输出限制
```

## 二、输出结构模板

| `output_spec` | 画成什么样 |
|---|---|
| `four_view` | 一张竖版图 2行2列 四视图：左上正面全身、右上侧面全身、左下背面全身、右下正面半身特写；纯浅灰摄影棚背景、均匀柔光、站姿自然；四视图脸型发型服装体态完全一致 |
| `look_multiview` | 完整造型多视图：正面、45°、侧面、背面，**头手脚必须完整在画面里**，鞋履必须画出来 |
| `scene_wide` | 空镜定场图，无人物 |
| `prop_multi` | 正 / 侧 / 45° 三视图，纯色背景 |
| `closeup` | 特写 + 位置示意 |
| `state_asset` | 以父资产为首张参考，只表现本状态相对父资产的变化 |

`look_multiview` 的「头手脚完整」不是可选项：**LOOK 裁掉脚，鞋子就要等到
视频里第一次生成** —— 那时候模型只能自己编一双。

## 三、参考图角色映射（Image 编号必须写）

**出图模型收到的是 N 张没有标签的图，它只知道第 1 张、第 2 张。**
它不认识 `C001` 这个编号，也不知道哪张图是 C001。

只写「参考资产C001，严格沿用同一人物」等于让它猜：
一张时勉强蒙对，两张必然错位 —— 拿病房的图去沿用人脸。

逐张写，编号顺序**严格等于 `reference_assets` 的顺序**（程序按这个顺序上传）：

```
Image 1 = C002 Rizky Adhitama（父资产）
  MUST PRESERVE：脸型、五官、肤色、体型比例、发型
  MUST TRANSFORM：只画手背局部，不出现完整人物
  MUST NOT COPY：这张图的姿势、机位、构图、背景
  DOES NOT CONTROL：病床、床品、医疗设备、光线
Image 2 = ST008 医院重症监护室夜间状态（依赖资产）
  MUST PRESERVE：床品材质、冷白灯光、医疗设备外观
  MUST TRANSFORM：只取床面局部作为承托
  MUST NOT COPY：这张图的空间构图和取景
  DOES NOT CONTROL：人物身份、肤色、手部结构
```

四段各有各的作用，缺一段各有各的坏法：

- **MUST PRESERVE** 不写 → 模型重新设计父资产，脸变了
- **MUST TRANSFORM** 不写 → 照抄整张图，特写变成全身
- **MUST NOT COPY** —— **最常漏的一段**。参考图给的是「身份权威」不是像素目标；
  不明确禁止，模型会把姿势、机位、构图、背景一起搬过来，
  于是每张状态图都长得像父资产那张四视图
- **DOES NOT CONTROL** 不写 → 多张参考图互相打架，不知道听谁的光线和服装

硬规矩：有几张写几条、不许跳号、不许合并成一句、
`Image N = <asset_id> <名称>` 两样都要写。没有参考图的资产整段省略。

## 四、状态资产额外要求

先**原样复述**父资产的 `identity_anchors`，再单独用「状态差异」写本状态
相对父资产变了什么。**不得重新设计父资产**的五官、体型或服装基础形制。

## 五、自相矛盾的输入怎么办

拿到的资产定义可能自己打架 —— 典型是声明空镜无人物，
`appearance` 里却写着「某某在画面左侧、某某在右侧递东西」。

**以 `output_spec` 为准，把不属于这条资产的内容删掉，不要照抄。**
空镜就只写空间、光线、陈设、痕迹，一个角色名都不出现；
人物站位和动作是分镜的事，写进资产图只会让模型二选一，另一半白写。

## 六、强制收尾句

每份提示词末尾必须带：

```
超高清，细节清晰，避免手部畸形、多余手指、多余肢体、模糊面部。
画面内不得出现任何文字、字母、数字、标注、水印。
```
