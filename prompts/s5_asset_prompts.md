# 第五环节｜资产生产提示词

> **本次只处理 {{EPISODE}} 这一集。** 下面【待生产资产清单】里已经**只剩这一集新出现、
> 还没写过提示词的资产**——前面几集写过的不会再给你，别去操心它们。
> 资产提示词是全剧共用一份的（同一个角色只出一张图，跨集人脸才一致）。

为每个待生产资产输出一份**完整、独立、可直接复制**的图片生成提示词。

## 每份提示词必须包含
资产名称 / 输出结构 / 参考图角色映射（无参考图时省略）/ 身份绑定 / 外观与结构 / 材质 / 基础状态或剧情状态 / 允许改变内容 / 禁止改变内容 / 使用场景 / 输出限制

## 输出规格模板
- `four_view`（人物/生物）：一张竖版图 2行2列 四视图——左上正面全身、右上侧面全身、左下背面全身、右下正面半身特写；纯浅灰摄影棚背景、均匀柔光、站姿自然；四视图人物脸型发型服装体态完全一致
- `scene_wide`（场景）：空镜定场图，无人物
- `prop_multi`（道具）：正/侧/45° 三视图，纯色背景
- `closeup`（附属特征）：特写 + 位置示意
- `state_asset`（连续性状态资产）：以父资产为首张参考图，继承一张或多张固定资产，
  只表现本状态相对父资产的变化或复杂关系结果

## 强制收尾句
每份提示词末尾必须带：`超高清，细节清晰，避免手部畸形、多余手指、多余肢体、模糊面部。画面内不得出现任何文字、字母、数字、标注、水印。`

## 连续性状态资产怎么写

先原样复述 `parent_asset_id` 对应父资产的 `identity_anchors`，再用单独的「状态差异」
写清本状态相对父资产发生了什么。逐张复述 `reference_assets` 的身份绑定并明确控制范围。
状态资产不得重新设计父资产；复杂多人/场景/道具关系必须保留全部依赖资产。

## `reference_assets` 怎么填（这决定出图时喂哪几张参考图）

`reference_assets` 是状态资产的完整依赖列表，**第一张必须是父资产**，画面里必然出现的
其他已建资产也要列上，
否则那部分只能靠模型现编，出来和别处对不上。

- 先复制待生产状态资产自身声明的 `parent_asset_id` 和 `reference_assets`，不得擅自删减。
- **但只复制会出图的那些。** 环节4 的那份列表里可能混进了没有图的编号 ——
  最常见的是空间母资产（`SP001` 这种，它属于 `space_master_id` 那一栏，不是参考图）。
  照抄下来的话，出图那一步会去找一个永远不存在的 `SP001.png`，这一条资产
  **永远出不来**，而引用到它的故事板会跟着停。
  剔掉的那几个在 `note` 里写一句「环节4 把 XXX 写进了参考图，它没有图，已剔除」。
  一个空间真的需要作为参考图时，引它 `regions[].environment_asset_id`
  指向的环境资产（例如 `S001`）。
- 父资产必须排在列表第一位；单体状态通常只有父资产，复杂关系可有多张依赖。
- 画面里实际可见并需要保持一致的已建资产必须全部列入。
- 只能引用生产顺序早于本资产的来源；禁止同级资产互相引用或形成任何循环依赖。
- 可用ID以【可用参考资产目录】为准。
  例：手背特写搁在病床上 → `["C002", "ST008"]`（人 + 病房状态）。
- 只列**清单里真实存在**的 `asset_id`。写一个不存在的 ID，出图那一步会直接停。

## 「参考图角色映射」必须写 Image 编号（强制）

**出图模型收到的是 N 张没有标签的图，它只知道第 1 张、第 2 张。** 它没见过
`C001` 这个编号，也不知道哪张图是 C001。所以只写「参考资产C001，严格沿用同一
Aisyah」等于让它猜：一张时勉强蒙对，两张必然错位——把病房的图当成人脸沿用。

映射段必须**逐张列出**，编号顺序**严格等于 `reference_assets` 的顺序**
（程序就是按这个顺序上传的，第 1 个元素就是 Image 1）：

```
参考图角色映射：
Image 1 = C002 Rizky Adhitama（父资产）
  MUST PRESERVE：脸型、五官、肤色、体型比例、发型
  MUST TRANSFORM：只画手背局部，不出现完整人物
  MUST NOT COPY：这张图的姿势、机位、构图、背景
  DOES NOT CONTROL：病床、床品、医疗设备、光线
Image 2 = ST008 医院重症监护室夜间状态（依赖资产）
  MUST PRESERVE：床品材质、冷白灯光、医疗设备外观
  MUST TRANSFORM：只取床面局部作为承托
  MUST NOT COPY：这张图的空间构图和取景
  DOES NOT CONTROL：人物身份、肤色、手部结构
```

四段的作用各不相同，缺一段就会出问题：

- **MUST PRESERVE**（必须沿用）——不写，模型会重新设计父资产，脸就变了。
- **MUST TRANSFORM**（必须改变）——不写，模型会照抄整张图，特写变成全身。
- **MUST NOT COPY**（不许复制）——**最常漏的一段**。参考图给的是「身份权威」，
  不是像素目标。不明确禁止，模型会把参考图的姿势、机位、构图、背景一起搬过来，
  于是每张状态图都长得像父资产那张四视图。
- **DOES NOT CONTROL**（不管什么）——不写，多张参考图会互相打架：
  模型不知道该听哪张的光线、哪张的服装。

硬规矩：

- 有几张参考图就写几条 `Image N =`，不许合并成一句、不许跳号、不许多写。
- `Image N = <asset_id> <资产名称>` —— **ID 和名称都要**，只写 ID 模型对不上，
  只写名称程序核对不了。
- 没有参考图的资产（父资产自己）整段省略，不要写「Image 1 = 无」。

## 输出结构与画面内容不一致时怎么办

拿到连续性状态资产却声明 `scene_wide` 时，不要删除人物、也不要缩减参考图；本份提示词
必须改用 `state_asset`。只有基础环境资产明确写着「空镜、无人物」时，
`scene_wide` 才能保持空镜。
