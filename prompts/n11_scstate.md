# 第十一环节｜场景状态图编译（SCSTATE）

> **本次只编译这一段：{{SEGMENT}}。** 其它段不用管。

把这一段的世界状态合成**一张完整的场景图**：这一刻，整个世界怎么稳定地组合在一起。

## 一、这一层是干什么的

以前故事板直接拿一堆原子资产当参考图 —— 一段传五张：人物 A、人物 B、
场景、状态一、状态二。**五张各有各的姿势、机位、背景，互相打架**，
模型只能取平均，出来的东西谁也不像。

SCSTATE 先把它们合成**一张**：人在他该在的位置上、穿着当前的衣服、
拿着当前的道具、在当前的空间里。然后故事板主要参考这一张。

```
CVS（谁在哪、什么状态）
+ 当前人物资产（LOOK / CT）
+ 场景与空间
+ 道具外观与实例状态
        ↓
    SCSTATE  ← 一张完整的世界图
```

## 二、SCSTATE 不是什么

| 不是 | 为什么要说清 |
|---|---|
| 故事板 | 它是中性机位的世界图，不是分镜画面 |
| 最终镜头 | 故事板会重新决定机位、景别、构图 |
| 动作过程图 | 它是**稳定状态**，不画动作进行到一半 |
| 人物定妆图 | 它是多主体的组合，不是单人 |
| 第二套状态数据 | 状态真相在 CVS，它只是把已定的状态画出来 |

**和 CVS 冲突时，CVS 是对的**，SCSTATE 作废重生成。
不许为了迁就出来的图去改 CVS。

## 二（补）｜**默认是逻辑合同，不是图**

> V6.1 的核心改动落在这一层：SCSTATE **默认不出图**。
> 它首先是一份从 CVS 派生的**逻辑状态合同**，出图是例外。

每个 SCSTATE 先写完整的文字合同，再过一道门控决定要不要出图：

```
目标 Canonical ID：
逻辑状态是否已完整登记：是 / 否
候选图片角色：
物化触发条件：
视频推断风险：
跨 SEG 复用：
首次显露覆盖缺口：
单图复杂度分：
决定：LOGICAL_ONLY | VISUAL_ANCHOR_REQUIRED | VISUAL_QC_REQUIRED | DEFER_TO_VIDEO
理由：
```

**这个决定必须同时写进输出里的 `decision` 栏**（见下面的输出结构）。
只写在正文里的话程序读不到，会照样给它派一个出图任务 ——
而一份文字合同没有参考图映射，出图前的校验会报「没说哪张图是谁」，
报错指向映射，真正的毛病是这条压根不该出图。

**只有命中下面任一条才允许出图**：

1. 新人物或新 LOOK 首次出现
2. 首次全身、背面、侧面、手部、鞋履或此前未定义区域显露
3. 不可逆伤势、污渍、破损、换装、道具损坏或场景永久变化**首次激活**
4. 跨 SEG 入口或出口需要精确视觉继承
5. Hero 道具需要近景辨认、可读内容或精确数量规格
6. 新场景首次建立且机位会显露关键几何、通路、路线或地标
7. 实测高风险的合成（多人同框、手部动作、道具交接）

**中间动作、姿势、反应、纯机位变化一律 `DEFER_TO_VIDEO`。**
「保险起见出一张」不是合法触发条件 —— 那正是图片层过度承载的来源。

当前策略：`{{SCSTATE_MATERIALIZATION_POLICY}}`

### 但删图不等于删合同

**这条最容易做错。** 判成 `LOGICAL_ONLY` 只是不生成图片，
它的 Source CVS、Zone、Anchor、Support Binding、Route、Orientation、
道具数量与持有人**一条都不能少**，而且照旧不可变 ——
没有被批准的移动事件谁都不许换位置。

减压减的是**图片张数**，不是**一致性维度**。

## 二（补二）｜同一状态横跨不相容空间时，切片

同一个 CVS 如果横跨远距离、不同高度、被 Barrier 隔开，
或者两边是**不相容的动作轴**（一个在讲台上、一个在观众席里争吵），
不要硬塞进一张图。

建立 **Zone-Coherent 切片**：每个切片只显示**一个机位连贯的空间簇**，
共享同一个故事时间、同一份物体计数、同一个来源 CVS。
其他区域的实体登记为 **OFF-FRAME ACTIVE** —— 他们在场、状态照常继承，
只是这一张里看不见。

**绝对不许为了同框把人移过来，或者把两个空间融成一个。**
那是位置状态门控要拦的事，在这里就别制造。

## 三、出图规格（只对判定要出图的那些）

- 单幅完整场景，{{IMAGE_SIZE}}
- **中性的中全景或全景，机位稳定**
- 人物占画面高度大约 45%–70%，按场景调整
- 尽量覆盖：人物身份、当前状态、稳定走位、相对位置、关键道具、主要地标
- **不用**极端特写、极端广角、倾斜构图、夸张俯仰、运动模糊、多格拼贴

中性是有意的：故事板要在它基础上**重新观察**，
所以它自己不能带强烈的镜头语言。

## 四、提示词必须包含的部分

按这个顺序写，一个都不能少：

1. **任务** —— 这是一张场景状态图
2. **本条身份** —— SCSTATE 编号、来自哪个 CVS、故事时间、现实线程
3. **参考图角色映射** —— 见下，最要紧
4. **人物状态合同** —— 逐人：当前视觉根、区域锚点坐标、姿态、朝向、
   视线、手上占用、当前生效的持续状态清单、哪些必须可见 / 哪些可以被遮挡
5. **道具实例合同** —— 逐个关键道具：实例编号、当前状态、持有人、哪只手、
   容器、位置、可见性、**存在总数对账**
6. **空间合同** —— 空间编号、区域、锚点坐标、地标、通路、禁止的空间改变
7. **关系走位** —— 人物间距离、朝向、高度关系、接触、视线、遮挡优先级
8. **可见性合同** —— 哪些明确可见、部分可见、被遮挡、画外、尚未激活
9. **时间锁** —— 这一刻允许存在什么、**绝对禁止出现什么未来状态**
10. **必须保留清单** —— 当前所有关键身份、状态、道具、持有人、地标
11. **禁止清单** —— 未来的贴片、未来的破损、错误的持有人、
    不该出现的人物、恢复成干净状态、无授权的空间改变
12. **机位规则** —— 中性中全景，稳定机位
13. **输出限制** —— 画面内不得出现文字、字幕、水印、UI

## 四（续）、位置差异继承：只有被批准的人能动

每份 SCSTATE 提示词**先声明上一个稳定状态，再声明唯一合法的差异**：

```
【上一个稳定状态】SCST_…_SC01_01
【位置不变的人】C005 —— Zone、Anchor、支撑、朝向、障碍侧全部沿用
【被批准移动的人】C001
【对应的移动事件】VT_EP01_03
【起点 / 路线 / 终点】BED_01 → R1 → DOOR_01
【支撑的解除或获得】解除 BED_01 的 SEATED_ON
【禁止的位置变化】C005 不许离开床尾；任何人不许出现在桌前
```

规则：

- **相邻 SCSTATE 默认继承全部人物的 Zone、Anchor、支撑、朝向、障碍侧。**
- **只有 `authorized_movers` 里的人**允许改变位置。
- **情绪升级、对白变化、把照片摔出去、换机位，都不自动授权换位。**
- 为了让三人同框、为了露全身、为了做对峙构图，**不许把人物移到房间中央**。
- 一个机位看不全所有人时，允许人物部分可见、被遮挡或者离画；
  也可以换一个中性观察机位 —— 但**不许改变人在世界里的位置**。

**SCSTATE 是世界状态的验证图，不是宣传剧照。**
生成出来的图和 CVS 的位置冲突时，这张 SCSTATE 作废重生，
**不许把错误的位置回写进 CVS**。

## 五、参考图角色映射（Image 编号必须写）

**出图模型收到的是 N 张没有标签的图，它只知道第 1 张、第 2 张。**
它不认识 `C001` 这个编号，也不知道哪张图是 C001。

所以逐张写，编号顺序**严格等于 `reference_assets` 的顺序**：

```
Image 1 = C001 Aisyah（人物身份）
  MUST PRESERVE：脸型、五官、烧伤疤痕位置、身体比例
  MUST TRANSFORM：按本条的姿态和位置重新摆
  MUST NOT COPY：这张图的四视图版式、站姿、纯灰背景
  DOES NOT CONTROL：别的人物、场景、道具、光线
Image 2 = S001 雅加达私人医院（场景）
  MUST PRESERVE：建筑材质、色彩、固定设施、光线基调
  MUST TRANSFORM：按本条的机位重新取景
  MUST NOT COPY：这张图里的人物（如果有）
  DOES NOT CONTROL：人物身份、服装、道具状态
```

四段各有各的作用，**`MUST NOT COPY` 是最常漏也最要紧的那段**：
参考图给的是「身份权威」不是像素目标。不明确禁止，模型会把参考图的
姿势、机位、构图、背景一起搬过来 —— 于是每张 SCSTATE 都长得像那张四视图。

硬规矩：有几张写几条、不许跳号、不许合并成一句、`Image N = <ID> <名称>`
两样都要写。

## 六、参考图选哪些（`reference_assets`）

- 这一刻画面里**出现的每个主体**都必须在里面 —— 少一个，那部分只能靠模型编
- 顺序：人物 → 场景 → 道具 → 状态
- 只列真实存在的资产编号，写一个不存在的，出图那一步会停
- 数量控制在**能力范围内**；实在超了，优先保住身份类和当前状态类，
  次要背景可以退回文字描述

### 关于换行（很重要，漏了下游没法逐项校验）

上面那些 `Image N = …` 和它下面的六项，**必须逐项分行**，
在 JSON 字符串里用 `\n` 表示换行。像这样：

```
"prompt": "…前面的内容…\nImage 1 = C002 甲\n  是谁/是什么 + 画面可见内容：成年男性正面半身\n  故事时间 / 当前状态：基准身份，未受伤\n  有权控制：脸型、五官、肤色、发型\n  无权控制：这张图的姿势、机位、构图、背景\n  适用范围：本次生成这一张\n…后面的内容…"
```

**不许把六项合并成一段连续文字。** 合并之后：
· 两张以上参考图时，分不清哪一项归哪张图 —— 模型会把几张平均融合
· 程序没法逐项校验，会把这一条拦下来重做

实测踩过：64 份提示词全写成了单段文字，一个 `\n` 都没有，
结果 41 条在出图那一步被拦住。
