# 第三环节｜叙事结构（场次与节拍）

> **一次处理全剧。** 按 `Project → Episode → Scene → Beat` 逐层拆，
> 每个 Scene 必须写清它属于哪一集（`episode` 字段），
> 集的划分见【故事真相】里的 `episode_ranges`，**不要自己重新分集**。
>
> 为什么全剧一次做：场次归属和跨集的因果链是同一件事。
> 按集分开做，第 5 集就看不到第 1 集埋的伏笔要在哪一场回收。

把故事真相组织成戏剧结构：

```
Project → Episode → Scene → Beat → Shot 表达需求
```

**SEG 不在这条链里。** Scene、Beat、Shot 由剧情决定；SEG 是后面按视频模型
一次能生成多久去装箱的技术容器。**不许按 SEG 反推剧情** ——
「这一段只有 15 秒所以砍掉一个转折」是本环节最严重的错误。

本环节**不设计镜头**，只写「这个节拍需要什么样的镜头表达」。

## 一、Scene（场次）

定义：**在相对连续的时间和行动过程中，围绕一个主要戏剧目标展开、
并产生明确状态变化的完整戏剧单位。**

切新 Scene 的常见条件：

- 时间、空间或现实线程发生**有叙事意义**的切换
- 主要目标结束或被替换
- 前一场已经形成明确结果，新的行动链开始
- 叙事需要用离场/入场建立新的戏剧单位

**地点变化不必然等于新场次**；同一地点也可以包含多场戏。
走出病房到走廊继续同一场争执，那是同一场。

每个 Scene 必须能回答完这几项 —— 答不上来的多半不是一个完整场次，
应该并进相邻场次：

| 字段 | 在问什么 |
|---|---|
| `objective` | 谁想要什么 |
| `conflict` | 什么挡着 |
| `tactics` | 他试了哪些办法（有先后） |
| `turn` | 哪一下让局面变了 |
| `outcome` | 结果是什么 |
| `exit_state` | 这场结束时，世界处于什么状态 |

`entry_state` 必须接得上前一场的 `exit_state`。接不上就是漏了事件。

## 二、Beat（戏剧节拍）

定义：**刺激或行动导致认知、目标、情绪、关系、权力或局势发生一次
有意义变化的最小戏剧单位。**

判定只问一句：

> 这个节点结束后，相比开始前，**什么重要的东西改变了**？

六类算数的变化：

1. **认知** —— 未知变已知
2. **目标** —— 当前想要的东西变了
3. **情绪** —— 情绪结果显著改变
4. **关系** —— 信任、亲密、敌意或关系定义改变
5. **权力** —— 优势、控制权或持有人改变
6. **局势** —— 危险、空间局势或资源状态改变

只有动作而没有意义变化的（眨眼、走两步、抬手、递东西），**属于 Beat 内部动作**，
不单独成为 Beat。

**不要为每句对白机械创建 Beat。** 三句对白推进同一个认知变化，那是一个 Beat。
反过来，一个眼神造成关系翻转，那就是一个完整 Beat。

节拍结束时没有任何有意义变化 → 并进相邻节拍，或标成内部动作。

## 三、Shot 表达需求（`shot_need`）

这里**只写需求，不写镜头**。写的是「要让观众看懂这个节拍，画面必须交代什么」：

```
✅ 必须让观众同时看到两人的距离和她手里的文件
✅ 关键是他听完之后那 2 秒没反应
❌ 中景，机位在床尾，缓慢推近      ← 这是第九环节的事
```

**不得固定「一个 Beat 一个镜头」。** 一个节拍可以一个镜头、多个镜头，
也可以和相邻节拍共用一个镜头 —— 镜头数由信息量、动作复杂度、表演节奏、
空间关系和导演意图决定，那是后面才定的事。
