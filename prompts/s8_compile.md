# 第八环节｜故事板与视频提示词编译

> **本次只处理 {{EPISODE}} 这一集。** 下面给的输入都是这一集的，所有段落 id 必须是 `{{EPISODE}}-SEGnn`；
> 集号写错，后面的绑定、分镜、出图出片会全部对不上号。


本环节**只编译不创作**——内容全部来自上游产物的拼装。每段输出三部分：参考图上传顺序、完整故事板提示词、完整视频提示词。

## 故事板提示词固定结构
一、输出结构（分格故事板、排布、每格竖构图、格左上角标注镜头编号、按时间顺序）
  - **格数由你按【正式分镜】采样决定，取 4—6 格**。它是镜头的关键帧采样，
    **不必也不应与镜头数 1:1** —— 7 个镜头采成 5 格是正常的，挑出状态变化的那几个。
二、参考图角色映射（逐张 `Image N = <asset_id> <资产名称>`，四段权威写全）
  - 编号顺序**严格等于 `reference_order` 的顺序**，程序就是按这个顺序上传的。
    出图模型收到的是 N 张没标签的图，它只知道第几张，不认识 `C001` 这个编号 ——
    编号对不上，每张参考图都会被错误归属，而且不报错。
  - **ID 和名称都要写。** 只写 ID 模型对不上人，只写名称程序核对不了。
  - 有几张就写几条，不许合并成一句、不许跳号、不许多写。
  - **只写职责边界，不复述外观**。外观在第三节有完整原文，这里再写一遍是重复，
    而且两处措辞一旦不一致，模型会不知道听哪个。
  - 四段各有各的作用，`MUST NOT COPY` 是最常漏也最要紧的那段 ——
    参考图给的是「身份权威」不是像素目标，不明确禁止，模型会把参考图的姿势、
    机位、构图、背景一起搬进故事板，于是每格都像那张四视图。
  - 例：
    ```
    Image 1 = C001 Aisyah
      MUST PRESERVE：脸型、五官、烧伤疤痕位置、头巾与旧罩衫的基础形制
      MUST TRANSFORM：按本段分镜重新摆姿势、机位和景别
      MUST NOT COPY：这张图的四视图版式、站姿、纯灰背景
      DOES NOT CONTROL：Dewi、Rizky、场景、道具、光线
    ```
三、身份与资产绑定（**从资产清单原样复制 appearance，禁止重新组织语言**）
四、视觉风格（引用压缩版基调）
五、空间与轴线（原样落实绑定的 space_context、character_space_context，以及分镜的 space_note、character_space_note）
  - 故事板每格的人物位置、身体与视线朝向、与固定物关系、人物相对位置必须服从对应分镜的 `positions`；
    没有 `change_trigger` 或明确移动镜头时不得让人物换边、换位、突然坐下/站起或离开固定物。
  - 视频首帧必须继承人物 `entry_state`，末帧必须落在 `exit_state`；存在 `inherit_to_seg` 时，末帧状态必须可直接作为下一 SEG 的进入状态。
六、关键帧顺序（逐格内容，首格=进入状态，末格=退出状态）
七、进入状态
八、退出状态
九、连续性限制
十、输出限制（含技术避错句 + 画面文字规则**逐字按下方【画面文字规则】转述**，分格镜头编号除外。不许自行扩写禁令范围 —— 把剧情文字〔手机屏幕、招牌、路牌、信件、弹幕这类〕也禁掉，等于改设定）

## 视频提示词固定结构
一、基础输出（"基于参考故事板，按格子顺序生成 {{DURATION}} 秒连续画面，镜头间直接硬切"）
二、人物、场景和状态连续性（点名具体特征，禁止"保持人物一致"这类空话）
三、完整时间轴（自然语言连续叙述，不用字段式；对白写进时间轴并标说话人）
四、镜头与硬切规则
五、动作和穿模控制
六、段落边界（末尾必须停在 exit_state）
七、禁止内容（含 forbidden_future 的防剧透项 + 画面文字规则**逐字按下方【画面文字规则】转述**。不许自行扩写禁令范围 —— 把剧情文字〔手机屏幕、招牌、路牌、信件、弹幕这类〕也禁掉，等于改设定）

## 故事板参考原则（`reference_order` 填的就是这个）
`reference_order` 是**出这张故事板时要上传的参考图**，来自【段落资产绑定】。

- 每一项的 `asset_id` **必须是资产清单里真实存在的资产 ID**（C001 / ST007 / P002 / S001 这类）。
- **绝对不能填「本段故事板」「{{EPISODE}}-SEGnn-STORYBOARD」或任何段号。**
  故事板还没出，拿它当自己的参考图是循环；程序会因为指不到文件而停在出图这一步。
  拿故事板当参考图是**下面视频那一节**的事，两者不要混。
- 顺序照抄绑定表的顺序，人物在前、场景道具在后。

## 视频参考原则（这一节**不写进 `reference_order`**）
视频的参考图由程序自动装配：`Image 1 = 当前段固定故事板`，不用你填。
只有系统文字、商品包装或微小关键道具无法识别时，才在 `aux_reference_asset_id` 里填**一个资产 ID**做辅助参考图，并在视频提示词正文里写明：Image 1 控制人物/场景/构图/镜头顺序/动作顺序/状态；Image 2 只控制指定细节；Image 1 优先级高于 Image 2。不需要就填空字符串。

## 输出 schema

```json
{
  "compiled": [
    {
      "id": "{{EPISODE}}-SEG01",
      "reference_order": [{"image_n": 1, "asset_id": "C001", "control_scope": ""}],
      "storyboard_prompt": "完整故事板提示词正文，可直接复制",
      "video_prompt": "完整视频提示词正文，可直接复制",
      "aux_reference_asset_id": "需要辅助参考图时填资产ID，否则空字符串"
    }
  ]
}
```
