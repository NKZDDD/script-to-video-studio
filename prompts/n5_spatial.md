# 第五环节｜空间主表

> **一次建全剧的空间主表。** 同一个地点全剧**只有一套坐标真相** ——
> 第 1 集的病房和第 20 集的病房是同一个 `spatial_id`，
> 门窗位置、锚点坐标、通路一律不变。
>
> 按集分开建的话，同一个房间会得到几套互相矛盾的坐标，
> 跨集出现的场景就再也拼不拢了。

给每个地点建**一套坐标真相**：原点在哪、轴怎么定、单位是什么、有哪些区域、
锚点的实际坐标、通路怎么连、哪些结构固定不动。

## 一、为什么必须用坐标，不能用「画面左边」

这是本环节存在的全部理由。

「病床在画面左侧」是**某一个机位看到的样子**。换个机位它就在右边。
如果把它当成空间真相记下来，切镜时模型只能二选一：要么让病床跳到另一边，
要么让人物绕到另一侧 —— 两种都是错的，而且不报错。

```
✅ 病床：Zone=A 区，锚点 BED_01，坐标 [2.4, 0, 1.8]，床头朝 +X
❌ 病床：在画面左侧，靠近后景
```

**坐标属于物理真相，画面左右属于镜头。** 后面第九环节算画面左右时，
是拿机位去投影这套坐标，不是反过来。

## 二、本项目的空间做到哪一档

skill 给了四档，从强到弱：

```
真实 3D 块模 / 摄影测量
> 带尺寸的 2.5D 平面 + 轴测
> 纯文字坐标合同          ← 本项目做到这一档
> 各视角分别自由生图      （这一档不算过关）
```

**本项目不建 3D 代理**（出图模型做不出可靠的几何代理），所以你要做的是
**把文字坐标合同写扎实**：带尺寸的区域、明确的锚点坐标、成序列的通路、
以及多个视角之间共用的地标。

这一档的已知代价：同一场景多机位之间**不保证严格可拼合**。所以更要写清
`landmarks` —— 它们是不同视角之间唯一的对齐依据。

## 三、坐标合同要写什么

每个空间：

- `world_origin` —— 原点定在哪个真实位置（「主入口地面中心」这种能指认的地方），
  不要写 `[0,0,0]` 就完事。
- `axis` —— `+X` `+Y` `+Z` 各指向哪。写成人能核对的（「+X 指向窗户」）。
- `unit` —— 米。
- `zones` —— 有叙事意义的区域，每个给范围和它支持什么剧情行为
  （病房：床位区 / 探视区 / 门口区 / 窗边区）。
- `anchors` —— 固定物的锚点，**必须给 xyz**。`门边`、`床旁`不算锚点。
- `routes` —— 通路写成**锚点序列**，不是一句话。
- `landmarks` —— 不同机位都看得见、可以用来对齐的东西。
- `fixed_structures` —— 墙、门、窗、楼梯、电梯、大型家具，含开门方向。
- `scale_anchors` —— 已知尺寸的参照物（门高 2.1 米、病床长 2 米），
  模型靠它稳住比例。
- `forbidden_geometry_changes` —— 明写不许镜像翻转、不许移门窗、
  不许为了构图挪固定家具。

## 四、区分三种「变化」

| | 例子 | 怎么处理 |
|---|---|---|
| 永久几何 | 墙、门、窗、走廊、病床固定区 | 写进 `fixed_structures`，不许变 |
| 可修订几何 | 爆炸、倒塌、装修 | 建新的 `spatial_revision`，显式说明 |
| 临时空间状态 | 碎玻璃、封路、移动的障碍 | 写进 `temporary_obstacles`，走连续性总账 |

通路当前被障碍挡住时，**不能因为后面会移开就提前当成可用**。

## 五、障碍、通口与通路：空间拓扑不是背景装饰

桌子、柜台、病床护栏、墙、玻璃、门、车辆、舞台边缘、围栏 ——
这些必须**作为拓扑登记**，不能只当成陈设写一句「房间里有张长桌」。

不登记的后果很具体：下游会让人物**直接穿过实心会议桌**出现在对面，
而且画面上看不出破绽（那一格构图甚至更好）。

三样东西要分清：

| | 是什么 | 不写的后果 |
|---|---|---|
| `barriers` | 挡住通行的实体，带 bbox 和两侧分区 | 人物穿桌穿墙 |
| `portals` | 障碍上**唯一合法**的通口：门、桌端空隙、缺口 | 从任意位置翻过去 |
| `routes` | 有序锚点串成的通路，带长度、最窄处、**最少耗时** | 三步走完二十米 |

`supports` 单独一项：椅子、病床、轮椅、担架、车辆座位。
坐、躺、乘车、跪靠**不是普通姿态**，它们绑定一个支撑实体 ——
人物离开座位前必须先解除支撑，这一层要给出「解除大概要多久」。

`minimum_action_time` 是给第十三环节用的：一段移动物理上要 1.5 秒，
而镜头窗口只有 0.6 秒，那就是不可能完成的走位，必须回去改导演设计。

## 五（续）、机位覆盖（`loc_views`）

登记全剧需要从哪几个方向看这个空间。每个视角写：机位大致位置、朝向、
覆盖到哪几个 Zone、能看见哪几个地标。

**这一步只是登记需求，不出图。** 它的用处是让后面第九环节挑机位时，
知道哪些方向是已经想清楚的；镜头要求一个没登记过的方向时，
应该回到这里补，而不是在故事板里第一次发明房间另一侧长什么样。

### 需求驱动，不是先摆三视图

> V6.1 明确：**先从场次、走位、镜头/关键帧需求和显露包络提取真实空间需求**，
> 再决定要几个机位。不是先摆一套正面/侧面/俯视，然后去找用途。

每个 Location 先立**一张视觉 Master**，然后按实际需求排 View：
**默认只留当前执行不可替代的 1–2 个**。

每新增一个都要写清五样，缺一样就不该留：

| 要写的 | 意思 |
|---|---|
| `role` | 这个机位是干什么用的 |
| `unique_coverage` | 它**独有**的 Zone / 通口 / 路线 / 障碍 / 锚点 |
| `consumers` | 哪几个镜头或关键帧要用它（写完整 ID） |
| `overlap_with` | 和哪个已有 View 重叠、大概多少 |
| `why_not_crop` | 为什么不能靠裁已有的那张来替代 |

### 重复视图要主动否掉

重叠超过 **{{REDUNDANCY_OVERLAP_HEURISTIC}}**、又说不出独有 Zone / 独有关系 /
明确消费者的候选机位，直接判 `REDUNDANT_VIEW_REJECTED`。

**这几种不算新机位**：只是焦段不同、只是推拉、只是轻微横移、
只是裁切范围不同。它们靠 `allowed_crop` 就能得到。

覆盖不够的解法是**新 View 或限制镜头**，不是多堆几张差不多的图。

### 相邻 View 当参考时只管固定结构

拿已有 View 给新 View 当参考时，它**只控制**固定结构的身份、地标、
尺度和重叠区域。提示词里必须明写它**不控制**当前机位坐标、视线方向、
焦段、裁切、构图和可见 Zone —— **并且禁止复现邻图的构图**。

不写这句的后果很具体：新机位出来是旧机位的轻微变体，
两张图覆盖同一片区域，而真正需要的那个方向还是没有。
