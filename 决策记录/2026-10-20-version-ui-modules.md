# 版本管理由长表单改为独立功能模块

日期：2026-10-20
起因：用户反馈“这个ui不太好看，可以以功能模块展示，不用全部一页放下来而且间隔和样式页不合理不符合ios的样式设计”。

## 定性与范围

`auth_service/studio_auth/web/releases.js` 在一个 660px 弹窗里连续追加校验控制、测试登记、构建记录和正式发布；共享的通用表单样式只处理单个输入框，没有模块级导航、分组间距和固定操作区。暂停操作还复用位于正式发布底部的提示，导致操作反馈落到视野外。之前按功能逐项补入口，没有重新整理信息结构，因此内容越加越长。

范围为用户截图的「客户端版本」窗口，覆盖全体系、电影级和通用级的管理操作。不调整账号/Key 页面、生产任务流程或版本校验服务规则。

## 用户要求与实施

按明确要求将界面分为「版本概览、测试登记、正式发布、构建记录」，一次只显示一个模块。使用接近 iOS 设置界面的分段导航、浅灰背景、白色分组、统一圆角和间距；标题、模块导航与提交区固定，模块内容独立滚动。

正式发布将下载地址及校验信息收起，保留展开和原生表单校验定位；文件导入改为完整可点击的卡片。概览按体系显示推荐/最低版本，构建记录可筛选。测试、正式发布和校验控制各自显示操作结果，切换模块保留输入。窄屏变为单列，键盘方向键、Home、End 可切换模块。

新增样式仅作用于版本窗口，作为独立 CSS 随服务端一起交付；资源 URL 带版本号，避免旧缓存将新结构配到旧样式。

## 避免的问题

用户可直接进入需要的功能，不必穿过其他操作的表单。登记测试构建和正式发布保持独立，提交按钮与结果留在当前模块的可见操作区，避免误把测试登记当成更新发布，也避免暂停结果被埋在页面底部。

## 验证与交付

Studio 全量 3441 项通过（231.71 秒），服务端全量 79 项通过（83.23 秒，1 条既有弃用提示）。独立 WebView2 验证模块互斥显示、切换保留输入、键盘导航、测试登记和正式发布调用、局部成功/失败反馈、构建筛选、隐藏信息校验定位，以及桌面和窄屏布局。

新增 CSS/JS 的 HTTP 路由、内容类型、带版本号引用及 health 版本通过验证。交付服务端 1.6.3 升级 ZIP、部署说明和界面预览，验证包内 CRC 与全部 SHA256SUMS；不重新打包客户端，未部署或修改线上策略。
