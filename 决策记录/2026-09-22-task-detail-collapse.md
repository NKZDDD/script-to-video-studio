# 确认任务明细不能收起的位置

用户反馈：“下面的哪个具体的任务明细那好像也有点不对，不能收起来”。

查到的机制：生产页的批次卡片由 renderJobs 固定输出为 div，本来没有折叠入口；点击“任务明细”打开的 dialog 有关闭按钮，但内容很长时标题和按钮会随窗口内容滚动；资源树右侧详情由 renderDetail 渲染，目前也没有收起按钮。三处对应不同的修改，需确认用户实际指的位置。

## 需要确认

不能收起的是哪一处？

- A：生产页下面一串“生产批次 running / done / error”卡片。可以把这一组做成可展开收起的列表，减少页面长度。
- B：点“任务明细”弹出的窗口。需要修复明细窗口的关闭操作或关闭按钮可见性。
- C：资源树点开后右侧的具体任务详情。需要增加详情收起操作。

结合上一张截图，较可能是 A；尚未按此推断修改。

## 用户回答

用户回答“任务明细”，确认修改点击“任务明细”打开的窗口。

## 实施

明细窗口原先整体滚动，长任务表格会把顶部关闭按钮一起滚出视野，用户滚到底部时找不到收起入口。改为任务明细专用布局：标题和“收起明细”按钮固定在窗口顶部，表格和日志在内容区滚动；自动刷新保留内容区位置。沿用关闭按钮和 Esc 的关闭流程，收起不停止生产，关闭后晚到的刷新响应不能重新打开窗口。其他对话框保留原布局。

## 验证与交付

全量 2653 项测试通过；使用 140 条任务和长日志完成 7 项浏览器验收：长列表底部按钮可用、刷新保留滚动、关闭时晚到响应不重开、关闭后停止明细轮询而生产继续、Esc 关闭、重新打开回到顶部、窄屏按钮始终可见。首次沙箱测试被临时目录/浏览器权限阻止，改为本机执行后通过，未发起付费生产。

修改源码，未重新打包 EXE。下次打开长任务明细，无需滚回窗口顶部寻找关闭按钮。
