# 巨轮 Q10 专用规格与 ASCII 报错核对

日期：2026-09-30
起因：用户提交 Q10 时返回 HTTP 400，包含 `fail_to_fetch_task` / `'ascii' codec can't encode characters`，尚无 task ID；随后提供《Q10-SD2.5全参-下游对接文档.md》。

## 查明的机制

文档中的模型正式名称就是 `Q10-SD2.5 全参`；`ratio` 与 `aspect_ratio` 等价。
现有 Studio 的请求为 `requests.request(json=body)`，中文模型、提示词、参考图 URL 经标准 JSON 转义，中文不进入 HTTP 请求头。
因此不能把“模型名含中文”或“用了 ratio”直接认定为此次 ASCII 错误的根因；错误由巨轮 HTTP 响应返回，需要服务商对应提交记录的完整详情才能继续定位。无 task ID 时可用提交时间和请求编号排查。

另一个已确认的接入差异：Q10 之前在 UNSPECED，`build_video_body` 在未填写清晰度时兜底 720p；文档仅支持 480p。专用规格缺失也使界面没有正确的逐模型参数选项。这能独立修复，但不能声称修复了服务端 ASCII 错误。

## 实施范围

- 主程序与 `zz_julun_latest.py` 同步登记 Q10：4–30 秒、480p、16:9/9:16、30 图/10 视频/10 音频。
- 使用文档主字段 aspect_ratio；既有 ratio 并非非法字段，其余模型保持原格式。
- Q10 时长必须为 4–30 整数，不静默改时长；提示词超过 4500 字符明确报错，不截断。
- 参考图不截断为 9 张；单图 20MB 为服务商要求，现有 URL 流程不额外下载所有素材做容量预检，仍需按此要求准备。
- 保留已有任务恢复、视频自动续传和其他模型规则。本次没有修改错误分类，没有把 HTTP 400 查询异常当成生成失败，也没有付费创建任务。
- 输出可安装到旧版 Studio 数据目录的完整巨轮外挂。

## 验证

专项测试 117 passed（3.96 秒）；全量测试 2904 passed（477.05 秒）。覆盖专用规格、默认 480p、合法整数时长、30 图/10 视频/10 音频不丢失、4500 字符边界及实际请求编码路径的离线 Unicode 回归；既有外挂一致性、任务查询与下载检查一并通过。

交付 `dist/Respect-Studio-Julun-Q10-20260930.zip`。主程序、外挂和压缩包中的 julun 实现一致，ZIP 完整性与内部 SHA256 校验通过。未进行付费生成。

用户补充：当时选择“跟随任务”，已找不到对应任务的错误详情。
跟随任务可能沿用任务内的 720p，也可能在缺省时触发旧代码的 720p 兜底；缺少该任务参数，不能确认实际发送值。
建议安装后在 Q10 生产行明确选 480p。原 ASCII 错误具体来源仍未确认，可凭截图时间让巨轮排查；不会通过猜测删除中文模型名或提示词。
