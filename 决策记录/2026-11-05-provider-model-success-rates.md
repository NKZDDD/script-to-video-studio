# 选择模型时显示服务商自己的成功率

日期：2026-11-05

起因：用户说「客户端和服务端都需要增加一个这个显示，在选择模型时候可以看到这样就知道什么模型比较稳定」。此前已确认：使用服务商公开的统计，包括无限画布、沧元、章鱼哥的公开任务样本；不使用 Studio 用户的任务记录来计算。

## 定性与范围

原监测只检查接口连通和 Key 鉴权。客户端模型能力表提供模型、参数和权限，后台 Key 库只提供模型 ID 绑定；两处都没有服务商模型统计的数据通道。因此刷新模型或监测健康状态也不会出现成功率，这不是生成接口故障。

覆盖客户端生产页、首选及备用模型设置、新项目创建向导，以及服务端管理后台的 Key 库模型绑定区。当前需求明确，沿用已确认的供应商统计口径，无需再次确认。

## 实现

- `auth_service/studio_auth/model_statistics.py`：两端共用的公开接口解析和缓存。每个进程最多两个后台读取线程、每家五分钟缓存；页面接口只读缓存。没有生成请求，不需要额外 Key。
- `core/model_statistics.py`：按账号当前可用模型筛选；完整模型 ID 精确匹配，不去后缀，不把别的网关统计套给自定义地址。
- `web/model-statistics.js`、CSS 及后台同名资源：模型旁显示成功率、统计窗口、样本和平均耗时；展开后可搜索、查看更新时间并选择。客户端保存原始模型 ID，后台追加绑定后仍由管理员点击保存 Key。
- `web/agent.js`：生产设置与备用设置复用同一入口；创建向导切换服务商会同步替换模型候选和统计。
- `auth_service/studio_auth/model_statistics_api.py`、`provisioning.js`：管理员登录后查看统计、添加模型绑定。公有统计不表示当前 Key 一定有该模型权限。

### 数据源

| 服务商 | 来源 | 展示口径 |
| --- | --- | --- |
| 纵横 | www.yeepay.top `/api/model-stats`，配合 `/api/models` 映射公开模型 ID | 服务商公布的终态比例 |
| 阿珂 | snumom.com `/api/model_status` | 服务商原比例；保留其样本补齐口径说明，不擅自改算 |
| 无限画布 | videogogo.top `/api/model-plaza/v1/models` | 服务商最近最多 100 条终态样本换算，取消除外；保留分组 |
| 沧元 | ai.cangyuansuanli.cn `/api/pricing/video-history` | 服务商最近最多 20 条视频任务换算，审核拒绝计入分母 |
| 章鱼哥 | zexapi.com `/agent-api/v1/public/model-status` | 服务商真实样本换算，按其页面口径排除用户问题，不补模拟样本 |
| 巨轮、坤鸡、零视、小白龙、Vale | 各自域名 `/api/perf-metrics/summary?hours=24` | 服务商公布的请求成功率；明确标注不一定等同视频最终成片成功率 |

合计 10 家，其中 7 家读取比例，3 家按供应商公开样本换算。不是全平台所有模型都有数字；没有数据的模型显示「暂无数据」，不填 0% 或 100%。

### 异常和兼容

刷新失败保留最近成功数据及其时间，标明旧数据；首次失败显示统计暂不可用。服务商请求在后台执行，统计异常不会阻止选模型、保存设置或提交生产，也不会触发自动换模型。未确认统计接口的服务商照常使用。

请求只发往固定公开 HTTPS 接口，不携带账号 Key、Cookie 或任务内容，不跟随重定向；浏览器传入地址仅用于匹配供应商，不会作为抓取目标。服务端接口保留管理员会话检查，客户端接口保留本机登录检查。

## 交付与生效方式

本次完成源码修改及本地提交，未打包 EXE、未上传 R2、未部署服务器。客户端需要包含新代码的 EXE，后台需要更新本次服务端代码与静态资源，并按 `auth_service/requirements.txt` 安装新增的 certifi 证书依赖。无需数据库迁移、无需重新分配 Key、无需升级服务商适配包才能读取这些公开统计。

修完后，用户选模型时能够看到供应商提供的统计和范围，避免把健康接口正常当作模型生成稳定，也避免把缺失统计、不同窗口或过期数字误当成同一种成功率。数字用于选型参考，不保证某次生成成功。
