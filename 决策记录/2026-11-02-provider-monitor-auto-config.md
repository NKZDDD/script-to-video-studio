# 监测自动读取适配包中的接口规则

日期：2026-11-02

用户要求：先询问“为什么监测还需要额外配置呢”，确认采用“接口信息自动读取适配包，每家只选择一把检测 Key，未知规则保留手动设置”的方式后，要求“按照这个思路完成”。

## 机制与范围

第一版 `provider_monitor.py` 只保存独立的 URL、鉴权和响应字段，`provider-monitor.js` 要求管理员填写它们；`build_provider_bundle.py` 只导出可执行接口代码，没有向监测提供静态规则。原 `list_models()` 存在缓存、静态兜底和吞掉异常的实现，因此直接调用它不能证明实时接口可用。第一版接口与权限测试均能通过，仍未覆盖“不需要重新填已知接口”的实际使用过程。

范围是适配包声明、服务端规则解析/监测配置、后台操作界面及升级交付。保留双端检测、每家一把 Key、账号隔离、离线补报、独立后台线程；不修改生产接口或放宽账号权限。

## 实施方式

- 适配器声明 GET 监测规则，构建时自动附加纯数据模块。保留适配包协议 1，服务器仅用 AST 读取字面量，不执行适配器代码。
- 后台默认自动读取已发布适配包；选择 Key 后显示自动识别的地址和鉴权范围，保存只绑定服务商、检测 Key 与启用状态。无规则时明确提示，允许选择手动设置。
- 自动配置读取 Key 已有 Base URL；没有填写时使用适配器默认地址，保留 `/api` 前缀并避免重复 `/v1`。分组凭据使用所选 Key 内一把可用凭据。
- 发布或回退适配包后，自动监测随规则变更，旧结果和迟到上报不混入新规则。已有手动配置保持原值，编辑时可切换为自动。
- 28 个已维护服务商中，26 个有标准 GET 规则；XMD 动态签名和 HVTALD WebDAV 自检明确标为需要专门适配，不用静态模型制造正常状态。
- 本次升级账号服务至 1.11.1，并发布带规则的适配包 2026.11.02.3。已安装 Studio 2026.11.02.2 可直接接收原格式的完整监测配置，不需要重复安装 EXE。

## 预期结果

已有标准接口的服务商只需选择检测 Key 并启用，不必重复填写接口地址、鉴权头和 JSON 字段。将来接口规则更新随适配包发布，避免用户各自维护不同版本；没有规则或凭据不全时显示具体原因，不把猜测的 `/v1/models` 当成已知配置。
