# 修复生产契约预览乱码

日期：2026-10-03
用户原话：「查看生产契约是乱码」。

## 原因与范围

截图对应项目 `11_PRJ_CFBFDF0614` 的 `00_项目说明/production-contract.md` 直接以 UTF-8 读取时中文正常。实际查询当前运行的 127.0.0.1:8770 文件接口，响应为 `Content-Type: text/markdown`，没有字符集，返回字节与磁盘文件完全一致并可正确解码 UTF-8。页面「查看生产契约」经 `/file` 打开原文件，服务端只用系统 MIME 映射推测类型，没有声明字符集；同一页面的 HTML/JS/CSS 则已经显式指定 UTF-8，所以页面正常但契约预览会依赖浏览器的编码猜测。Windows 对 `.md` 的文件类型注册也可能不同。

该问题同样影响通过 `/file` 打开的 Agent 模板、文本提示词和 JSON。原来的 HTTP 测试覆盖了视频 Range，但未检查中文文件的响应字符集，因此此前自检没有发现。

## 修复

`server/app.py` 的项目文件响应将 `.md` / `.markdown` 固定为 `text/plain`，文本类型和 JSON 显式附加 `charset=utf-8`。继续返回原始字节，保持文件长度和 Range 行为，不修改项目文件、发布散列或生产契约。

修复后契约和模板按 UTF-8 纯文本打开，不依赖浏览器猜编码或 Windows 的 Markdown 类型关联。图片、视频下载逻辑保持不变。

## 验证

新增真实 HTTP 回归覆盖 Markdown 类型、未注册扩展名、大小写扩展名、模板、提示词和 JSON。修改前复现缺少 charset，修改后 6 项通过；既有视频 Range 测试也通过，共 7 项针对性验证。全量测试 3025 passed，耗时 186.42 秒，日志 outputs/preview-encoding-full-20261003.log。
