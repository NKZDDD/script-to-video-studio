# 视频只有一张参考图；「满足条件继续重试」没生效

日期：2026-08-25

我感觉是之前被哪边锁住了. 2、就是上次说的满足条件就开始干，没做出图片，
满足条件继续重试好像还没有生效」

## 问题一：视频只有一张参考图

### 先排除

- **produce 那一层是对的**：`core/produce.py` 组的是 `storyboard_refs` 整条
  （按 order 排）+ `reference_images` 补图 + V6.1 的 `aux_reference`，
  还有 `_check_video_ref_map` 两头对账。
- **服务商声明的上限也不是**：13 家 video 的 `max_refs` 都是 8/9/30，没有 1。
- **LLM 策略也不是**：`video_reference_policy` 已经是 V6.2 的
  `mandatory_storyboard_plus_selective_effective_supplemental`，
  `storyboard_video_reference_policy` 是 `mandatory_temporal_spine`，
  n13 模板里明写「V6.1 按可靠度分路那条改掉了，再高也不能退化成一张起始图」。

所以「锁」不在这三处。按路径分，有**三个各自独立的原因**：

### A. 材料导入模式（最可能是你现在撞的这个）—— 契约没要求骨架多张

契约里 `storyboard_refs` 只写了「必填、空的就不出片」，**从没说它要覆盖完整
关键时间推进的多张**，也没有一个字提补图（`reference_images` 只写「骨架之后的
补图，编号接着排」）。验收那十条里，「视频必须有骨架」查的是**非空**。

更直接的：**契约里那份四行样例，视频只带一张 `storyboard_refs`。**
codex 照样例的形状产，就是一张。

而上一份真实材料的比例是 84 张故事板 : 84 段视频 = **1:1** —— 一段一张。
V6.2 第 19 章那套（骨架必给且要覆盖完整时间推进、补图要证明独有作用）
一个字都没进契约。这不是被锁住，是**我没把这条要求写进契约**。

### B. 电影级十七章 LLM 模式 —— 装配层静默挑掉补图

`core/run_v34.py` 装配视频任务时：

```python
[r for r in (vp.get("reference_order") or [])
 if isinstance(r, dict) and r.get("asset_id") in amap]
```

资产表里认不出的 asset_id **在进 `split_refs` 之前就被挑掉了**，不进
`no_image_refs`，不落 diagnose。注释自己写着「这一处历来如此，不在这次改动
范围内」。骨架不受影响（走 `sb_by_seg`），少的是补图。

### C. 通用十二环节 —— 结构上就只有两张

`core/stages.py` 装配的视频任务字段是 `storyboard_ref`（单数，一张）+
`aux_reference`（单数，一张），没有 `storyboard_refs` 列表，也没有
`reference_images`。这是 V6.1 的输出结构（`aux_reference_asset_id` 本来就是
单数），不是哪里被夹了 —— 这套体系的视频天生最多两张参考图。

### 怎么一眼确认是哪一个

跑视频时那行日志：

```
故事板骨架×N 补图×M 参考图共×K
```

- `骨架×1 补图×0` → A 或 C（材料只给了一张 / 通用版结构）
- `骨架×3 补图×0` 而提示词里映射了 5 张 → B（补图被挑掉了）

## 问题二：条件补跑没生效

### 定性

`core/relay.py::sweep_redo` 是实现了的，而且注释就是照你上次的原话写的
（「只要有出现满足条件，没报错的情况，东西还没做出来就要重试去做」）。
问题是**它只在一条路径上被调用**：

- `core/pipeline_v34.py:532` 和 `core/pipeline.py:672` —— 都在
  「一键跑到底」的 produce 块收摊之后。
- **「生产」页那三个「开始」按钮走的是 `/api/generate`**，它用 `run_chain`，
  `deps_of` 只对**资产**给（`S.asset_deps`），故事板和视频**一个 relay 都没有**，
  收摊后也不调 `sweep_redo`。

所以：
1. 在「生产」页出图出片，**没有条件补跑** —— 上游后来落盘了，它不会自己复活。
2. 故事板/视频在这条路上**连「就绪即派」都没有** —— 参考图没齐也照样派出去，
   撞成失败记录（花一次调用或者至少落一条记录）。

而材料导入模式下，导入完的提示正是「现在可以直接去『生产』页出图出片」——
**恰好是没有补跑的那条路**。一键跑到底在材料模式下不能用（它会去跑 LLM 环节，
而材料模式没有那些中间产物）。

## 怎么修的

### A. 契约要求完整时间骨架（材料导入模式）

- `storyboard_refs` 的说明改成「要覆盖这一段完整的关键时间推进，把本段全部
  有序 Sheet 按 `image_n` 都给上，**不许退化成一张起始图**」。
- 新增一节「视频的参考图分两层」：骨架必给（负责先后顺序、施动受动、动作
  阶段、镜头顺序），补图要证明独有作用（四条准入），额度先给骨架、不许砍骨架。
- 验收新增 `VIDEO_SPINE_SINGLE`，**warn 不 error**：判 error 会把已经产出来
  的材料（84 张故事板 : 84 段视频）全变成死路，而死路比漏检更糟。
- **样例的视频改成带两张骨架。** 这一条是根上的：样例只给一张的话，
  codex 照样例的形状产就是一张 —— 样例本身在教它给一张。

### B. 电影级装配层不再静默挑掉补图

`core/run_v34.py` 里那个 `if r.get("asset_id") in amap` 前置过滤删掉了。
视频是四类里**唯一**带它的（故事板那条直接进 `split_refs`），而 `split_refs`
的设计意图恰恰相反 ——「认不出的 ID 留在列表里、file_ref 留空，不要悄悄删掉；
删了数量看着是对的，反而看不出少了一张」。现在照故事板那条路走，
由出片前 `_check_video_ref_map` 硬停并报清楚缺哪张。

### C. 通用十二环节的视频补图：一个 → 有序一组

- `prompts/s8_compile.md`：`aux_reference_asset_id`（一个 ID）→
  `video_reference_order`（有序列表），带四条准入（UNIQUE / NONCONFLICTING /
  WINDOWED / LEGIBLE）、禁止动机、以及「正文里逐张写
  `Image N = <asset_id> <名称>`」。
- 模板里加了 `{{REF_LIMIT}}`，**并且在 v61 的 s8 变量表里接上** ——
  这个变量原来只有 v34 填，不接的话字面量直接喂给模型。取 `ref_limit_video`：
  s8 编的是视频提示词，拿出图那家的数会差一倍。
- `core/stages.py` 装配：读列表，老产物的单个字段照旧认；认不出的 ID 留在
  列表里、file_ref 留空（和 v34 同一条口径）。
- **顺带修了一个连带 bug**：produce 里 `aux_reference` 和 `reference_images`
  两个字段都有值时，第一张补图会被**上传两次** —— 而 `image_n` 按上传顺序算，
  它后面每一张的编号整体错位，每条描述都套到别的图上。画面出得来，
  参考全是错的。改成只在没有 `reference_images` 时才认老字段。

范围说清：这套体系的故事板环节**一段只出一张图**
（`_STORYBOARD_V01_FIXED`），所以骨架仍然是一张 —— 多张有序骨架是电影级
十七章那套的设计。这里长出来的是补图。

### 问题二：两处都接上

**一、`/api/generate`（生产页那三个「开始」）**
- 建 `Relay`，**登记全四类**（漏一类，等它产物的下游会误判成「没人会做它」
  而立刻开跑），这一趟不跑的三类标成收摊（否则本类会一直等一个永远不会
  开始的批次）。
- `run_chain(..., ready_of=...)` —— 参考图没齐**不发请求**。以前故事板和视频
  在这条路上照样派出去，撞成一条「失败」，而它不是失败，是条件不具备。
- 批次收摊后调 `sweep_redo`，并且**终态按磁盘重算** —— 还用批次的 `left`
  判的话，会把补出来的那几条报成失败。

**二、「只跑生产」入口**
`plan/run/preview` 三处加 `include_llm`（两套体系都加），页面一个勾选框。
勾上时跳过全部 LLM 环节和 n0 冻结，只按 tasks.json 出图出片，走的还是一键
跑到底那条路 —— 就绪即派、条件补跑、跨类接力全都在。勾上时「包含出图出片」
强制勾住（两个都不勾的话计划里一步都不剩，跑起来是「完成」而什么都没做）。

## 为什么会有这些问题

**视频只有一张参考图** —— 三个原因各自独立，共同点是：**产参考图的那一层和
用参考图的那一层各自都对**。produce 传整条骨架 + 补图，对的；`split_refs`
把认不出的留下来报错，对的；n13 模板要求完整骨架，对的。错在中间那几处
「谁给它多少」：契约只要求非空、装配层多一道前置过滤、v61 的输出 schema
只有单数字段。每一处都不报错，只是少。

**条件补跑没生效** —— 功能做完了，**但只接在一条路径上**。而那条路径
（一键跑到底）在材料导入模式下根本不能用，它会去跑 LLM 环节。导入完程序
还提示「去『生产』页出图出片」，正好指向没有补跑的那条。这类漏法这个项目
里出过好几次：后端做了页面不发那个值；一键跑接了单跑那一步没接。
共同点是**不报错，功能只是悄悄不在**。

## 修完能避免什么

- **视频参考图**：以前一段只带一张故事板，模型不知道这一段先发生什么后发生
  什么，**会把后段的画面当前段用而不报错** —— 片子出得来，时间顺序是乱的，
  要人看片才发现。现在材料验收会提醒、v34 不再静默丢补图、v61 能带一组补图，
  而重复上传导致编号整体错位那个 bug 也修了。
- **条件补跑**：以前在「生产」页出图出片，一条任务派单那刻输入没齐就被标成
  条件不具备，之后上游补完了它不会复活，得人再点一次「开始」—— 而人不知道
  该点第几次。现在同一趟里自动捞：产物没有、输入齐了、不是真报过错的，
  自动重派，按生产顺序前一步补出来的后一步立刻用。
