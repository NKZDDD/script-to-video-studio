# 巨轮自动续传及独立外挂

日期：2026-09-28。

用户要求：补上程序的自动续传并给出一个外挂。

## 问题机制与范围

已有诊断见 `2026-09-28-julun-download-range-recovery.md`。巨轮已完成的视频在整文件传输时断流，但小段 Range 请求可成功。通用下载器失败后删除临时文件并从头重试，没有利用已取回的字节，所以连续三次断流后仍无成品。普通下载顺利时不会暴露此缺口；completed/progress 95 的状态识别没有问题。

本次只改巨轮的视频结果下载，覆盖新提交任务和已保存任务 ID 的恢复入口。图片下载及其他服务商保持原逻辑。范围为内置 `core/providers/julun.py` 与数据目录外挂 `providers/zz_julun_latest.py`，两者使用完全相同源码；版本 20260928.3。

## 实施

- 首先普通下载，断流后从已收到的位置改用 64 KiB Range 小段传输，保留 4 KiB 重叠部分核对衔接内容。
- 严格核对 HTTP 206、Content-Range 起止和总大小、实际段长度；有 ETag / Last-Modified 时核对版本。无版本标识时总大小与重叠内容可发现衔接不一致，但不能证明文件任何位置都未被服务商改动。
- Range 被忽略而返回 200 时从头替换临时内容，绝不把整文件追加到断点。错误重试及总等待均有上限，取消可中止下载。
- 完成后检查 MP4 顶层 box 边界及 ftyp/moov/mdat，再原子替换成品；错误页、残缺文件不会发布。此检查不是全量媒体解码；真实交付验证另做 FFmpeg 全量解码。
- 结果下载失败归为 TASK_FATAL，错误码 result_download_failed，不触发付费重新生成；新版 Studio 原有任务 ID 保留机制继续有效。
- 只有服务商同源下载入口携带 API Key，外部结果存储不携带；不把 Key 打进日志或外挂。
- 沿用此前巨轮模型更新，包括 seedance-2.5-deal 4–30 秒与 480p。外挂不依赖旧 EXE 的巨轮规格表，兼容缺少 submitted / RUNNING_STATES 的旧宿主。

本次断点只在一次取回过程中保存，退出或取消清理临时文件。下次继续取回同一任务时重新下载，不承诺跨程序重启保留字节断点。没有历史任务 ID 持久化功能的旧 EXE，外挂不能凭空恢复其已丢失的历史 ID。

## 交付与避免的问题

外挂 ZIP：`outputs/julun-update-20260928/Respect-Studio-Julun-20260928.3.zip`，只包含 `providers/zz_julun_latest.py` 与安装说明，不含 Key 或用户项目。

ZIP CRC 检查通过，包内适配器与内置源码字节一致。ZIP SHA256：`ed5fa88b0c167d35b1b4c929c0aafa47a16727d43a3b04efbd2fd9e26b0f1369`。

退出 Studio，将文件放进实际数据目录的 providers 文件夹，替换同名旧外挂，将其他旧巨轮外挂移出该目录，重启即可。对于“已提交待取回”，保留原任务并再次开始生产即可继续取回，不要放弃并重新提交。

下次再遇到同类断流，日志会提示从断点分段续传并显示下载量；取回完整视频才算成功。即使续传最终失败，也不会发布半截视频、覆盖已有成品或为了下载错误重新付费生成。
