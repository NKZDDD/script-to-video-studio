## 为什么会有这些问题

- 文件控件、服务商选择框、选中高亮这三处，都是「写了代码但没有对应的样式」或者「样式写了但名字对不上」。
  工作台是从原型改过来的：原型里的类名（`rv-provider-picker`、`data-active`）和最终代码用的（`active`、新的 `label` 结构）分了两套，页面照样能用，只是看起来不对，所以一直没人发现。
- 时长报错只把 Python 列表原样拼进句子里，读的人看不出是哪个模型、数据从哪来、该怎么办。写报错时默认读者知道校验的来龙去脉。
- 生产计划跟着悬浮：9 月 20 日的要求是「按钮和计划随时可见」，当时把计划和按钮当成一个整体做成了吸顶卡片，没有考虑计划展开以后会有多高。
- 跨机器交接：最初的设计明确假定 Agent 和 Studio 在同一台机器上，所以模板只写本机绝对路径，接收只靠扫描本机目录。

## 修完能避免什么

- 以前另一台机器上的 Codex 拿到的是一串它访问不到的本机路径，只能靠人手工搬文件。搬错位置、漏掉 `READY.json`、散列对不上，都要等扫描时才冒出来，而且页面上看不出是搬运出了错。
  现在两头各一个 zip：导入时当场给出结论，已接收、跳过还是撤回，撤回的会写明原因，并告诉你该用哪个版本号。
- 以前导入一个比当前版本旧的发布，会被扫描静默跳过：看起来导进去了，实际什么都没发生。现在当场拒绝。
- 以前报「30 秒不在 [4, 5, …, 12] 中」，要么去猜，要么来问。现在报错直接写明服务商、模型、数据来源和三种处理办法。
- 以前放一个写坏的服务商文件进 `providers`，会把一家原本能用的同名服务商顶掉。现在从页面导入时，加载失败会自动恢复原样。

## 顺带发现的：切换项目卡在「正在读取项目…」（用户确认后已修）

**机制**：`loadProject` 用一个递增的序号丢弃过期请求，而后台每 4 秒的自动刷新也会递增这个序号。
在某个项目的生产 / 契约 / 产物页里切换到另一个项目时，如果切换请求还没回来，后台刷新就发出了请求，切换请求回来时会被当成过期丢掉，数据没放进去，页面画成「正在读取项目…」。
后台刷新回来时只存数据、不重画页面，返回的「上一份数据」是 null，于是这一轮什么都不做。下一轮开始做局部更新，却找不到还没画出来的资源树，每 4 秒报一次 `scrollTop` 错误，只能刷新浏览器恢复。
项目越大（加载越慢），越容易撞上。
能长期存在没被发现，是因为它要求两次请求交错，而且焦点不在输入控件上（焦点在控件上时，后台刷新会整轮跳过）。

**修法**（`web/agent.js`）：
- 后台刷新不再递增序号，只用来判断自己是否过期，永远不会作废用户主动发起的请求；
- 数据到了、页面还没画出来时，整页重画，不做局部更新；
- 后台刷新刚拿到第一份数据时（上一份是 null）也会触发重画。

**验证**：把切换请求延迟 5 秒、接下来那次后台刷新延迟 8 秒，可以稳定复现。
- 旧代码：切换后 7 秒、19 秒都停在「正在读取项目…」，并报 `scrollTop` 错误。
- 新代码：同样的时序下，7 秒时页面已经正常显示，19 秒时没有任何报错。
- 两个浏览器验收脚本仍然都是 7/7，Agent 相关的 61 项测试通过。
