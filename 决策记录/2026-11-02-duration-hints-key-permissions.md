# 时长声明改为提示，修复 Key 授权边界与后台弹窗

日期：2026-11-02

用户要求：
> 4项都需要修改，而且服务端的设置不用拉到最上面点关闭点周边空白位置就可以，然后秒数开放会不会有更好的方案？因为我是防止模型更新拉取到最新的模型原来是30秒结果他运行60秒了会被我的设置给夹住

## 定性与范围

本次基于 `56604cd` 审查发现的四项问题进行修改：

1. `auth_service/studio_auth/key_library.py` 分配 Key 时检查账号容量，但编辑 Key 的服务商时没有重新检查全部已分配账号。可以形成单家 33 把 Key 或 49 家服务商，随后客户端拒绝安装整份配置，表现为账号无法登录。一般编辑/授权测试没有覆盖共享 Key 迁移至边界账号。
2. `core/providers/__init__.py` 和 `core/model_catalog.py` 为放开时长而将所有声明覆盖为 1–60、删除模型级时长。这样既掩盖了真实声明，也让不接收秒数参数的章鱼哥和固定 15 秒接口显示可调整时长。客户端与旧生产页还分别存在 600 秒硬上限和按模型下拉/交集约束。
3. LensForge `_media_refs` 没有裁剪参考文件，却把参考素材的时长元数据限制到 2–30 秒；45 秒素材会被标成 30 秒。原测试只测范围内素材，未能发现元数据与真实文件不一致。
4. Key 分配账号窗口移除已选标签时只改 Set 和标签，未重画下方复选框；显示仍被选中，但保存时已移除权限。API 测试无法覆盖页面内部这两个表示是否同步。

范围包括 Agent 工作台、旧生产界面、模型清单合并、LensForge 适配器、固定时长协议声明以及账号服务后台；不改导演契约、生产提示词或已提交任务。

## 确定的方案

- **任务的目标时长与模型能力声明分开**：留空沿用任务；填写正整数则使用填写值。可调整时长的模型不按旧清单、本地通用 60 秒或 600 秒上限截短、拒绝或取最近值。上游是否接收该值由生成接口决定。
- 拉取模型保留真实的逐模型时长，供页面提示；新清单更新提示，不改写用户选择。例如旧声明到 30 秒仍允许提交 60 秒；刷新为支持 60 秒后，用户明确选的 30 秒仍然提交 30 秒。
- **不接收秒数参数的协议单独显示**：章鱼哥注明由模型/服务商决定；Hvtald 注明接口固定 15 秒。生产计划显示同样信息，不再声称按用户任意秒数发送。遗留的不适用秒数覆盖明确报错；在视频行清空或切换模型即可解决，包括清除旧高级覆盖。
- LensForge 按提供或探测的有效真实时长上报；不改变 URL，也不伪造时长。无效/非有限/非正时长在创建任务前报错，是否接收长素材由上游判断。
- Key 改服务商时，在同一写事务内检查每个已分配账号，沿用 256 条 / 48 家 / 每家 32 把的既有规则。任一账号超限则整笔编辑失败，原 Key、revision、密钥和授权关系都不变；提示先调整该账号的分配。停用 Key 也计入容量，和现有分配规则一致。
- 移除已选账号后同步可见复选框；搜索结果之外的其他已选账号仍保留。
- 所有后台原生弹窗通过统一事件处理支持点击周边空白关闭；弹窗内部、内部留白和从内部拖到外部不触发关闭。关闭等同现有关闭按钮，不自动保存。

## 修复后避免什么

模型升级为支持 60 秒时，不会再被 Studio 的旧 30 秒提示或统一时长上限夹住；用户明确选择的较短时长也不会自动放大。固定协议的页面与实际请求不再互相矛盾。参考素材时长与未裁剪的文件保持一致。共享 Key 的迁移不会绕过账号容量导致下一次登录失败，账号标签与勾选状态一致，后台长弹窗可以直接点击周边退出。
