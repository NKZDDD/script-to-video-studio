# 独立 C 字段别名兼容

日期：2026-10-20

## 用户要求

“也兼容一下 `"handoff_type": "scene_c"`”。结合前文，一并兼容用户材料中的 `handoff_type: "independent_c"`。

## 为什么会有这个问题

独立 C 扩展只识别 `handoff_mode: "independent_c"`。外部材料生成端使用了 `handoff_type`，JSONL 解析没有读取该字段，随后将 ABC 家族且无 region 的图片归为整板，因此视频 IN_C 引用触发 VIDEO_USES_BOARD。原有测试使用规范字段，没有覆盖外部材料的两种写法。

影响范围：JSONL 导入及其任务构建（两套体系共用），以及 Agent 发布包的引用校验。不是提示词或文件名问题。

## 修改规则

- 统一识别 `handoff_type: "scene_c"` 和 `handoff_type: "independent_c"`。
- JSONL 导入转换为规范的 `handoff_mode: "independent_c"`，后续按场景状态图调度。
- Agent 发布校验使用同一识别函数；发布文件及 READY 散列不被改写。
- 非空 handoff_mode 优先，非法值仍校验失败，不被别名掩盖。
- ab_board、ab_panel 等值不提升为独立 C；整板直接用于视频仍被拦截。
- 独立 C 的形状、IN_C 角色、AB 来源一致性及去重规则不变。
- 契约和 schema 补充兼容说明，扩展标记升级，旧项目刷新契约时可补充新规则。

## 修完能避免什么

使用这两种 handoff_type 写法的独立 C 不再因为字段名不同被误判为整板，正确的 IN_C 引用可以导入；真正的整板引用及错误依赖仍会被拒绝。
