# 超模按渠道分组选 Key，参考图点击放大

日期：2026-09-30

## 用户要求

“我直接给你th,和4k的kye对应的模型名称，参考图那边点一下就跑到任务去了，很多时候要看他长什么样要么是放大图片展示要么就是鼠标悬停预览，超模的这个锁定的可以用外挂给exe吗”

用户提供 5 个 TH 模型和 4 个统一 Native 模型截图。选择点击放大，独立保留查看任务入口。用户已授权，暂无需要额外确认的产品分歧。

## 为什么会有这个问题

Studio 的 `server/app.py::_provider_key_slot` 使用模型名是否含 `4k` 区分两把图片 Key。这与旧固定档位模型名吻合，但统一 Native 模型名没有 4K，分辨率由 size 参数指定，因此会错取图片 1K 字段中的 TH Key。旧模型快照又会覆盖插件声明的模型列表，导致仅补模型列表也不一定显示。

参考图卡片整体绑定 jump，没有独立看图入口。用户点击图片会直接改变当前选中任务，无法在当前视频任务旁检查参考图细节。

## 怎么修改

- 主程序统一 Key 路由咨询超模服务商的分组映射。5 个 TH 模型使用 image_1k 字段；4 个统一 Native 及原有固定档位 Native 使用 image_4k 字段。输出分辨率独立传 size，画幅仍传 ratio。
- 清单保留用户确认的 9 个模型，避免旧快照或单 Key 返回结果覆盖隐藏。未配置对应 Key 时沿用明确报错，不跨分组回退。
- 旧 EXE 使用完整超模外挂，并通过延迟安装兼容包装器修正宿主 Key 路由与模型清单合并。插件移除后重启恢复内置行为。主程序和外挂实现保持字节一致。
- 设置标签改为 TH / Native，底层字段不变，不迁移或合并密钥。
- 资源详情的所有参考图共用 refCards：已完成内部图与外部图点击放大，缺失内部图保留状态；查看任务使用独立按钮。对话框期间保留当前任务、勾选及定时刷新的保护。
- 图片参考图不增加本地数量限制，不截断；服务商协议限制由服务商返回。任务取回、失败 ID 管理、其他服务商不变。

## 修完能避免什么

TH 模型输出 4K 不会误切到原生 Key，Native 模型输出 1K 也不会误切到 TH Key。旧 EXE 加载外挂后同样生效，不会只显示了新模型却仍选错 Key。查看参考图外观不会把用户带离当前任务，仍可明确点击入口跳转。
