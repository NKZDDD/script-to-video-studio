# 并发工具的界面要改成傻瓜式，不是 studio 的翻版

日期：2026-09-04
起因：用户原话——「要傻瓜式的不要去复刻studio，我要做的是选择服务商然后必要参数填写可以用模板然后跑批即可，不要训练用户去用什么换行啊本地地址什么的」

## 我查到的

### 机制：我把 studio 的「熟练用户界面」照搬了过来

`respect_batch/web/index.html` 的跑批页，用户要先学会 **8 件事**才能开跑：

| # | 要学的东西 | 在哪 |
|---|---|---|
| 1 | `\|` 把一行分成「提示词 \| 参考图 \| 文件名」三段 | 提示词框 placeholder |
| 2 | 多张参考图之间用 `;` | 同上 |
| 3 | `#` 开头的行会跳过 | 同上 |
| 4 | 参考图要填**本机绝对路径** | 同上 |
| 5 | 输出目录也要**自己打路径** | outDir 输入框 |
| 6 | size / ratio / duration / resolution 四个框同时露着，哪些真正生效取决于模型 | 参数行 |
| 7 | 并发数、每条几张、失败重试次数 —— 三个裸数字框 | 参数行 |
| 8 | 设置页是 studio 那套：逐家密钥 + 对象存储 + 三层闸上限 | 设置页 |

第 1-4 条是**批处理清单语法**。这套东西对写脚本的人很顺手，对「选个服务商跑一批」
的人是纯负担 —— 而且错了不会当场说，是跑完才发现文件名不对、参考图没生效。

第 5 条尤其没道理：浏览器里本来就能拖文件、能弹原生目录选择框，让人手打路径是我偷懒。

第 6 条是**声明已经在手里却没用**：每家的 `capabilities()` 里写着这个模型到底有
`sizes` 还是 `ratios`、有没有 `resolutions`、时长是不是固定档位。我全露出来了，
等于把「这个参数对当前模型有没有用」这个判断推给用户。

### 范围：要改的是界面层，调度层不动

`core/batch.py`（并发、闸门、重试、跳过、未发）和 17 家服务商都不动 ——
上一轮那 27 项测试也不该因为换界面而挂。要改的是 `web/index.html`
和 `core/server.py` 里为它服务的几个接口（加：文件接收、原生目录选择、模板存取）。

`parse_lines` 的 `|` `;` `#` 语法**保留但不再是主路**：命令行 `run.py run --file`
还靠它，那条路的用户就是写脚本的。界面上不再要求任何人知道它。

## 要你定的

### 1. 一次跑批的「多」，多在哪？

这决定主界面长什么样，两种做出来是两个东西。

- **A（推荐）多条不同的提示词** —— 主界面是一列任务卡片，一张卡一条提示词。
  想批量就把一段文字粘进去，程序**自动拆成多张卡**并显示「拆成了 12 条」，
  可以逐张改/删。不需要学任何符号。
  —— 好处：这才是「跑批」；代价：卡片多了要滚动。
- **B 一条提示词、出很多份** —— 主界面就一个提示词框 + 一个「出几份」。
  —— 好处：最简单；代价：只能做「同一个提示词多抽几张」，
  20 个不同镜头还是得跑 20 次。
- **C 两个都要**：默认 B 那样一条，点「批量」才展开成 A 的卡片列表。
  —— 好处：第一眼最干净；代价：多一层，而且「批量」按钮本身也是要学的东西。

我倾向 **A**：这个程序存在的理由就是 ComfyUI 一次只能跑一条。
如果主用法是"一条提示词多出几份"，它省下的时间有限，不值得单独做个程序。
但**这一条我最没把握**，因为我不知道你平时是一次准备 20 个不同镜头，
还是同一个镜头多抽几版。

### 2. 参考图是全批共用，还是每条各自一张？

- **A（推荐）两块分开摆**：上面一块「这一批都用这些参考图」（拖进来出缩略图），
  卡片上再有一个小小的「这条另外加图」。
  —— 好处：同一个角色出 20 个动作时，图只拖一次；图生视频时每条也能各配各的。
  代价：界面上多一块区域。
- **B 只有全批共用**：一处拖图，所有任务都用它。
  —— 好处：最干净。代价：图生视频（一张图对一条片子）做不了，
  而那恰好是最耗时、最该并发的活。
- **C 只有逐条**：每张卡片自己拖图。
  —— 好处：概念统一。代价：同一组参考图要拖 20 遍。

我倾向 **A**。**参考图一律拖拽或点选，绝不让人打路径** —— 这条不用问，直接做。

## 你的回答

1. **主界面**：多条不同提示词（推荐项）
2. **参考图**：全批共用 + 可单条加（推荐项）

## 怎么改的

### 三步，每一步都少一样要学的东西

| 原来要学 | 现在 |
|---|---|
| `\|` 分三段 | 没有了。任务是卡片，一张卡一条 |
| `;` 分参考图 | 没有了。拖进来出缩略图 |
| `#` 注释 | 没有了。不要的那条点 × 删掉 |
| 参考图手打绝对路径 | **拖进来或点一下选**，`core/assets.py` 落盘 |
| 输出目录手打 | 点「换个地方」弹**系统原生**选择框 |
| 四个参数框不管用不用都露着 | **只画这个模型真的有的项** |
| 三个裸数字框 | 只留「同时跑几条」，其余收进「高级」 |
| 想批量得懂换行规则 | **粘一段文字自动拆成多条**，提示「拆成了 12 条」 |

「只显示这个模型真的要的参数」不是猜的，是**声明本来就在手里**：各家
`capabilities()` 里有 `sizes`/`ratios`/`durations`/`resolutions`，鹤、Gate、
无限画布、阿珂四家还有逐模型的 `model_options`（无限画布五个模型的时长各不相同）。
原来我把四个框全露出来，等于把「这个参数对当前模型有没有用」这个判断推给用户 ——
而判断错了不报错，是发出去被平台悄悄改掉或者直接 400。

### 新增两个文件

- `core/assets.py` —— 拖进来的图落盘（按内容哈希去重，同一张拖十次只存一份）
  + `pick_dir()` 原生选目录框
- `core/templates.py` —— 模板：**只存「怎么跑」**（哪家/模型/参数/并发/输出目录），
  不存提示词、密钥、参考图

### 调度层一行没动

`core/batch.py` 加了 `spec["tasks"]` 结构化清单和 `spec["refs"]` 全批共用参考图，
`|` `;` `#` 那套**保留但只服务命令行**（`run.py run --file`，那条路的用户是写脚本的）。
并发、闸门、重试、跳过、未发全部原样 —— 上一轮那 27 项测试一个没改就全绿。

### 顺手堵住的两处

1. **`/api/file` 只放行 uploads 目录里的文件。** 缩略图要一个"按路径取文件"的接口，
   不限制的话这个进程就成了本机文件读取器 —— 服务虽然只绑 127.0.0.1，
   但浏览器里**任何一个页面**都能往它发请求。用 `..` 绕出去也不行（realpath + commonpath）。
2. **模板用白名单而不是黑名单存字段。** 黑名单在 spec 将来加字段时会把凭据
   一起写进模板文件，而模板是会被人拷来拷去的东西。

### 一处顺序问题

共用参考图**拼在每条自己的前面**并去重。顺序就是各家的「图1、图2」
（鹤的 `@Image1`、超模的 content 块次序），反过来会让 `@Image1` 指向别人 ——
而那不会报错，只是出来的不对。

## 为什么会有这个问题

**我把「这套代码原来长什么样」当成了「它该长什么样」。** 服务商层从 studio 拷过来是
对的（那些坑不该再踩一遍），但界面也顺着拷了 —— 而 studio 的界面是给**知道
十七个环节叫什么**的人用的，它的用户已经付过学习成本了。这个程序的定位是
「想起来就双击一下」，同一套界面在这儿就变成了纯负担。

更具体的机制：**批处理清单语法对写代码的人是最省事的输入形式**（一个文本框 +
一个 split，我少写两百行 JS），代价全部转嫁给用户，而且转嫁得很隐蔽 ——
`|` 写错了不会报错，只是文件名变成了提示词的一部分；参考图路径打错了要跑到
那一条才说。省下的那两百行，是用「用户每次都要重新想一遍规则」换的。

## 修完能避免什么

- 第一次用的人不用读任何说明就能跑完一批：选家 → 三个下拉 → 拖图 → 粘提示词 → 开跑。
- 不会再有「跑完发现文件名里带着参考图路径」这种 `|` 写错的产物 ——
  没有 `|` 可写错了。
- 不会再有「这个模型到底认不认 resolution」的猜测：界面上没有的项就是没有。
  以前填了不生效不报错，平台悄悄用默认值，看成片才发现不对。
- 参考图不会再因为路径打错、或者路径对但文件是 0 字节而在跑到一半才炸 ——
  拖进来的那一刻就验过了，缩略图显示不出来就是有问题。
- 「只收公网链接的家 + 没配对象存储」这个组合**在拖图的那一刻就红字提示**，
  而不是等开跑之后第一条失败。

## 测试

`py -m pytest` → **38 passed**（原 27 + 11 项新的）。新增覆盖：结构化清单优先、
空卡片被忽略、共用参考图顺序与去重、拖图去重/拒非图/拒空图、uploads 白名单
（含 `..` 绕行）、模板白名单不漏凭据、逐模型参数确实不一样。
