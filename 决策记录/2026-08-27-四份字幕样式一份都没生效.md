# 四份字幕样式一份都没生效

## 起因

用户原话：

> 我的那4份字幕样式呢

（指 `字幕样式/` 下的 中文/英文 × 横屏/竖屏 四份 ASS 样式。）

## 我查到的

**那四份样式当时一份都用不上，三层原因叠在一起，每一层都不报错。**

### 第一层：设置页没有选样式的控件

字幕那张卡做了「压制画质」，**没做样式选择**。`grep sbStyle` 是空的。

### 第二层：程序硬写了一个不存在的样式名

`core/subtitle.py` 的 `DEFAULTS` 里写着 `"style": "default"`，
每次生成的 config.toml 都是 `style = "default"`。而
`videocaptioner style` 列出来的只有那四份 —— **没有叫 `default` 的样式**。
它输出里那个 "default" 是提示句 "use default style" 里的一个词。

### 第三层：软字幕下样式根本不生效

VideoCaptioner 自己在样式清单末尾写着：

```
Note: Styles only apply to hard subtitles (--subtitle-mode hard).
      Soft subtitles are rendered by the video player.
```

而默认是 `soft`（2026-08-27 上一轮定的）。**软字幕的样子是播放器决定的。**

### 第四层（补完前三层之后才露出来）：竖屏样式被放大 1.78 倍

`videocaptioner/core/subtitle/ass_renderer.py`：

```python
reference_height: int = 720
scale_factor = height / reference_height
style_str = _scale_ass_style(style_str, scale_factor)
```

`height / 720` 的前提是「720P = 1280×720 的**横屏**片」，取的是短边。
而竖屏 720×1280 的 `height` 是 **1280**（长边），于是：

| 中文竖屏标准版 | 写的 | 实际渲染 |
| --- | --- | --- |
| 字号 | 40 | **71** |
| 描边 | 2.6 | **4.62** |
| 底边距 | 138 | **245** |

横屏那两份高度正好 720，×1.0 分毫不差 —— **这个坑只在竖屏踩到，
而短剧全是竖屏**，也就是说用户唯一会用的那两份正是坏的那两份。

实拍验证：18 个字一行（`max_word_count_cjk` 的默认值）按 71px 要 1278px，
画面只有 720px 宽，**两头各切掉三个字**，抽帧截图确认。

## 要你定的

| 问 | 答 |
| --- | --- |
| 软字幕还是硬字幕 | **改成硬字幕，让样式生效** |
| 四份怎么选 | **下拉手选，不自动按比例猜** |
| 缩放怎么处理 | **studio 自动补偿，所见即所写** |

## 怎么修的

### 1. 默认改成硬字幕

`DEFAULTS["subtitle_mode"]` 由 `soft` 改成 `hard`。代价照实写在页面上：
整片重编码（慢、掉一次画质、字幕不可关）。

### 2. `style` 默认由 `"default"` 改成 `""`

空 = 不写这个键，让它用自己的默认。**不能填一个不存在的名字** ——
那种错的表现是「字幕照出、但还是默认样子」，不报错。

### 3. 设置页加样式下拉，候选从 VideoCaptioner 实拉

新增 `/api/subtitle/styles` → `subtitle.list_styles()`。

**不列我们自己的 `字幕样式/` 目录。** 我们只是把自带的四份装进去
（`core/captions.install`），用户在它那边自己加的、改的、删的都算数，
而那些我们目录里没有。列我们的目录 = 页面上列四份、实际可用的是另一批。

下拉里带上字号和底边距（`40号 · 华文楷体 · 底边距138`）——
「中文横屏标准版」和「中文竖屏标准版」光看名字分不出哪个配 9:16。

存着的样式名在候选里找不到时**保留并标出**「⚠ 现在找不到这份样式」，
不静默改成默认 —— 那会把「名字写错了」变成「样式莫名其妙没生效」。

### 4. 竖屏缩放补偿：`style_override()`

跑的时候按**成片的真实分辨率**（`probe.video_size`，不是设置里的意图值）
算出它会乘多少，把样式值预先除掉，用 `--style-override` 发过去。

顺序是关键：`style_override` 在 `to_ass_string()` **之前**合并，
而缩放在之后 —— 所以覆盖值同样会被乘，必须先除。反过来的话就不该除。

四个被缩放的字段（`font_size` / `outline_width` / `spacing` /
`margin_bottom`）**全都要补**：只补字号的话，描边和底边距还是 1.78 倍，
字幕又粗又高，跟写的完全不是一回事。副样式（双语第二行）同理。

只在竖屏补。横屏本来就对，去动它等于制造一个新问题。

实拍验收：

```
补偿前  18 字只看得见 12 个，两头切掉；字号 71、底边距 245
补偿后  18 字全部放下，两边留白；字号 39（≈40）、底边距 138 ✓
```

### 5. 硬字幕的「做过没有」不能看字幕轨

**从软字幕切到硬字幕时最容易中招。** 硬字幕是烧进画面的，
文件里查不到任何字幕轨；而源成片上可能还留着上一轮压进去的字幕轨，
于是判「已经有了，跳过」——**用户改了设置却什么都没变，且不报错**。

所以硬字幕只认产物文件在不在。`run()` 和 `status()` 两处判据必须一致，
否则预览说「0 集要配」而实跑又做一遍。

### 6. 两种静默失效在开跑前就拦

`config_problems()` 新增两条：软字幕 + 选了样式、样式名找不到。
都是「字幕照出、样式没生效、没有任何报错」那一类。
页面上也当场标黄，不用等点了「开始」才知道。

样式列不出来时（VideoCaptioner 没装好）**不拦** —— 那是「没装」该报的事，
在这儿再报一遍只会把人往样式上引。

## 为什么会有这个问题

上一轮做字幕接入时，我把 `style` 当成一个「填了就行」的普通配置项：
写进 DEFAULTS、写进 config.toml，然后**既没做界面、也没验证它真的生效**。
四层失效里没有一层会报错，所以测试全绿、自检通过、跑完有产物 ——
而用户备好的样式一个字都没起作用。

更根本的一条：**外包一个环节时，只验证「它跑完了」是不够的，
要验证「它按我给的参数跑的」。** 前三层都是参数根本没传到，
第四层是传到了但被它改写了。这四层都只能靠**看渲染出来的画面**发现，
看退出码和产物是否存在一律是绿的。

## 修完能避免什么

- 那四份样式能选、能生效，且**所见即所写**：写 40 号就是 40 号，
  写底边距 138 就是 138，18 个字一行正好放得下。
- 以后自己加样式，下拉里自动出现，不用改代码。
- 软/硬、样式名这两种静默失效，在开跑前就报，不用先烧一次重编码的时间。
- 从软切到硬（或反过来）时会真的重做，不会被「已经有字幕轨了」骗过去。
