## 定性与范围

现有产品保留“由 Studio 驱动 LLM 各环节”的页面和运行路径，但用户主流程已转为 Codex 编译材料。项目创建、契约和材料导入分散；契约没有完整项目绝对路径上下文；资产按类别列表展示，不能按实体树与集统一选择。仅藏流程页不能解决生产自动改写及字幕内隐含的 LLM 调用。

改造涉及创建、项目检索、完整技能包版本与默认值、Codex 契约、材料直写发现、两套旧项目、新 v7 计划、资源树、选择与依赖、生产失败修订、字幕及可选功能。详细方案见 `docs/design/codex-production-v7/架构方案.md`。

## 三项产品选择

1. 功能显示：**用户已确认按功能包隐藏页面和入口，先不做多人账号**。不把此开关描述为安全权限。
2. Codex 启动：推荐创建项目后生成模板，由用户交给 Codex；备选为 Studio 直接启动并跟踪 Codex。**待用户确认**。原型暂采用前者。
3. 旧项目：推荐继续查看和生产，所有旧 LLM 入口移除，新项目统一 v7；备选为旧项目只读、转换后生产。**待用户确认**。原型暂采用前者。

## 本轮交付

架构方案、创建选项及默认来源、资源树与磁盘映射、直接落盘协议草案、Codex 模板示例、实现分期与验收条件、可交互虚拟 UI。用户可先试用并修改，再确认正式实施范围。

当前方案解决的是责任与契约不一致：创建时锁定本机路径和完整技能版本；Codex 直接生成约定清单；Studio 自动验证并加载；通过资源选择与依赖计划控制实际生成。这样下一次不需要用户手工搬材料和猜解析格式，也不会因取消一个参考图而静默改变视频输入。

本轮没有修改 core/server/web 正式程序、没有创建真实项目和服务商任务。原型数据与按钮均为模拟；目录监听、文件写入、调度和新 API 是后续开发事项。
