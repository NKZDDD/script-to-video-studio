# 接入红鸟视频服务商

日期：2026-09-23
起因：用户提供 OpenAPI 文档、地址和测试凭据，验证模型查询可用后要求“接入，名字是红鸟”。

## 定性与范围

红鸟地址为 `https://an.hongniaoai.com/api`，Bearer 鉴权；使用 `/v1/videos` 创建任务、`/v1/videos/{id}` 查询。完成结果为顶层或 result 下的 video_url。模型列表不同于标准 OpenAI 数组，位于 data.models，逐模型参数在 tasks[].parameters。

现有通用目录解析只认 data 数组，直接新增名称会让“拉取最新模型”失败；只使用通用轮询还可能把已经提交/完成后的查询或下载失败当成可重试生产。因此接入必须同时覆盖目录格式与已提交任务的错误处理。

本次范围为 Studio 服务商适配，不修改批量工具或 ComfyUI 节点。当前凭据只返回 5 个视频模型，不根据文档示例虚构图片模型。

## 实施

- 新增内置 `hongniao`，显示名称“红鸟”，加入冻结 EXE 的服务商发现清单。
- 内置 2026-09-23 实拉的 5 个视频模型与各自时长、比例和参考素材数量；模型目录识别 data.models，并提取公开参数更新页面选项。
- 图像以 URL/Data URI 传入，视频与音频参考传公网 URL；时长按文档传字符串，支持 resolution、parameters 和 metadata。未硬编码服务商未声明的图片大小限制。
- POST 创建只发一次；记录任务 ID。临时查询失败继续查询同一个任务，完成后立即下载；完成缺 URL、下载失败、提交回执不确定和超时均明确报错，避免自动重复付费提交。
- 复用下载完整性校验和原子落盘；结果 CDN 不携带红鸟 API Key。真实 Key 不写进源码、测试、插件或交付包。
- 同一适配文件使用绝对导入，可交付为现有 EXE 的 providers 外挂；旧 EXE 的目录刷新仍受旧解析器限制，内置 5 个模型和连通性测试可用。

## 验证

- 全量测试 2678 项通过（188.78 秒，退出码 0），日志 `outputs/hongniao-tests.log`。
- 新适配器实际请求红鸟：鉴权自检通过，目录刷新返回 5 个模型，时长/比例/参考素材数量映射正确；未创建付费任务。
- 本地 HTTP 服务验证完整的创建、查询、结果下载，确认 CDN 请求不携带 Key；覆盖 HTTP 200 内业务错误、失败原因、提交不确定、下载失败、完成缺 URL、超时和取消等分支。
- 用此前发行的 Studio EXE 在隔离数据目录加载同一外挂文件，确认启动成功且 bootstrap 中出现“红鸟”和全部 5 个模型。报告：`outputs/hongniao-plugin-qa/20260923-113843/results.json`。
- 交付外挂文件及安装说明；不在本次接入中重新构建 Studio EXE。

以后选择红鸟即可按它的协议提交和取回视频；刷新模型不再因 data.models 的不同包装被误判为空，已提交任务的查询或取回异常也不会自动重新付费创建。实际生产成功率仍需后续付费任务验证。
