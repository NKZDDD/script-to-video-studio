# 将字幕模块拆成独立 Windows 程序

日期：2026-09-22
起因：用户要求“我需要把字幕模块剥离出来，单独一个程序”。

## 我查到的

现有字幕处理通过 VideoCaptioner 和 FFmpeg 执行，但入口绑定 Studio 的项目对象、成片目录、项目配置和任务管理，不能直接作为面向任意视频文件的独立程序使用。

- `core/subtitle.py`：旧版完整字幕配置、识别、优化/翻译选项、样式微调和压制流程，输入来自项目成片。
- `core/captions.py` 和 `字幕样式/`：四份中文/英文、横屏/竖屏样式、自定义样式安装和 FFmpeg 准备。
- `core/agent_post.py`：新版识别和压制入口，明确关闭文字优化和翻译，只允许项目 `06_成片/` 内有效 MP4。
- `server/app.py`、`server/agent_api.py`：旧、新版配置与任务接口。
- `core/pipeline.py`、`core/pipeline_v34.py`：两套旧流水线的字幕环节。
- `run.py`、`打包exe.py`：字幕命令行入口和发行包依赖。

拆分需要独立的文件输入、输出目录、设置、任务状态和打包入口，不能只复制一个字幕处理文件。

## 拟定使用方式

独立 Windows EXE；直接选择视频或文件夹，设置输出位置；保留原视频，生成字幕文件和带字幕视频。复用现有字幕引擎和四份样式，不依赖 Studio 项目材料、服务商生产任务或 Agent 模板。

## 要确认的范围

### 1. 独立程序保留哪套功能？

- A（推荐）：完整字幕功能。保留旧版识别、纠错、翻译、样式微调和压制，纠错/翻译可选，默认关闭。满足独立字幕用途，但配置项较多。
- B：新版精简功能。仅识别、选择样式、输出字幕和带字幕视频；使用更简单，不提供纠错和翻译。

### 2. Studio 原来的字幕入口如何处理？

- A（推荐）：先保留，独立程序单独交付。现有用户与流水线仍能照常使用。
- B：同步移除 Studio 字幕入口和对应打包依赖。实现彻底拆分，但需要修改两套旧流水线、新版后期入口和 Studio 打包配置。

## 用户回答

用户确认：“修复流程已经完成了，可以继续拆成独立的exe原程序不需要了”。

按完整功能创建独立字幕工作台：直接选择视频/文件夹、已有字幕和输出目录；识别、可选纠错/翻译、样式微调、字幕导出及硬/软字幕合成。纠错与翻译默认关闭。独立设置目录，不需要安装或启动 Studio。

实现放在 `subtitle_app/`，发行构建只带字幕处理所需模块和四份样式，不包含 Studio 服务端、Agent 模板和项目资源。每次输出独立目录，原视频和导入字幕保持不变；识别与压制之间显式执行可选的字幕优化/翻译步骤，防止配置打开但实际未执行。
