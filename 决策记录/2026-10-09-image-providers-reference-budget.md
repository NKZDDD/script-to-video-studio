# 沧元、超模香蕉和坤鸡合入主程序，统一参考图体积与图片格式

日期：2026-10-09

## 用户要求

将提供的 `zz_cangyuan.py`、`zz_chaomo_banana.py`、`zz_kunji_latest(1).py` 合入 Studio，按沧元文档修改接入；兼容参考图小于 10 MB 的限制；区分比例、像素尺寸和模型通道决定的清晰度；解决 JPEG 返回与 PNG 任务路径不一致导致的失败。

## 为什么会有这个问题

- 用户提供的沧元外挂使用 multipart 和统一九张参考图截断，与当前官方逐模型文档的 JSON `images` HTTPS URL 协议不一致，并会静默改模型或忽略清晰度。
- 旧界面将像素尺寸和档位混用，清晰度只允许硬编码的 1K/2K/4K，忽略模型不同的参数能力。
- `HttpSession._save_once` 按任务扩展名检查真实格式。返回 JPEG、目标 `.png` 时，完整图片也被判为错误。昨天香蕉测试保存到 `.jpg`，未覆盖生产 PNG 路径，所以未发现。用户外挂仅处理部分 base64 返回，不能覆盖 URL 下载和其他适配器。
- multipart、data URI、对象存储准备路径没有统一文件字节预算，未缩尺寸的参考图可能直接超过网关限制。旧对象存储缓存也可能继续使用超限文件。

## 范围和实现

共用图片保存层先检查返回图片完整性，再按任务扩展名真实转码，不改像素尺寸；支持 URL、data URI、裸 base64。HTML、截断或不可解码内容仍拒绝，失败不会覆盖旧产物。超模元数据比较转换前字节数，避免转码后的 PNG 大小造成误判。

共用参考图准备覆盖图片/视频生产、字节上传、内联数据和对象存储；默认单张预算 9,500,000 字节，兼容常见十进制 10 MB 上限。这是用户要求的本地保守策略，不表示所有服务商文档都限制 10 MB。低于预算且无指定尺寸/格式时字节不变；超限先压缩上传副本，必要时缩尺寸，记录处理前后信息，保留原素材和透明通道。远程图片也先下载验证体积，超限后重新上传副本。缓存版本更新，避免复用旧超限 URL。

沧元以官方 31 个图像公共模型逐个声明比例/像素/固定档位/独立参数和参考图数量。不统一截断到九张，不自动换计费通道。Gemini 用比例 `size` 和 `quality`；GPT `-x` 用 `tier`，2.5-x 同时提供 `series`；固定后缀模型不重复传 tier。参考图需要已配置 HTTPS 对象存储。异步任务按原创建路径查询，每次只创建一个任务；结果下载失败继续沿用原 ID。Midjourney 若 n=1 仍返回多图，遵循 Studio 单任务单文件契约，保存第一张并明确记录数量。

超模香蕉独立 provider ID / Key，保留用户提供的三种模型、multipart 参考图和 `image_size` 参数，Flash / 2.1 的 512 档也由能力声明显示。坤鸡五个香蕉名继续走 Gemini，比例与清晰度分开；旧任务 `size=1K/2K/4K` 保留档位和原来的自动比例行为。适配器不再静默截断参考图或丢弃无法编码的输入。

生产页按模型显示比例选择、像素尺寸输入、清晰度或“模型固定 4K”，切换模型清除不兼容参数；固定通道/像素模式会去掉旧任务不再适用的独立清晰度。新服务商加入 EXE 冻结加载清单。并发准备同一内容哈希参考图时复用已发布完整缓存，不因 Windows 正在读取而强行覆盖失败。

## 修完能避免什么

JPEG 正常结果不再因为 PNG 任务路径被当失败；无效内容仍不进入产物库。超限参考图在提交前变为符合预算的上传副本，不覆盖原图、不漏参考图。尺寸不会因为选了 4K 就被误当比例，也不会偷偷改模型通道。旧香蕉任务保留原来的清晰度，512 等模型声明档位可以在界面选择。
