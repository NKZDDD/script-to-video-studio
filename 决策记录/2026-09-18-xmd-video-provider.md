# 接入 XMD 视频，并在上传前保证单张参考图不超过 10MB

日期：2026-09-18

起因：用户原话：「这个服务商想要接入，他有要求图片不能超过10MB」。附件为 `# 视频生成 API 接入说明.txt`。

## 定性和范围

现有注册表没有这家服务商。其 API Key + Secret 的 HMAC 签名与通用 Bearer 请求不同；直接套通用网关会鉴权失败。单张 10MB 是这家 `/v1/images` 的明确限制，而通用参考图策略默认原样发送，因此需要在这家的上传入口对实际字节做限制。

这是新增协议支持，过去的服务商测试不覆盖该签名或上传限额，不能用其它服务商的成功结果证明它可用。另查到模型刷新独立于 Provider.list_models，会直接构造 Bearer 头；该服务商没有 `/v1/models`，也需阻止整段 Key/Secret 被当作通用 Key 发出。

电影级和通用体系、一键生产和单独出片都经 `core.produce.make_video_worker` 及服务商注册表。新增 `core/providers/xmd.py`，声明 `ref_mode=bytes`，使本机参考图交由适配器上传，不被全局 R2 设置提前转换。公网图也在该适配器中读取并检查。图片生成的资产图、场景状态图、故事板以及其它服务商不受此次限制影响。

## 实施选择

- 依文档接入上传、签名、提交、查询、下载及只读账户探活。名称暂按域名标为 XMD。
- 10MB 按 10,000,000 字节计算。限额内逐字节保留；超限时处理上传副本，先压缩、再按需等比缩小，保留 PNG 透明度及本地原图，并记录处理结果。
- 只开放文档中的模型、30 秒时长和六种比例；提示词超过 3000 字符、参考图合计超过 10 张、错误模型/时长等在提交前报错，提示修改位置，不静默截断或丢图。
- 单次 HTTP 提交重试复用订单号，每次签名采用新 nonce；轮询网络错误继续查原任务。使用现有共用结果下载逻辑，成功后的下载失败不会被重新提交生成。
- API Key 框兼容一行 `api_key=…;api_secret=…`，无需修改已发布 exe 的凭据表单；Secret 不在页面回显，也不会传给下载端点。
- 源码加入内置清单，同一适配器文件可作为已有 exe 的外挂插件。固定模型刷新在源码中直接跳过；插件也禁止旧 exe 将组合凭据作为 Bearer 发出。
- 真人图库必须先在服务商网页过审。适配器可接收显式 `VideoTask.extra.gallery_ids/shield`；现有 Studio 页面没有图库选择或视频盾开关，本次不扩展为图库管理产品，也不自动选择账号人物。

## 避免什么

超限原图以后不会原样撞上这家的 10MB 拒绝：上传前会生成达标副本，日志可见处理前后大小，磁盘原图保留。限额内图片仍逐字节发送，其它服务商的图不会被一同压缩。

该服务商会使用文档要求的精确请求体签名，而不是 Bearer 头；模型、时长和图片数量错误在付费提交前明确暴露。结果成功后会立即进入下载阶段，继续使用原结果地址的超时重试。

## 验证和交付

- `py -m pytest`：**2463 passed in 91.79s**，新增 49 项 XMD 用例。
- 针对超过 10,000,000 字节的真实 RGBA PNG 验证上传达标、透明度保留、磁盘原图 SHA-256 不变；JPEG/WebP 压缩及限额内逐字节保留也有测试。
- `build/verify_xmd_plugin.py` 用隔离数据目录启动已有 `0fe3a3b` exe，在本机模拟接口验证插件加载、HMAC 请求、PNG/JPEG/WebP、multipart、生成/查询/下载、页面不回显凭据。模拟视频只用于 HTTP 与落盘检查，不代表真实生成画质。
- 用户尚未提供真实凭据；未调用真实服务商，不产生生成费用。实际服务商的可用性和生成质量仍需配好凭据后验证。
- 接入说明见 `docs/XMD服务商接入.md`；插件交付为 `dist/XMD-服务商插件.zip`。
