# 外部资产图放进文件夹后仍显示待生产；加批量放图

日期：2026-09-25
起因：

> 我还有一个疑问就是我从别的地方获取的资产图用codex分析后放入了文件夹在输出部分有看到他的路径为什么还是待生产呢

截图：`PRJ_JZJ__CHAR_0002_R01`，输出 `02_固定资产/人物身份资产/0002-云黑 - 奶满法老叔叔.png`，状态待生产；顶部「671 项待生产 · 0 项可复用」。

## 我查到的

- 「已完成」只看输出路径上是否有一张完整的图（`agent_runtime.valid_output`：存在、≥512 字节、内容和扩展名一致、有收尾标记、能完整解码）。
  详情里的「输出」是程序要找的位置，不是文件已经在那里的证明。
- 截图里的详情没有「删除产物…」按钮。这一版里只要输出路径上有任何文件（`t.exists`，坏的也算）就会显示这个按钮 ——
  所以那个路径上没有文件。全项目 0 项可复用，说明是成批对不上。
- 契约写的是「已有外部图片应登记为资源和任务后由用户手动放图」（`agent_projects.contract`）；Codex 自己把图放进文件夹时，
  名字、扩展名或子文件夹和任务的输出路径不一致就不算；Codex 在另一台电脑上时，发布包只带 `03_提示词/releases/`，图不会跟着回来。
- 手动放图原来只能一张一张放，而且项目里有任何批次在跑就拒绝。

用户选了「要，按文件名对应、先预览再放」。

## 怎么修的

- `core/bulk_place.py`：按文件名对应出图任务 —— 和输出文件名相同 100 分、和任务 ID / 资源 ID 相同 95、和资源名称相同 90，
  包含关系递减；NFKC 归一（全角半角）、不分大小写、去掉空格和常见标点；中文文件名两个字就能按包含对上。
  同分的不替人挑；两个文件对到同一个任务只留分高的；已有文件的任务不选。
- `/api/agent/place-plan` 返回对应结果；真正存图仍走 `/api/agent/manual`（按输出格式转换、完整校验、原子写入、不覆盖已有文件）。
- 手动放图改成只拒绝「这一条正在生成」，别的批次在跑也能放。
- 页面：生产页标题旁「批量放图…」，选文件夹或多选图片 → 对应表（下拉改选、输入任务 ID 手动选）→ 放进去，逐张显示结果。

## 为什么会有这个问题

程序判断「做过没有」只认输出路径，而这个路径是 Agent 发布任务时定的。外部拿来的图经过 Codex 整理，
文件名、格式、子文件夹稍有不同，程序就当它不存在，而页面上看到的是程序要找的路径 —— 看着像「路径就在那里」，
其实是「那里还空着」。唯一的纠正办法是手动放图，一张一张来，几百张不现实。

## 修完能避免什么

以前外部拿来的一批图要么逐张手动放，要么自己对着每条任务的输出路径改名挪文件，漏一个字就还是待生产，
而且会被当成没做过、重新花钱生成。现在选一次文件夹，程序列出每张图对应哪条任务，确认后一次放完；
对不上的、会重名的、已经有图的都在表里写明，不会悄悄放错或覆盖。

## 后续：文件夹后面的数字（同日）

> 是展示的数有问题里面有已完成的然后显示还是0

用户确认说的是生产树里文件夹后面的数字。那个数原来是「勾选了几条 / 共几条」，跟完成与否无关，
所以一组里已经有「已完成」的条目时它照样可能是 0（没勾）或满数（全勾）—— 看着像完成数，其实不是。
改成「已完成 a/b」，没全选时后面另标「选中 c」；勾选状态仍由文件夹前的勾选框表示。
以后放完图，文件夹后面的数会跟着涨，不会再和里面的「已完成」对不上。

> 选中数和完成数都显示

改成两个数一直都显示：「已完成 a/b · 选中 c/b」。
