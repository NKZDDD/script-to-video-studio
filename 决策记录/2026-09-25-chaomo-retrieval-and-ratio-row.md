# 超模图片回收慢是否还在；比例参数放到生产页服务商那一行

日期：2026-09-25
起因：

> 超模的图片回收慢问题还存在吗？以及超模还是有出现比例问题，比例参数也需要放到外面服务商选模型那边

## 我查到的

**回收慢**：指的是 2026-09-18 那条（`决策记录/2026-09-18-completed之后下载不返回.md`，提交 `0fe3a3b`）——
超模显示 completed 之后，下载沿用 900 秒超时，停在那里十几分钟，失败后还会重新提交生成。
当前代码里修复仍在：`core/apiutil.py` `HttpSession._save_once` 下载用 15 秒连接 / 30 秒停传超时，
`save_item` 停传只重取同一结果最多 3 次、不重新生成，持续失败报 `result_download_failed`。
超模 `generate_image` 的日志分段也在（开始下载 / 正在下载 x MB / 结果已保存 / 核验 / 已就绪）。
9 月 24 日打的 EXE 包含这次修复。本机没有真实项目记录，无法确认用户那台机器上是否还有别的慢点。

另一处会让出图「看起来慢」的：2026-09-24 修的调度问题（有任务在跑时不回来看别的已就绪任务），
场景状态图等依赖别的类别产物的图也受影响。这条修复只在源码里，EXE 里还没有。

**比例**：代码里比例怎么到超模的——
Agent 任务里写的 `params.size` → 生产计划按超模声明的十个比例校验（`core/agent_runtime.py` `preview`）
→ 出图时原样交给超模 → `_to_ratio` 转成 `ratio` 字段发出（文生图 JSON、图生图 multipart 都带）。
发出去的就是任务里写的那个值，程序没有改它。所以出现比例不对只有两种可能：
- 任务里写的比例本身不是想要的（Agent 写的）；
- 请求带对了，超模这个模型没按它出（出图后 `_ratio_warn` 会挂「比例不对」提醒，写明请求发的是什么、回来的是多少像素）。
第二种里有一个未证实的疑点：有参考图时走 `/v1/images/edits`，这条端点是否遵守 `ratio` 没有文档或实测依据，
可能按参考图的形状出图。本机没有真实记录，且验证要真实付费出图，这次没有测。

以前比例只能在打开「高级参数」功能包后，在每一行填一个文本框覆盖；平时页面上改不了。

## 这次做的

用户说的就是位置，只有一种做法，没有另外问：
- 生产页「本次服务商与并发」每一行加「比例」下拉：图片行改 `size`，视频行改 `ratio`；
  选项是当前模型声明支持的（超模十个比例），选「跟随任务」就用每条任务里写的。
  存在 `production-settings.json` 对应那一类里，生产计划时覆盖任务参数，也就是发给服务商的值。
- 选的值当前模型不支持时，生产计划直接挡住，报「这一行选的 X 与服务商支持的 … 不兼容」。
- 生产计划里写出「比例按 X 传给服务商」。
- 高级参数里重复的比例 / 尺寸框去掉。
- 窄屏下服务商行重新排：服务商、模型各占一整行，比例 / 清晰度 / 并发一行（以前模型框被挤进 80px 的一列）。

## 为什么会有这个问题

比例一直是「任务里写死、页面上不可见」：Agent 发布时就定了每条任务的比例，
生产页只能选服务商和模型，改比例要开高级参数功能包、再往文本框里手填。
所以一旦 Agent 写的比例不对、或者换了一家只认某几种比例的模型，人在生产页上没有地方改。

## 修完能避免什么

以前资产图出成竖的，只能去让 Agent 改发布、或者开高级参数手填；现在在资产图那一行选 16:9 再生产就行，
生产计划里能看到这次按什么比例发。选了模型不支持的比例，开始之前就会被挡住，不会发出去再出一张形状不对的图。
如果请求带对了、超模还是出错形状，任务上的「比例不对」提醒会写明请求和实际像素 —— 那就是模型没听，
换一档模型，或者把这类有参考图的活换一家。
