# 允许独立 C → AB 双联板，并让视频 IN_C 直接引用独立 C

日期：2026-10-19

起因：用户提供「独立 C → AB 双联板」和 V4.0 最小扩展适配截图，询问是否需要修改 Studio，随后要求「完成修改」。

## 定性与范围

原生产契约规定 C 是 ABC 整板派生的区域图，视频 IN_B/IN_C 来自同一整板。`core/agent_projects.py` 发布校验会拒绝独立 C；`core/matimport.py` 又按 key 中的 ABC 判断整板，独立 C 若沿用 ABC 家族命名，会被归入整板目录。此前规则服务于原 ABC 三分板，所以旧测试一直通过；只改提示词无法改变结构化任务分类、来源校验及依赖关系。

本次范围是 Agent 发布入口和 JSONL 材料导入入口、对应 schema 和生产契约。保留原 ABC 流程、字段含义、Image 编号、片段时长、上传和调度机制，不调整服务商接口，不修改已锁定的创作技能快照。

## 已确认的实现

- 独立 C 增加可选字段 `"handoff_mode":"independent_c"`，不填写 region/board/parent。用显式标记区分，避免凭名称误判旧项目的派生 C。
- JSONL 仍用 `kind:"image"`，独立 C 落到 `03b_场景状态图`；Agent 发布放到 `scstate_tasks`。
- AB 仍使用整板任务，直接引用一张独立 C；允许同时引用必要的身份资产。A/B 区域各自唯一引用该 AB，不再从该 AB 派生区域 C。
- 视频 `IN_C` 可直接引用独立 C。如果同时有 `IN_B`，校验其来源 AB 确实引用同一独立 C；不能将新 AB 的 B 与旧 ABC 的区域 C 混用。OUT_A 可属于另一出站边界。视频不得直接上传整板，独立 C 不得在两组引用中重复上传。
- 两个入口共用 `core/independent_c.py` 校验。未声明扩展的旧 ABC 材料继续遵守原规则。
- 新项目契约、离线交付包和定向修订说明包含扩展。旧项目打开时仅向生产契约追加扩展说明，不改旧锁、已接受发布或产物。
- 旧项目采用新流程需要重新导入材料或发布新 revision，仅改提示词不足以替换引用结构。可以继续使用原 ABC 流程，不强制迁移。

## 如何使用及排错

参考 `examples/独立C-AB双联板-生产材料.jsonl`：包含独立 C、AB、A/B 区域、两段 15 秒视频，展示出站 OUT_A 和入站 IN_B + IN_C。它是结构与引用示例，不代表用户项目的成品提示词。

若导入提示 `INDEPENDENT_C_SOURCE`，应将 IN_C 指向 IN_B 所属 AB 实际引用的独立 C；若提示 `AB_REGION_C`，应去掉该 AB 的派生 C，直接引用上游独立 C。原三分板项目继续沿用原材料即可。错误需在材料中改正并重新导入/发布，不通过忽略来源校验继续付费生产。

## 修改结果与验证

修改后，显式声明的独立 C 能进入正确任务类型；依赖按 C → AB → A/B → 视频执行，视频真正上传 B 和独立 C。来源不一致会在导入或发布时定位到具体任务，避免到付费出图/出片时才发现引用错板或缺图。

专项覆盖导入、发布、旧契约追加保护、离线契约导出、错误来源拦截、真实调度依赖顺序、视频请求参考图顺序及不重复上传。独立 C 专项 17 项通过；最终代码执行 `py -X utf8 -m pytest -o addopts='' -q`，3335 项全部通过（177.89 秒）。生产请求使用测试服务商，不发起付费生成。
