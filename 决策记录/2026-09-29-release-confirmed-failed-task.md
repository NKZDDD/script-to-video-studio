# 服务商明确失败后自动解除旧任务 ID

用户要求：服务商明确失败旧不需要我放弃了呀直接显示失败即可，这样下次提交就应该是新任务了。

## 原因与范围

此前固定 ID 的实现把明确生成失败、查询异常、下载失败统一包装为 submitted_pending，保留 submitted 文件。页面优先看到 submitted 就显示“已提交待取回”，因此服务商已经失败，页面仍提示取回。

共享轮询的 task_failed 与巨轮使用同一失败构造函数；Gate、好漫剧、红鸟、XMD 自定义轮询需要同时标记。task_finished 也用于查询 404，不能用它作为明确生成失败的凭据。

## 实施

- 只在服务商轮询明确返回失败状态的分支增加 provider_task_failed 标记。
- 图片和视频共用的 _deliver 收到标记且存在旧 ID 时解除记录，保存原始失败原因与任务 ID，返回独立诊断 PROVIDER_TASK_FAILED。
- 该错误本批不自动重试、不改写、不切换服务商。下次用户重新生产才使用最新提示词、参数、模型提交。
- 原 UI 状态逻辑自然回落到“失败”；查询、下载、文件检查异常及 404 保留旧 ID。
- 无需迁移旧记录。旧记录再次查询确认失败后也解除；不解析历史错误字符串来猜测状态。

## 避免的问题

明确失败的任务不再一直显示待取回，也不必逐条手动放弃；网络或下载问题不会被误当成生成失败而重复计费。
