# 服务商监测改为完整页面并修正表单布局

日期：2026-11-02
起因：用户要求“我需要完整页面而且这个UI是不是有问题”，提供监测弹窗横向滚动、复选框整行拉伸的截图。

## 定性与范围

原 `web/provider-monitor.js` 使用默认最多 660px 的 dialog，却继承 `style.css` 的表格最小宽度 850px；普通 label 使用 grid，checkbox 又继承所有 input 的 width:100%。服务商和检测 Key 的两列表单套用带 20px padding 的工具栏，加重了留白。原 UI 测试只验证自动/手动字段切换，不验证布局，因此功能检查通过时仍会出现截图中的错位。

范围为账号后台的服务商监测入口、两张结果表、自动/手动配置和登录状态切换。用户明确要求完整页面，无需再确认页面与弹窗方案。客户端监测协议、生成接口、授权关系均不涉及。

## 实施

- 使用 `/admin/#provider-monitor` 独立页面，保留公共页头，返回账号管理恢复列表，支持浏览器返回和刷新。
- 监测专用样式覆盖表格最小宽度；表单用两列网格，复选框固定 18px 并同行展示文字，窄屏使用单列和结果卡片。
- 单独更新结果，不重建表单；手动刷新和定时刷新均保留未保存输入。离开页面或退出登录停止刷新，迟到响应不再写回。
- 显示实际发布的适配包版本和可用规则数量；缺规则时明确提示“导入并发布”，提供适配包管理入口。
- 服务端版本 1.11.2；沿用适配包 2026.11.02.3 和 EXE 2026.11.02.2，无需重打客户端或更改推更策略。

## 避免的问题

监测不再受默认弹窗宽度限制，复选框不再被文本输入样式撑开；管理员编辑时结果仍持续刷新，且不会丢失未保存内容。缺规则时能看到实际发布版本，区分尚未发布新版与对应服务商缺少规则。

## 验证

专项验证自动/手动字段切换、手动值保留、页面返回、登录状态切换与迟到响应丢弃；API 验证样式文件可访问、未发布及旧包无规则状态、新包版本与规则计数。
