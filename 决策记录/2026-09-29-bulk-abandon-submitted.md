# 批量放弃已选待取回任务

日期：2026-09-29。

用户问题：失败的任务下次是否使用新参数；旧任务是否兼容固定 ID；是否需要批量放弃。

## 规则与原因

固定 ID 规则意味着失败不再隐式删除已有任务。保留 ID 时再次生产仍取回最初提交的内容；明确放弃后，下一次开始生产才会使用新的提示词和生产计划参数重新提交。旧 submitted 记录无需迁移，identity 不再参与一致性检查；没有保存任务 ID 的更老版本，不能凭空恢复历史编号。

旧界面只能逐条放弃，用户有多条失败或不再需要取回的任务时操作繁琐，容易遗漏。本次增加明确选择的批量入口，不改变默认取回策略，不自动放弃所有失败任务。

## 实施

- 生产页勾选工具栏新增“批量放弃已选待取回”。只处理当前项目已勾选、有 submitted 记录、没有有效成品的任务。
- 确认框显示数量和任务名；筛选隐藏的勾选项也计算在内，明确提示隐藏数量。用户可以取消。
- 前端发送每一项的 key 和当时看到的 task_id。后端整批先检查有效性及 ID 是否变化，再执行清除；过期页面不能删除新的任务记录。重复 key 去重。
- 项目正在生产时要求停止并等待退出；以 finished_at 确认真正结束，点击停止后只有 cancelled 状态、旧调用仍在退出时也拒绝清除。批量检查与清除使用生产入口共享的 LOCK，避免与新批次启动交错。
- 已完成或已无待取回记录的项跳过；保留有效成品、未选记录、选择状态及参数。此操作只解除本地 ID 绑定，不调用服务商取消接口，不自动生成。
- 完成后使旧生产计划失效，提示核对参数、重新查看计划，再开始生产。

## 验证

- 专项 41 passed：覆盖限定选择、重复条目、整批过期 ID 拒绝、错误输入、运行阻止、项目隔离、成品保留、取消确认及前端真实函数执行。
- 验证移除旧记录 identity 字段后仍取回原 ID；手动放弃后真实 worker 提交使用新的提示词、20 秒、16:9、720p，提交次数从 1 增至 2。
- Node 语法检查通过。
- 补充取消后仍在退出的保护，批量功能专项 15 passed（11.14 秒）。最初版本单独应用于干净版本：14 passed（11.64 秒），没有夹带其他未提交功能。
- 全量测试：2854 passed（265.55 秒）；另补充的取消后退出保护由上述 15 项专项覆盖。

## 交付

本次是主程序和页面源码改动，尚未打包 EXE。旧 EXE 需要更新主程序，巨轮下载续传外挂不包含这个入口。

这样用户能一次明确放弃多项任务，不必逐条操作；之后按新参数重新生成仍需查看计划并主动开始，不会因批量放弃而立即产生新的计费任务。
