## 我查到的

## 实施与问题机制

此前登录只控制页面访问，本机配置独立供生成使用，没有账号与任务统计的关联。本次增加按账号保存的服务商分配与用量表、后台配置/对账页面、CSV 导出。有效校验返回该账号的配置，客户端仅在内存中覆盖调用参数，不改写个人 config.json；后台 Key 绑定后台指定或适配器内置 HTTPS 地址，避免跟随个人 URL。超模独立分组不静默回落到个人 Key。

图片和视频共用生产入口在每次生成尝试记录 UUID；公共任务 ID 保存钩子补充服务商任务号。状态更新以同一 UUID 的递增版本上报，服务端去重并拒绝旧状态覆盖，查询和下载不增加生成量。旧记录取回单独标记来源未知，不伪装成历史生成统计。已知旧任务若账号或 Key 已变化，明确提示恢复原账号/Key，保留任务 ID 而不重新生成。

客户端 SQLite 暂存不含密钥的记录，按原用户隔离补传；未上报数量在账号按钮提示。切换存储目录用 SQLite 备份迁移，后台线程与迁移互斥。原有运行批次保留凭据；恢复任务的凭据也在启动批次时固定，避免后来登录另一个账号后误用其配置。

到期、停用校验继续由现有在线授权执行；上报用于对账而非计费。已提取的 Key 仍需在服务商处撤销。改写 LLM、字幕与对象存储不纳入本次图片/视频对账。
