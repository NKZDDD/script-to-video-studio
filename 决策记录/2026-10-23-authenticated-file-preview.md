# 文件原图在 Studio 内沿用登录会话预览

日期：2026-10-23
用户确认：“需要改进，因为在缩略图是可以查看的”。

## 定性与范围

工作台图片、原文件、参考原图等链接使用 target=_blank，桌面 pywebview 默认将新窗口请求交给系统浏览器。Studio WebView 的独立 Cookie 存储与 Edge 不共享；因此同一张图片在缩略图正常，在 Edge 的 /file 接口被登录校验拒绝。已有登录测试验证接口鉴权，未覆盖桌面跳外部浏览器这条交互。
范围包括工作台所有同源 /file 链接（产物图片、原文件、参考图弹窗、文本等），不改服务商远程链接、不改已提交任务、不更改服务器认证协议。旧 index.html 已不是服务器提供的入口。

## 方案与授权

用户明确授权修复，无需再确认。使用独立的站内文件预览对话框，保留底层生产树和原有弹窗状态。点击及中键打开同源 /file 时不跳外部浏览器；下载仍使用同源下载链接。
先用单字节 Range GET 确认文件与本地登录状态，随后按类型显示图片、音视频或受 sandbox 限制的纯文本/JSON iframe；其他类型提供下载。无需额外联网认证，不传递登录令牌到 URL，不开放匿名文件访问。
真正返回 login_required 时关闭预览并显示登录页；登录组件检测失效时也关闭预览。关闭对话框会取消尚未完成的请求并停止音视频，避免迟到响应重开预览。

## 改动与效果

新增 web/output-preview.js，通过捕获阶段统一处理动态生成的文件链接，避免遗漏不同入口。agent.html 引入脚本，server/app.py 白名单放行静态脚本，打包自检也验证此 HTTP 资源。样式与登录锁定逻辑配套。
用户从缩略图打开原图时保持原登录会话，不再看到外部浏览器的 login_required。站外链接仍按原方式打开；文件接口依然需要登录。

## 验证与交付

实际 JavaScript 逻辑测试覆盖同源与外链区分、Range 请求、图片/视频/音频/文本、下载、无文件、失效登录、关闭竞争和停止播放。HTTP 测试验证同一 Cookie 下 Range/全文件读取不调用在线验证，无 Cookie 仍401。
全量回归：3535 passed，1 skipped（252.68秒）。Node 文件预览与登录脚本行为测试通过。当前仅修改源码，未打包 EXE 或上传 R2；现有安装版需要升级客户端才能生效。
