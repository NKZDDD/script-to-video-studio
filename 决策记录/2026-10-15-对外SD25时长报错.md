# 对外 SD2.5 返回 invalid_duration

日期：2026-10-15
起因：用户截图显示“视频时长必须在 4～30 秒之间”，状态仍进行中，尝试次数为 2；用户确认 SD2.5，未提供当次界面时长或任务记录。

## 核对结果

对外 `respect_batch` 的公开 SD2.5 路由为小裴 `sd2.5-720均衡版`。`build_video_body` 生成顶层整数 duration，`_seconds_for` 将其限制在 4～29 秒；页面可选范围同样为 4～29，默认 10。并非要求用户自己填写 HTTP 参数；界面选择经程序转换后提交。当前源码不能证明另一台机器当次请求实际内容。

只读使用发行配置拉取 `/v1/models` 返回 200，均衡版仍在列表。`/api/status` 给出的官方文档站为 https://api.aione.help，官网脚本 `assets/video-generator.sd25-catalog-20261010.js?v=1` 标注 SD2.5 4～30 秒，统一创建体使用 seconds 与 extra.reference_*。官方 `/docs/api/video-plugin-api.md` 同时声明 duration/seconds 数字和数字字符串兼容，未提供逐模型实时约束。故只能确认客户端和官网示例的写法不同，不能认定 duration 已失效，也不能凭截图断言服务商更改接口。

未发起付费生成或原任务重新提交。确切原因仍需当次提交参数及服务商记录核对；若实际为范围内整数仍被拒绝，需要服务商检查该模型的字段映射和上游约束。

## 已确定并修正的问题

批量包和 Studio 共用错误分级逻辑都未识别 invalid_duration。轮询 HTTP 200 中的 failed 被转成 status=0 的 ApiError，随后按网络类可重试处理。因此原样重发了确定的参数错误，用户看见“进行中、次数2”。

两处都将明确的 invalid_duration 归为 task_fatal，失败后直接显示失败，不自动原参重发；网络 timeout 保持可重试。未未经验证更改模型字段形状或放宽时长。

批量包 6 项专项通过，含模拟失败后 max_retry=2 仍仅调用一次；全量 94 项通过（29.41 秒）。Studio 5 项时长分类通过。该修正尚未进入新 EXE。
