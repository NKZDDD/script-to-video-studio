# 已提交任务固定 ID，重新生成必须手动放弃

日期：2026-09-29。

用户要求：是否可以改成只用固定任务 ID，不用校验参数是否一致，这样就需要手动放弃任务。

## 定性

页面只要存在 submitted 记录就承诺继续取回，但 produce._pending 会在身份指纹变化时清除记录，_deliver 会在服务商返回终态失败时清除记录；视频账号不可用也会清除。与此同时，自动改写/重发可能在拿到任务 ID 后再次提交。页面承诺与真实执行不一致，普通输入不变且查询成功时无法暴露此缺口。

本次用户已经明确了策略，不需要追加确认。范围覆盖 Studio 图片、视频，Agent 生产入口与旧流程的依赖调度；不修改服务商视频生成协议，不打包 EXE，也不修改昨天的巨轮下载外挂。

## 实施规则

1. 当前输出保存着服务商任务 ID，就优先取回。提示词、参考图、时长、比例、清晰度和模型变化不再自动放弃记录；旧 identity 字段兼容保留，仅供追溯。
2. 取回路径跳过当前生成材料校验和参考图上传。预检及调度不再等待已提交任务的上游图片；已下线模型也可尝试查询旧 ID。
3. 查询超时、下载失败、服务商生成失败、任务查不到，均保留旧记录；错误归为 SUBMITTED_PENDING，不允许自动换服务商重做。
4. 已有 ID 后禁止自动改写或重发；未获得 ID 且明确未提交成功的原有重试逻辑保留。
5. 使用原任务记录中的模型选择服务商 Key；原账号不可用时保留记录并提示恢复。当前生产行切换了服务商时，要求切回原服务商或明确放弃，不把旧 ID 发到另一家。
6. 只有成品检查通过后清除待取回记录，或用户明确点击“放弃这个任务，下次重新提交”。已存在有效成品时按原规则复用。预览为取回、开始时记录已被放弃的批次会停下，要求重新预览，不擅自变为新生成。
7. 取回成功按原服务商和模型记入记录与用量；没有保存的旧时长/画幅不拿当前参数冒充。

## 边界

固定的是当前项目、当前输出位置对应的服务商 ID。更改输出路径会形成另一个输出任务，本次不做跨路径或跨项目的历史 ID 猜测。取回旧 ID 得到的是最初提交时的内容，后改的提示词和参数不会改变已经提交的任务。

从主程序生产路径修复；旧 EXE 装 20260928.3 巨轮外挂只获得下载续传，仍需更新主程序才能获得本次固定 ID 策略。

## 验证

- 初次专项 80 passed，包含参数/参考图变化、原服务商限制、失败后保留和手动放弃后的新生成。
- 补充旧模型 Key 路由及预览后放弃边界：27 passed。
- 最终全量：2840 passed（251.79 秒）。前一轮运行期间继续补充边界代码，3 条 inspect.getsource 检查受到旧行号影响，另有 1 条项目导入目录瞬时 WinError 5；固定代码后完整重跑全部通过，未修改无关导入代码。
- 独立提交复核：将本次改动单独应用到 HEAD 干净副本，27 passed（14.53 秒）；没有夹带工作区已有的其他功能改动。

## 为什么修、避免什么

原来“取回”前还走新生成的参数比较和素材准备，参数变化或终态失败会悄悄抹掉已有 ID。现在取回是一条独立路径，失败保留任务号并给出手动放弃入口。下一次点击生产不会因参数变化或失败而新增付费任务，重新生成由用户明确决定。
