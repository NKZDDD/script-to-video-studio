# 基础版保留服务商密钥、并发和线程状态

日期：2026-09-20。阶段：继续完善架构与原型，不实施正式程序。

## 用户请求

“服务商的密钥填写设置还有并发数量，和当前线程数和建议线程数旧程序中的必要功能呢”

## 为什么上一版漏了

上一版围绕 Agent 交接和资产树组织页面，只用“正式版保留基础服务商设置”的说明文字代替实际表单；并发数字又放进默认隐藏的高级功能包。说明中的保留承诺没有落实成可见、可操作的基础页面，用户自然无法确认旧程序是否还能正常生产。

旧代码确认需要保留的机制：`core/executor.py` 三层并发；`core/resources.py` 实际线程与建议；`web/index.html` 服务商分组密钥及资源仪表；`server/app.py` `/api/resources` 的采样接口。范围覆盖所有项目和五类新生产任务，不仅某一行图片。

## 本轮修正

原型升级 0.3：顶部常驻运行仪表；设置分为服务商与密钥、并发上限、界面功能；生产页五行服务商/模型/并发常驻；功能包不能隐藏上述基础能力。密钥分用途提示配置状态，缺所需 Key 阻止模拟开始；全局/服务商配额跨项目共享；实际线程数与建议生产并发分别表达。

本轮没有修改任何真实配置或正式运行代码。原型不请求真实服务商、不保存真实密钥；建议值和运行指标均标明为演示。详细设计见 `docs/design/codex-production-v7/基础生产功能补充.md`。

## 下次能避免什么

即使切到简洁版，仍能找到密钥、修改并发并看到运行状态；不会因选到 4K 模型却只有 1K Key 而静默降级；多个项目不会把各自的并发数字当成独占额度；没有采样证据时显示未知/待采样，不伪造 0 或精确建议。
