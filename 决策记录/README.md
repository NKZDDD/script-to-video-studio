# 决策记录

一次改动一个文件：`YYYY-MM-DD-<短横线短名>.md`。

每份四段：

```
起因      用户的原话（照抄，不改写）
我查到的  定性结论 —— 机制是什么、在哪几处成立
要你定的  最多四个问题，每个带选项、代价、我的推荐
怎么修的  最后做了什么；为什么会有这个问题；修完能避免什么
```

## 为什么留着

**为了下次遇到同类问题时先搜这里。**

这个项目里有一批参数和判定的取值是「当时讨论过、定下来的」，而它们
既不在代码里（代码只写了结果）也不在 git 里（提交说明写的是怎么改，
不是为什么这么定）。半年后再看，那些取值看着像随手写的。

典型的几条：为什么集数按总时长算而不是数剧本里有几章；为什么剧情文字
一律允许而只留一个字幕开关；为什么装箱漏镜头要停、而时长压缩只记不停。
每一条都有理由，而理由只在对话里 —— 对话会丢。

## 什么时候写

流程见 `.claude/skills/studio-fix-flow/SKILL.md`。

**不是每次改动都写。** 只在「不同理解会做出不同的东西」时才写 ——
改错别字、补一条日志、修一个只有一种合理修法的 bug，直接做完汇报。
每次都写的结果是这个目录变成噪音，然后没人再看它。
