# 字幕样式的八个旋钮

## 起因

用户原话：

> 并且字幕是有字幕的字体，字号，垂直间距（控制字幕在画面的Y轴位置），
> 字幕颜色，字幕描边颜色，字幕描边粗细，字幕的字符间距，字幕的行间距
> 这些选项的，样式里面包含这些

## 我查到的

对着 `videocaptioner/core/subtitle/style_manager.py` 的
`SubtitleStyle.to_ass_string()` 逐个核过。用户列的八项里 **七项有、一项没有**：

| 用户说的 | ASS 字段 | 有没有 |
| --- | --- | --- |
| 字体 | `font_name` | ✓ |
| 字号 | `font_size` | ✓ |
| 垂直间距（Y 位置） | `margin_bottom` | ✓ |
| 字幕颜色 | `primary_color` | ✓ |
| 描边颜色 | `outline_color` | ✓ |
| 描边粗细 | `outline_width` | ✓ |
| 字符间距 | `spacing` | ✓ |
| **行间距** | `line_spacing` | ✗ |

**行间距在 ASS 模式里不存在。** `SubtitleStyle` 里确实有 `line_spacing`
这个字段，但它只出现在 `to_rounded_dict()` —— 也就是「圆角背景块」
那种渲染模式。`to_ass_string()` 一次都没碰它。而这四份样式都是 ASS 模式
（`[V4+ Styles]`）。ASS v4+ 的 Style 行里根本没有行距这一栏，
行距由字体自身的行高决定。

所以行间距**不能放进表单**：放了人填了没反应，而且不报错 ——
正是这一批改动一直在消灭的那类失效。

另一件查出来的事：**字体名写错会静默回落成默认字体**。
VideoCaptioner 自己只带一个 `NotoSansSC-Regular.ttf`，
而这四份样式用的「华文楷体」是 Windows 系统字体 —— 烧录时由 libass
去系统字体集里找，找不到就换一个，片子照出、字幕照有、字体不对、不报错。
这台机器上注册表里有 371 条字体、归并成 249 个族名。

## 要你定的

没有需要定的 —— 用户已经把要哪些说清了，唯一的分歧（行间距）
是「它不存在」而不是「要不要做」。

## 怎么修的

### 1. 「字幕微调」表单：七个旋钮

设置页字幕卡里加一块，盖掉所选样式的对应值，**样式文件本身不动** ——
想换一部剧的观感时不用另存一份样式。

不填 = 按样式走。每个框的 placeholder 是**所选样式的当前值**（灰字），
换样式时跟着换 —— 不换的话灰字还是上一份的数，人照着它判断
「要不要改」就判错了。

走 `--style-override`，不改样式文件、不改 config.toml 的 `[synthesize]`。

### 2. 表单结构由后端给

`STYLE_FIELDS` 在 `core/subtitle.py`，`/api/subtitle/styles` 一并返回，
前端只管渲染。前后端各写一份的话，加一个旋钮要改两处，
**对不上的表现是「页面上有、存不下」**。

### 3. 微调过的字段也要做竖屏补偿

**这是最容易漏的一处。** 微调和补偿分开做的结果是「改过的字段不补偿」：
把字号改成 50，出来是 89（50×1.78），而没改的字段都是对的 ——
一部分对一部分不对，最难查。

所以 `style_override()` 一次做两件事：先算最终值（微调优先，
没微调就用样式自己的），再整体除掉缩放系数。
颜色和字体名不参与缩放，原样发过去。

副样式（双语字幕第二行）的字号**按样式里主副的比例跟着主字号走** ——
不然改完主字号，译文那行还是老样式的大小，两行比例失调。

### 4. 加粗做成三态下拉，不是勾选框

勾选框做不了三态：「没动过」和「明确要求不加粗」长得一样，
于是没动过也会被当成覆盖发出去，**把样式里的加粗关掉**。
所以是「按样式（加粗）/ 加粗 / 不加粗」三个选项。

### 5. 字体给真实候选 + 开跑前核一次

`core/captions.system_fonts()` 从注册表读（HKLM + HKCU），
去掉 `(TrueType)` 后缀、按 `&` 拆多族名条目、归并字重后缀。
中文字体排在前面 —— 短剧用的就是那几个。

读注册表而不是扫 `C:\Windows\Fonts`：注册表里的显示名就是
**你在 Windows 字体列表里看到的那个名字**（「华文楷体」而不是
STKAITI.TTF），和人要填的东西一致；而且扫目录要逐个解析 name 表，
371 个文件要几秒。

填了机器上没有的字体，页面上当场标黄，开跑前 `config_problems`
再拦一次，并给出最接近的几个候选。

**列不出字体时不拦** —— 把「我们读不到注册表」报成
「你的字体不存在」是另一种错。

### 6. 值的边界

- 空串 = 没填 = 用样式的值。**不能当成 0** —— 那会把「没动过」
  变成「把字号设成 0」
- 按类型转（页面送来的都是字符串）：不转的话 toml 里写成 `"50"`，
  VideoCaptioner 读到类型不对
- 超范围夹住：字号填 99999 不会报错，只会烧出一个全屏都是字的片子
- 清空是**整块替换**而不是合并：合并的话删掉的项会一直留在 config 里，
  页面显示没填、实际还在生效

## 实拍验收

一次改七项（华文行楷 / 金黄 #ffd400 / 深褐描边 / 描边 4.0 /
字距 3.0 / 底边距 420 / 字号 46），抽帧确认**七项全部生效**，
底边距实测约 430px（要求 420，取整误差 1px 级）。

## 为什么会有这个问题

上一轮只做到「能选一份预设样式」。而预设是别人（或过去的自己）
定好的一套数，**想微调就只能去改样式文件** —— 而样式文件在
`%LOCALAPPDATA%\VideoCaptioner\...\resource\subtitle_style` 下，
路径又深又和项目无关，改完还要记得别被 `captions.install()` 盖回去。

## 修完能避免什么

- 换观感不用碰样式文件，也不用为每种观感另存一份样式
- 字体名写错当场就知道，不用等烧完一整片才发现字体不对
- 微调值和样式值走同一条补偿，不会出现「改过的字段偏大、没改的正常」
- 「行间距」这一项明确记下**它在 ASS 模式里不存在**，
  下次再问不用重新翻一遍源码
