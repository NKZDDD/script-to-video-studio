# 将联网授权检查移出普通页面操作

日期：2026-10-22
起因：用户要求“这个解开，然后应用中不要过多的进行校验，只需要做一个登录的校验，然后生产的校验”。

## 问题机制与范围

`core/studio_login.py` 在持有登录状态锁时执行校验、续期、适配包下载及用量上传；所有页面 API 和文件预览也要取得这把锁。`web/login.js` 每分钟强制在线校验，普通请求超过 60 秒也触发校验。每个认证子请求还同步检查一次版本。`server/app.py` 用安装生命周期锁包住所有 POST，导致模型/配置刷新也可能阻塞补全依赖和计划预览。

这是全工作台的入口机制，覆盖两套生产体系和所有任务类别，非某个供应商或共享盘特有。此前检查集中于未登录不可生产、停用立即拦截，缺少“服务器请求未返回时本地操作仍能完成”的并发回归。

## 已确认范围

按用户明确要求执行，不增加配置开关、不更改服务商生成请求、不打包。登录、开始批次、重新抽卡、合成前及手动刷新后台配置仍在线校验。普通查看/编辑、补全依赖、计划预览、页面轮询只检查本机会话和已知账号到期时间。后台配置变化在下一次在线校验生效，不保证空闲客户端即时获知远程停用。

## 实现

- 状态锁只保护短时状态读取/更新；独立网络操作锁串行化登录/校验/续期，网络请求不阻塞普通页面读取。会话代次防止退出后的迟到响应恢复旧登录。
- 用量上报不持有状态锁，不触发账号/版本检查；过期或上传失败时保留待同步记录。后台 R2 签名仍需线上授权，仅在令牌失效时续期。
- 普通页面每分钟只请求本地 status；生产及手动刷新配置保留强制 verify。已知到期时间本地拦截，服务器明确停用后清理会话。
- 版本确认成功缓存 60 秒，减少 login/verify/refresh/adapters 连续检查；手动检查不使用缓存。服务端的登录/校验接口继续执行版本策略。
- 临时网络错误阻止当前生产请求，但有效本机会话不会被前端错误地强制锁回登录页；版本服务不可达时不覆盖已登录工作台，服务器明确要求更新时仍拦截。
- 安装生命周期锁只覆盖新建批次与安装的互斥，普通 POST 不在远程刷新期间排队。

## 验证与结果

最终全量回归：`py -m pytest -o addopts= -q`，3497 passed、1 skipped，240.58 秒。另运行 `node tests/test_login_screen.js` 和 `node tests/test_update_screen.js`，均通过。覆盖真实 HTTP 路由在校验挂起、模型刷新挂起和生产启动锁占用时仍能完成本地请求；用量上传不阻塞、退出后的迟到响应不恢复登录、账号停用和已知到期拦截、强制更新仍生效。本次未打包 EXE、未部署服务端、未发起付费生成。

## 修完避免什么

当认证或用量请求迟迟不返回时，补全依赖和生产计划等本地请求不再因这把登录锁排队；模型刷新也不再占用所有 POST 共用的安装锁。生产前仍必须通过在线校验，断网不自动提交、不重新创建已有供应商任务。此项修改不保证消除共享盘 I/O、首次模型清单读取等其他来源的延迟。
