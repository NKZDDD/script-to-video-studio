# 客户端只展示后台分配的服务商名称与模型

日期：2026-10-22

起因：“实际的地址需要隐藏而且不是本机的个人备用配置才对，这个是新机安装的，不要从这边配置可以看见虽然服务端现在会下发但是不能看到这个，后续会再做成走服务端也就是走我们中转站任何服务商当上游”。

## 问题机制与范围

新机没有保存地址时，`web/agent.js` 的服务商表单仍读取 `cap.default_base_url` 并填入 Base URL；该默认值来自服务端下发的适配代码。先前只更换显示名称并声明后台 Key 优先，仍保留个人表单与默认地址，所以新机也会暴露上游网址。此前测试关注模型路由、密钥不回显和名称更新，没有检查默认地址与凭据表单是否仍传到页面。

范围是客户端的服务商页、启动元数据、模型刷新/适配器状态返回、配置保存入口及诊断信息显示。两套生产体系共用这层，内部执行仍需要完整适配能力和路由。LLM 独立配置、R2 存储、素材链接、提示词和升级下载地址不在服务商连接表单的删除范围。

## 实施

- 托管安装版只显示后台名称、授权状态和图片/视频模型列表，保留刷新后台配置与刷新模型按钮。
- 页面数据剔除默认地址、连接设置、凭据表单和适配器来源细节；不改内部能力声明、模型参数与 Key 路由。
- 托管客户端拒绝本地服务商设置写入；没有后台授权时不再使用遗留个人 Key。旧配置文件不删除。
- JSON 页面响应中的错误、诊断和日志隐藏链接与已知上游域名，保留错误码和文字原因；不修改磁盘诊断原件、提示词和媒体/安装包下载链接。

## 修复后能避免什么

新安装的客户端不会因为适配器默认值而在设置页出现真实地址，也不会再提示填写个人备用 Key。手工调用原保存接口同样无法写入备用服务商连接配置。后台调整名称、分配 Key 和模型后，刷新仍按新配置显示和调用，不会把不同模型路由到错误 Key。

本次实现界面与页面接口隐藏。适配代码和请求仍在客户端执行，地址与凭据仍需交给本机运行时；后续中转站建设才会把上游连接留在服务端，本次不声称已经完成网络隔离。

## 验证

覆盖新机与遗留配置、页面不返回默认地址和表单、配置写入拦截、未授权 Key 不回退、模型路由保持、诊断显示脱敏，以及真实前端函数的名称转义与刷新。

全量测试 3488 passed（226.31 秒，包含实际 Windows 安装器测试）；最终显示边界调整的 7 项针对性测试另行通过。Edge 浏览器验证只读页面、无连接输入框、模型展示、后台名称刷新和模型刷新均通过。客户端版本 2026.10.22.4，服务端与已发布适配包无需升级。
