# HZYF OpenAI 兼容图片接入及外挂

日期：2026-10-02

## 用户要求

接入 https://hzyfai.com/v1，测试是否通用 OpenAI 接口；成功后打入 Studio 并提供外挂。用户提供密钥供测试，不记录于本文件。

## 定性和实测

Studio 原来没有该服务商的能力声明及注册项，仅有基址和模型名不能保证参考图字段正确。该站模型列表提供 4 个 image-generation 模型，接口为 New API 网关；仅凭列表不能推断视频、聊天或所有 OpenAI 端点可用。

首次 Key 的文生图、编辑请求均返回 403 insufficient_user_quota，余额 0，未实施接入。用户换 Key 后列表正常；最初请求遇到服务商 CPU 94.3% 超过阈值 90% 的 503 system_cpu_overloaded。等待后单条重试成功：

- gpt-image-2 文生图：POST /v1/images/generations，JSON model/prompt/n/size/response_format，27.2 秒返回 200；下载到 1024x1024 PNG。
- gpt-image-2 双参考图编辑：POST /v1/images/edits，multipart image[]，24.8 秒返回 200；下载到 1536x1024 PNG，目视确认红三角、蓝圆均出现。
- 响应包含 data[].url、request_id、stage、status 等；request_id 不当成异步任务 ID。

## 实现范围

新增 core/providers/hzyfai.py，注册进 _BUILTIN_ORDER，确保冻结 EXE 中也可发现；外挂与内置文件字节一致，绝对导入可独立加载。
仅图片能力，共用服务商入口覆盖两套体系及资产图、场景状态、交接板等图片任务。不改提示词流程或其他服务商。
接收带 /v1 的基址并规范化，避免 /v1/v1；尺寸明确使用像素。参考图完整检查后通过 image[] 按序发送，不裁掉第十张及之后素材，不依赖 R2。
使用公共结果保存器验证落盘文件，HTTP 提交层只发一次；响应无图片时报错，不用追踪号虚构可续查任务。
用户 Key 不写入代码、外挂、测试或发布包。

## 避免的问题

新服务商能在旧 EXE 外挂及后续主程序中显示。图片编辑不会误用 JSON 参考图字段而丢图；无效图在付费提交前报出序号；尺寸不明确时要求选择已验证值。区分余额不足、服务商过载与接口兼容，避免把临时 503 判断为接口不支持。

## 验证与交付

针对性测试 31 项通过。后续其他模型验证、全量回归与旧 EXE 自检曾因本机 C 盘空间为 0 中断；已清理本项目可再生成的 build 缓存，并将测试临时目录移到 D 盘后重新验证。

- 全量回归：3009 passed in 199.97s。
- 旧版 2026-09-30 EXE 在隔离目录加载 HZYF 外挂，4 模型、3 尺寸和二进制参考图声明全部正确。
- 通过新增服务商代码真实生成并保存：gpt-image-2.5 1024x1536（41.6 秒）；flare 1024x1024（43.6 秒）；sunburst 1024x1024（43.0 秒）。flare 遇到一次 CPU 92.2% 的明确 503 拒绝，间隔重试成功。
- 配合前述 gpt-image-2 文生图和双图编辑，4 模型都有真实成功结果；并非全部模型与尺寸、素材组合均经过实测。
- 外挂发布包：dist/Respect-Studio-HZYF-Image-20261002.zip，含插件、安装说明和 SHA-256 manifest；压缩完整性及插件与源码一致性检查通过。
本次提供服务商外挂并合入主程序源码，不重新生成完整 EXE。
