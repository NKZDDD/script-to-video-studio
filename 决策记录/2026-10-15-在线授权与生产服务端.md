# 在线登录校验服务端（宝塔 Linux）

日期：2026-10-15
起因：用户要求“我有服务器和域名，你可以直接完成服务端的带给我进行部署”。

## 已查明的机制与范围

当前 `core/providers/base.py` 定义图片、视频生成及续查接口；各服务商通过 `core/apiutil.py` 在本机发起请求。只增加本地登录判断不能建立不可绕过的线上生产授权边界。本次先交付可部署的服务端，不宣称现有 EXE 已经切换到线上授权。

`core/submitted.py` 保存服务商任务 ID，并支持按旧 ID 取回。服务端同样需要持久化任务归属、幂等提交以及不确定提交状态，不能在请求超时后自动重建任务。

2. 服务器操作系统与已有部署方式，用于提供实际可用的部署包和步骤。

已通过会话问题收集上述信息；未发起服务商付费生成，未读取或打包本地真实 Key。

## 用户回答

用户明确：线上服务端只需要做登录校验，服务商 Key 均由客户端填写和调用。服务器为宝塔 Linux。

因此本次范围收敛为独立 `auth_service/`：账号密码、有效期、停用、会话校验/续期/退出、可选设备数量管理、终端管理工具和宝塔部署包。不代理生成、不接收服务商 Key、不迁移旧任务、不修改当前 Studio 生产入口。

已明确告知：此方案管理正常客户端授权，不能阻止修改本地代码绕过校验。当前 EXE 尚未接入新登录接口，部署服务端不等于旧 EXE 自动启用登录。

## 实施与机制

新增独立 `auth_service/`，未修改 Studio 的生成、Key 或项目处理逻辑。采用 FastAPI + Uvicorn + SQLite；密码 Argon2id，随机访问/续期凭证仅存哈希。每次 verify/refresh 均查询服务端账号启停、到期时间与会话状态，解决客户端仅依靠本地“曾经登录成功”标记无法反映后台停用的问题。

访问凭证 15 分钟，登录会话最长 30 天；续期轮换并检测重复使用，重置密码和管理员停用会撤销旧会话。可选设备数默认不限制。管理命令只在服务器终端执行，不提供默认公网管理员账户。Key、素材与生成请求始终留在客户端，服务端不代理生产。

附带宝塔 Nginx HTTPS 反向代理片段、systemd 服务及清理定时器、安装脚本、备份/恢复说明、接口文档和 Python SDK。客户端续期串行，超时不重复使用旧 refresh_token；网络失败不当成授权成功。已有 EXE 接入是后续工作，文档明确本包不会自动启用旧 EXE 登录。
