# 提示词改写 LLM 读取账号下发配置

日期：2026-10-26
起因：用户要求“LLM的改写也是需要走服务端的一样是走配置吃”。

## 定性与范围

`server/app.py:build_llm` 只读本地 `llm` 并回退本地服务商 Key，`_provider_api_key` 对 LLM 明确跳过 `cloud_config.provider`。媒体 Key 下发成功并不能配置改写，页面却没有区分配置来源；后台换 Key 后旧本地凭据仍会被使用。

影响所有共用 `build_llm` 的入口：Agent 图片/视频审核改写、重抽与重试、两套旧体系的 LLM 工厂和单环节入口、bootstrap 配置状态，以及后台导入与账号分配。未修改电影级模板、材料规则、提示词策略或生产调度。

## 实现选择

沿用现有 Key 库/账号分配/配置下发，以专用 `prompt_rewrite_llm` 条目绑定 HTTPS 地址、一个模型和 Key，不新增推理代理。管理员可命名、共享、勾选、排序和停用；多条时使用第一条启用项，不因失败换 Key。

客户端共享工厂在内存解析此配置，地址与凭据整体替换；本地覆盖值不能把云端 Key 指向其他地址。托管版无分配时明确不可用，个人配置模式保留原有本地回退。页面显示实际来源和配置状态，后台管理时只允许本地保存改写轮数。导入 config 同步支持明确的顶层 llm 配置，不猜缺失字段。

无需新增用户决策：本次按已有“服务端下发配置、客户端直接调用”的方式实现。

## 修完能避免什么

后台换 Key、换模型或调整排序后，登录/刷新会更新后续实例使用的配置，页面能核对实际生效来源。不会再出现媒体已经更新而改写默默拿旧本地 Key 的情况。停用/撤销授权不会在托管版回退旧 Key，密钥不回显或写回 config。构建 LLM 不联网，不会为改写配置增加页面等待。
