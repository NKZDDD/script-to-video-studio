## 我查到的

### 一、鹤：两处声明打架，没配对象存储时旧模型全线失败

`fd6198f` 删掉 `_legacy_video_body`、所有视频模型走同一个 `_video_body`，
这个判断本身是**对的**（见下面「文档怎么说」）。但校验也跟着对所有模型生效了：

```python
local_refs = [r for r in refs if not str(r).startswith(("http://", "https://"))]
if local_refs:
    problems.append("参考图必须先转成公网 http/https URL（请配置对象存储）")
```

而 `needs_url()`（core/providers/paisio.py:105）**只对 2.5 家族返回 True**。实测：

| 模型 | `needs_url` | `_video_body` |
|---|---|---|
| `sd2-720p` | False | 拒绝 data URI |
| `sd3-720p` | False | 拒绝 |
| `seedance2.0-standard-720p` | False | 拒绝 |
| `paisio-seedance-2.0-720p` | False | 拒绝 |
| `seedance2.5-26-720p` | True | 拒绝（一致） |

顺着 `core/produce.py:205` 的 `use_url = need_url or (configured and can_url)`：

- **配了对象存储** → 参考图本来就是 URL，看不出问题
- **没配对象存储** → 解析器按 `need_url=False` 交 data URI → 请求体当场
  `task_fatal`。**旧模型带参考图的活全线失败。**

而报错说的是「请配置对象存储」—— 话是对的，位置不对。这句该由
`core/uploader.py:149` 说，它才写得清去哪个设置页填哪几项。

**测试为什么没抓到**：唯一那条 data URI 用例
（`tests/test_paisio_seedance25.py:51`）用的是 2.5 模型，拒绝是对的。
**旧模型 + data URI 这个组合没人测**，而 `test_provider_marks_only_seedance25_as_url_only`
恰恰把打架的那一半写死成了断言。

### 三、范围：同一个毛病 ComfyUI 插件端也有，而且还没修

`respect_comfyui/he_nodes.py` 的 `RespectHeVideo` 默认 `compat_metadata=True`，

### 四、无限画布：认不出的字符串被当成 asset_id

`core/providers/wuxianhuabu.py` 的 `_asset()` 兜底分支原样返回不认识的值
（注释写「已有 asset_id 是普通字符串」）。一个写错的相对路径就变成一个
假 asset_id 发出去，服务商认不出就当没有这张参考图 —— 片子照出、照计费。

## 改了什么

**studio**

1. `needs_url()`：`media == "video"` 一律 True；图片那条不动（出图用 `image`
   字段，原来就能吃 data URI）。改完没配存储时的报错落在 uploader，
   那里写得清去哪儿填。
2. 报错前缀从写死的「Seedance 2.5 参数不符合鹤的接口要求」改成
   `f"鹤 {model} 的视频参数不符合接口要求"` —— 这个函数现在管所有模型，
   旧模型看到那句会以为自己选错了模型。
3. 把 `test_provider_marks_only_seedance25_as_url_only` 换成
   `test_video_needs_url_for_every_model_not_just_25`：逐个模型验
   「请求体拒绝 data URI ⇒ `needs_url` 必须说 True」，两处不许再打架。
   另加一条锁住图片仍然收 data URI，别被带跑偏。
4. `wuxianhuabu._asset()`：形状像 asset_id（`[A-Za-z0-9_-]{8,128}`）才放行，
   其余当场 `task_fatal`。

**ComfyUI 插件**

5. `compat_metadata` 默认改 False（widget 和函数签名两处一起改 —— 只改一处
   的话，没带这个 widget 的老工作流仍然按 True 走）。
6. **接了 IMAGE 口却发不出去时，从 `print` 改成 `raise`**，并写清两条路：
   正路是过『对象存储上传』把 url 填进 `image_url`；逃生口是打开
   `compat_metadata`，同时说明文档里没有那两个字段。

## 为什么会有这个问题

`_check()`（core/providers/\_\_init\_\_.py:62）已经在查参考图声明了，但它查的是
**声明之间**自洽（`needs_url` 和 `needs_bytes` 不能同时为真之类），
查不到**声明和请求体校验**打架 —— 那是两个文件里的两句话，谁也不认识谁。

而这一对打架**只在没配对象存储时才现形**：配了存储的机器上，参考图早在
`produce.py` 那层就变成 URL 了，两句话说的是同一件事。所以它能通过全部
2263 个用例、通过服务商自检、在开发机上跑得好好的。

## 修完能避免什么

以前：没配对象存储的机器上，旧模型（sd2/sd3/seedance2.0 全系）**带参考图的
视频一条都出不来**，报错说「请配置对象存储」，而页面上这一家看起来是支持
本机图的（`ref_mode="data_uri"`、`needs_url` 说 False）。人会以为是配置写错了，
去翻设置页，而设置页里那一项本来就是可选的。

现在：这类任务在 `uploader.to_url` 那里停，报错直接说「去『设置 → 参考图上传』
填 R2/OSS/COS 的 endpoint、bucket、密钥和公开访问域名，或者把这类任务换成能
直接收本地图的服务商」—— 停在该停的地方，说的是能照着做的话。

插件端以前：接了 IMAGE 口、关了 compat，参考图被悄悄丢掉，片子照出、照计费，
而正文里写的「@Image1 是谁」在请求里根本没有对应的图 —— 出来的脸不是本人，
一处都不报错，只能靠肉眼在几百段里发现。现在这一条直接不出，并告诉你
把图接『对象存储上传』、url 填进 `image_url`。
