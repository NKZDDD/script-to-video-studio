# 纵横科技视频服务商接入

日期：2026-10-26

用户要求：接入 https://cnd-coo-new.pages.dev/api-docs 所述服务商，并使用提供的 Key 核对接口。密钥不写入本记录、源码或适配包。

## 机制与范围

Studio 原先没有纵横科技适配器。该平台虽然使用 `/v1` 前缀，但视频要求 `duration`、`ratio`、`resolution`、`images`、`reference_videos`、`reference_audios`，查询使用 `/v1/tasks/{task_id}`；不能只把其他服务商的域名替换过来。

本次 Key 的模型清单返回 26 个视频模型、1 个对话模型，没有图片模型。对话继续使用已有的“提示词改写 LLM（OpenAI 兼容接口）”配置入口，不把它放进视频下拉框。

使用公共 Provider 层，覆盖两套生产体系的分段视频、一键生产和单独任务、后台按账号下发与个人服务商配置。图片生产不新增未授权且未经验证的模型。现有任务的续查继续使用原任务号，不迁移任务、不更换 Key。

## 已查明的接口细节

- `/v1/models?include_capabilities=1` 提供按 Key 授权的真实能力；公开 ID 有拼写差异、大小写和斜杠，保持原样。
- 目录中 `Aseedance2.0` 最高 14 秒，`wan3/1080` 缺少 28 秒等。不能从介绍文案或最小/最大值自行补齐时长。
- 当前 26 个型号的 `aspect_ratio_options` 全为空。按文档不发送没有开放选项的可选字段，客户端显示“自动比例”。用户选择固定比例时明确拦截并指引调整，避免静默丢弃用户要求。
- 参考图、音频、视频分别按模型上限校验；保留 30 图、10 音频、10 视频的完整输入，不套用统一 9 图限制。
- 本地图片使用 `/v1/media` 的 `file` multipart 上传，上传不是生成请求。公网 HTTPS 素材可以直接使用。
- 新生成携带唯一幂等号，同一次 HTTP 重试保持原号和原参数。未收到明确任务号时停止自动重新生成；拿到任务号立即记录，查询、下载、停止后仅续查。
- 按 `next_poll_seconds` 轮询；失败保留 `error_code`、`error_detail`，只在成功状态读取成品字段，不误收回显的参考视频。
- 兼容现有客户端的 `filter_catalog` 扩展点及服务端适配包协议，无需修改客户端网络请求总入口，也不增加浏览本地页面时的远程校验。

## 网络验证边界

本机访问文档页面正常；模型端点曾多次读取超时，随后原始 `/v1/models?include_capabilities=1` 和兼容 `/openai/v1/models?include_capabilities=1` 均成功返回 27 个模型。系统代理与直连对照也均成功。不能据此把故障直接归因于本地网络或服务商服务器，亦不能把模型列表成功当作视频生成成功。

采用文档原始基础地址 `https://cnd-coo-new.pages.dev`；不因一次兼容目录成功而把视频路由改到未验证的另一条路径。最终实测结果、回归数字见交付目录的 `验证记录.json`。

## 交付与避免的问题

导出包含原有 24 家及新增纵横科技的完整适配包，避免后台发布新包后遗漏其他账号已分配的服务商。后台导入并发布后，在 Key 库选择“纵横科技”创建并分配 Key，客户端刷新后台配置及模型。服务端已有动态名称和适配包机制，本次不必升级服务端程序。

下一次选择这家时，模型和参数能通过公共生产入口正确映射。无权限模型、错误秒数、超量参考或未声明的固定比例会在付费提交前明确报错；已提交视频发生查询或下载故障时保留原 ID，避免重复扣费。适配包可加载与真实生成可用分别验证，不相互替代。
