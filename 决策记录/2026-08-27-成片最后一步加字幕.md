# 成片最后一步加字幕

## 起因

用户原话：

> https://github.com/WEIFENG2333/VideoCaptioner，查看这个github的项目并查看我的studio
>
> 给studio补字幕，就在最后拼接好视频产出的最后一步加字幕就可以

## 我查到的

**VideoCaptioner 对这件事只有一半有用，而且是不值钱的那一半。**

它的管线是 `视频 → ASR 识别 → LLM 智能断句 → 翻译 → 压制`。前四步是为
「手上只有一个视频文件、不知道里面说了什么」准备的。而 studio 不是这个处境：

**台词和时间戳本来就在库里，是 LLM 早就写好的。**

| 体系 | 数据在哪 | 字段 |
| --- | --- | --- |
| 电影级十七章 | `n9_shots` → `timing_plan[]` | `dialogue`、`dialogue_start`、`dialogue_end`（镜内相对秒） |
| 通用十二环节 | `s2_segments` → `segments[].dialogues[]` | `{t: "0-4s", speaker, line, note}` |

`core/explorer.py:248` 和 `:333` 已经在读这两处的 `dialogues`。

所以：**不需要 ASR，不需要断句，不需要翻译**（对白语言在
`core/settings.py:90` `dialogue_language` 里已经是设定项）。VideoCaptioner
剩下能借的只有最后压制那一步，而那是一条 ffmpeg 命令。它是 GPL-3.0，
拷代码会传染许可证 —— 既然只用得上一条命令，就不用碰它的代码。

**真正的难点不是压字幕，是时间轴对账。**

`core/stages.py` 的 `assemble()` 现在做的是：按段号排序 → 写 concat 清单 →
`-c copy` 流拷贝拼接。字幕要落到成片上，得知道每一段在成片里从第几秒开始，
也就是前面所有段的**实际时长**累加。

而分镜里写的 `start/end`、`0-4s` 是 **LLM 规划的意图，不是成片的事实**。
出片模型多数只出固定时长（5s/10s），实际时长和规划秒数对不上是常态。
按规划秒数累加的话，字幕会**逐段累积漂移**，越到后面错得越多 ——
而且和「缺一段照样拼」是同一类毛病：不报错，只是不对。

`core/probe.py` 已经有 `find_ffprobe()` 和读流信息的能力，读每段实际时长
不需要新装东西。


**上面这一段有一半是我判断错的，留着不删，因为错的过程本身有用。**

我据此推断「成片多半没有人声轨，ASR 走不通」。用户反问「不是都用视频里
的音轨来识别吗」，去实测才发现**成片有音轨**，AAC 立体声 128kb/s，
代码里也对得上：`kunji.py:326` `generate_audio` 默认 True、
`paisio.py:239` `enableSound` 默认 on、`julun.py:53`「默认开配音」。

教训：**「模型多半不出音轨」这种话，代码里查得到的事不要靠印象。**
三个 provider 的默认值就在仓库里，grep 一次的事。

（另外那一轮探查里，我拿 `projects/XYQY-Lari-40` 的产物做过一次诊断，
说成片时间轴是坏的。用户说那不是他的生成文件，是这台机器上的旧残留，
所以那个结论**不具代表性，没有据此改任何东西**。）

## 怎么修的

### 做了什么

新增 `core/subtitle.py`：一个只有 subprocess 的适配层。它自己不做字幕，
只做三件事 —— 把设置页填的东西翻译成 VideoCaptioner 的 `config.toml`、
按顺序调它的两个子命令、把它的退出码翻译成人话。

两套体系各加一个环节，都排在拼接之后：

| 体系 | 环节 | 位置 |
| --- | --- | --- |
| 电影级十七章 | `d3` 字幕（第 17 环节） | `d2` 排序拼接与交付**之后** |
| 通用十二环节 | `s13` 环节13 字幕 | 环节12 拼接成片**之后** |

设置页加一张「字幕」卡：启用开关、识别引擎、软/硬字幕、LLM 优化、
翻译、以及**独立的一组 LLM Base URL / Key / 模型**，外加「运行自检（不花钱）」。

### 几个决定，和为什么

**1. 为什么是外部命令行调用，不是把代码搬进来**

VideoCaptioner 是 **GPL-3.0**。当独立命令行工具调用不受影响，
拷代码进本仓库会传染整个项目的许可证。所以 `core/subtitle.py` 里
一行它的代码都没有，只有 subprocess。

**2. 为什么每次跑都自己生成一份 config.toml**

它默认读 `~/.config/videocaptioner/config.toml`。依赖那份有两个坏处：
用户在 studio 设置页填的 key **不生效**（它读的是另一个文件），
而页面上照旧显示着填好的值 —— 又一个「填了白填」，
和 2026-08-21 那次「全局提示词改写架空了三组设置」是同一类；
反过来 studio 去写用户的全局配置，又会覆盖他手动
`videocaptioner config set` 配的东西。

它有 `--config FILE` 全局参数，所以每次跑生成一份传进去：
**studio 设置页是唯一权威，两边互不干扰。**
临时文件放 `07_检查与记录/videocaptioner.toml`，不放系统临时目录 ——
出问题时它和产物在一起，支持包一打就带上了。

**3. 为什么分两步（transcribe → synthesize）而不是一把 `process`**

`process` 一条命令能直接出压好字幕的成片，但中间的 srt 留不下来。分开有两个好处：

- srt 是**可看可改**的产物。识别错了人名，改那一行再跑压制就行，
  不用重新识别一遍（识别一集要几分钟）。
- 和本程序的续跑逻辑一致：**以磁盘产物为准**。srt 在就跳过识别，
  成片里已有字幕轨就跳过压制。

**4. 为什么 `kind` 是 `local` 而不是 `llm`**

它内部会调 LLM 优化字幕，但那是**它的调用、它的 key、它的账**，
本程序的分析引擎完全不参与。标成 `llm` 的话，
「先看会做什么」里的「至少几次分析调用」会把它算进去 ——
那个数是给人估自己网关花费用的，掺进别人的调用次数就成了假的。

**5. 为什么没开就不进计划，而不是进了计划再跳过**

进了再跳过的话，「先看会做什么」会列出一步「字幕」，人以为要做字幕，
跑完发现没有，而**全程没有一处说过它是关着的**。

**6. 为什么字幕失败不阻断交付**

成片在拼接那一步就已经交付了。字幕没做成是**少几行字**，不是成片坏了。
和「缺一段不许拼」不是一回事 —— 那个是成片短一截，必须停。
所以这一步失败记 `warn`，不 append 到 `failed`，不 return `"failed"`。

顺带补了前端：`PILL` 映射里原来没有 `warn`，会落到默认的 `pend`，
于是「做完了但有几集没配上」在页面上长得和「还没开始」一模一样，
人会一直等一个已经结束的步骤。

**7. 没装 VideoCaptioner 在哪儿说**

在「先看会做什么（不花钱）」里就说，不是等跑到最后一步才说：

```
待办: 字幕（⚠ 还没装 VideoCaptioner，先 pip install videocaptioner）
```

那个按钮的用处正是让人在开跑之前把该装的装好、该填的填好。
同理，「勾了 LLM 优化但没填 key」也在开跑前查（`config_problems`），
不然识别跑几分钟才报，那几分钟白等。

**不自动 pip install。** 装包是有副作用的动作，偷偷装了用户不知道
装了什么、装到哪个环境、占了多少盘。没装就明说，把命令给他。

### 为什么会有这个问题

程序原来到「拼接成片」就结束了。设置里那个 `subtitle`
（`core/settings.py:121`）叫「画面里要不要字幕」，管的是**出图出片时
画面里本身带不带字幕**（走提示词，烧在生成的画面里）——
它是生成侧的开关，不是后期通道。所以整条链路上**没有任何一处**
能给做好的成片配一条字幕轨。

### 修完能避免什么

- 成片交付前多一条字幕，不用导出去用别的工具再过一遍。
- 字幕的 LLM 和整剧解析的 LLM **分开计费、分开选型**：
  整剧解析要长上下文的贵模型，字幕纠错是短句批处理，
  用便宜的小模型就够，不用为它烧同一个额度。
- 没装 / 没填 key 这两种最常见的卡点，在**开跑之前**就说，
  不是跑到最后一步才报。
