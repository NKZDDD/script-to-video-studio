# 按 Key 展示模型成功率卡片

## 问题与用户确认

用户要求：“不应该是我那把 key 能拉取到的模型名的成功率直接展示吗，要有绿灯的元素和我刚刚的图类似。”沿用此前两端展示、使用服务商自己的统计的要求；Key 决定模型范围，统计不是该 Key 的个人生产成功率。

## 为什么会有这个问题

原后台统计组件只传 provider 和 base_url，没有传 Key ID；models 为 null 时直接列出服务商公开统计中的所有模型。它不读取 Key 模型接口，也不应用后台绑定清单。客户端已经按账号能力清单过滤，但两端共享的展示仍是折叠表格，没有绿色分段条。原测试仅验证添加绑定与公共统计读取，没有覆盖同一服务商的两把 Key 能看到不同模型。

## 修改

- 后台 Key 库每行新增“模型与成功率”，打开直接显示模型卡片；编辑 Key 下方同步显示，未保存或改了地址/凭据时提示保存后读取。
- 后台只按保存的 Key ID 查询模型配置，不采用浏览器指定的地址发送凭据。绑定模型与客户端保持一致，优先于自动拉取；未绑定时用已发布适配包的纯数据接口声明读取 Key 模型清单，绝不在服务器执行适配器代码。只提供公开列表或健康接口的服务商不能据此确认 Key 权限，提示绑定模型。
- 按 Key ID、配置 revision、接口规则隔离缓存；换 Key、换凭据/地址、换适配规则不会复用旧清单。停用立即清空。过期/鉴权失败不继续显示旧权限；不同分组凭据有任何一组失败会明确显示读取失败，避免误称为完整清单。
- 两个后台线程、五分钟缓存、失败三十秒后重试；网络请求在数据库事务及状态锁外，使用已有 DNS 公网校验、TLS 固定地址、禁止重定向、超时和响应大小限制。只回传模型 ID，不回传 Key 或服务商响应体。
- 客户端沿用当前账号的有效模型清单，点击模型输入框直接展开卡片。卡片显示完整模型名、成功率百分比、绿色分段条、平均耗时、样本量与统计窗口；已选模型下方保留简洁指标。
- 分段条只是百分比可视化，不伪造逐条任务历史。无统计为灰色“暂无数据”；实际 0% 为红色数字和未亮起的分段条；过期统计为黄色并标旧数据；请求统计与任务终态统计继续分别标注。

## 修完能避免什么

管理员不会再把某服务商公开模型误当成当前 Key 的可用清单。不同 Key 的模型范围各自展示；读取失败能看到具体是模型目录问题，未知成功率不会冒充 0% 或 100%。客户端选模型时直接看见服务商成功率，无需打开另一张表再查名字。
