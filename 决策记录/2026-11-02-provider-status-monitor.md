# 用模型或健康接口监测服务商状态

日期：2026-11-02

用户需求：
> 我现在已经有各家的获取模型接口或是健康检查接口，是否可以做一个服务商的状态监测？

## 已查明

现有客户端 `server/app.py` 的 `/api/selftest` 会优先调用服务商专用自检，再调用 `list_models()`；服务端已有按账号查看的请求诊断，但没有统一服务商定时探测页面。现有模型拉取不能直接当作健康判据：基类会把 API 错误转换为空列表，部分服务商有静态模型列表或缓存；Gate 等服务商的公开模型接口也不能证明某把 Key 的鉴权与生成权限有效。

因此需要明确区分实时探测结果、Key 鉴权和真实生产结果。模型/健康接口正常只能证明该入口当时可达且响应符合预期，不能保证所有模型都能生成。服务器探测也不能代表用户电脑到服务商的网络情况。

## 建议的首期范围

- 服务端管理后台新增服务商状态入口，复用 Key 库中选定的凭据及各家的实际探测接口。
- 后台独立任务定时探测，页面读取最近结果；提供手动检测。建议默认每 5 分钟一次，有限并发与超时，不持有数据库事务或登录锁等待外部网络。
- 分开显示连通正常、鉴权失败、限流、服务端错误、连接/超时、响应异常、未配置和结果过期；同时显示探测来源、时间和耗时。无鉴权的公开接口明确标记“未验证 Key”。
- 不使用静态或缓存模型列表作为本次探测成功证据，不发起图片、视频或 LLM 生成。日志不保存密钥及原始响应正文。
- 沿用现有账号请求诊断辅助对照实际用户失败，不自动归因为用户本地网络问题。

## 需要明确的两项范围

### 1. 从哪里发起探测

- A（推荐）：先由服务器探测，在后台集中查看；本期只升级服务端。
- B：服务器和 Studio 客户端都探测，后台可对比两端结果；同时需要更新客户端，客户端断网时结果只能恢复连接后补报。

### 2. Key 的监测范围

- A（推荐）：每个服务商选择一把检测 Key，优先判断服务商入口状态；其他 Key 的失败沿用账号请求诊断查看。
- B：检测 Key 库中所有启用的 Key，可以发现个别凭据的鉴权异常；同一服务商可能产生多次请求，需要分批限速，无鉴权健康接口仍不能验证 Key。

## 用户选择

用户已选择：服务器和客户端都监测；每家选择一把检测 Key。两端使用同一监测配置，客户端仅获取已获授权的检测 Key，不借监测扩大账号权限。服务端和客户端独立后台执行；客户端结果断网暂存、恢复后按原账号补报。未授权使用该检测 Key 的账号不参与该服务商探测，后台说明无记录的多种原因。

## 实施结果

- 账号服务升级为 `1.11.0`，Studio 升级为 `2026.11.02.2`。后台和客户端设置新增“服务商状态”；默认未配置，管理员逐家选择检测 Key、GET 地址、响应类型与鉴权请求头后启用。
- 两端复用轻量探测模块，实时读取模型列表或健康接口。每 5 分钟左右检测，手动检测间隔至少 30 秒；服务器最多两个并发、客户端单独后台线程。网络请求不占用账号锁、生产锁或数据库事务。
- 只记录状态、耗时、时间、模型数量和账号设备归属，不保存 Key、原始请求头或响应正文。状态可区分 DNS、TLS、超时、连接、鉴权、限流、服务端错误和格式异常；公开接口不承诺 Key 权限有效。
- 客户端使用与原登录会话绑定的受限监测凭证，避免普通访问令牌过期后被迫频繁进行完整登录/版本校验。该凭证不能访问普通账号或生产接口，随会话撤销、到期或停用失效。监测配置每次下发仍检查所选 Key 是否分配给该账号。
- 已获取配置最多保留 15 分钟；断网结果最多暂存 7 天 / 2,000 条，恢复连接后按原账号补报。服务器保留最多 7 天 / 50,000 条。配置或 Key 变更后旧结果不再作为当前结果；撤销权限后的迟到记录丢弃。
- 检测仅允许公网 HTTPS 443、标准请求头及 GET；校验 DNS 全部地址、绑定实际连接 IP 并校验证书，不携带凭据跟随重定向，不使用系统代理。此处结果反映直连路径；不能单凭成功或失败断言真实生成接口、代理路径或其他 Key 的状态。
- 现有适配包和生产链路保持兼容；旧客户端继续使用原功能，新客户端连接旧服务端时仅监测不可用。升级不会自动改变推荐版本、最低版本或停用服务商。

## 为什么需要这样修改

原模型拉取可能走静态表、缓存或吞掉接口异常，且服务器和用户电脑处于不同网络。仅看能否拉到模型、是否收到账号日志，无法确认请求究竟在哪一端失败。新的监测给两端提供统一且带时间的实时观察，并保留断网补报记录，减少把鉴权、服务商错误和网络故障混为一谈；无记录和过期结果明确不能当作正常或离线的证明。

## 升级交付

使用已有宝塔覆盖程序文件、重启服务的流程，保留数据库、环境与 Key 配置。无需新增依赖或重复初始化账号。具体步骤见 `auth_service/PROVIDER-MONITOR-UPGRADE.md`；发布资料目录为 `D:\Studio-release-20261102-provider-monitor`，R2 上传和后台登记/推荐是分开的步骤，不自动操作线上发布策略。

## 验证

- 客户端完整回归：`3810 passed, 1 skipped`；账号服务最终完整回归：`192 passed`。
- 实际升级 ZIP 解压后，监测接口专项 `7 passed`；升级包 78 个源文件逐一与源码及 SHA256 清单比对通过。
- 新增测试覆盖公网地址及重定向限制、凭据不泄露、多地址连接回退、慢探测不占锁、账号/设备隔离、离线补报与确认、配置租期、Key 撤销和变更、监测凭证权限/到期/撤销、记录上限/清理、网页转义和异步页面切换。
- 无 Key 健康接口实测成功返回 HTTP 200，耗时约 615ms；没有发起付费图片、视频或 LLM 生成。线上各服务商的正式监测仍需管理员配置后启用。
- 实际安装包内容、运行自检、本地启动和 R2 全量下载的后续验证结果随交付保存于 `VALIDATION.json`。
