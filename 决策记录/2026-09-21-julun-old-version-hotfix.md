# 用单文件外挂修复旧版巨轮结果查询

日期：2026-09-21

起因：用户询问旧版本也有巨轮问题，能否单独提供文件外挂覆盖，而不更换整个旧程序。

## 定性

现有服务商加载器先注册内置，再从数据目录 `providers/` 加载外部 Provider 子类；相同 `id` 允许覆盖，并在扫描报告中提示来源。首次内置巨轮的历史提交也具备该机制。

巨轮问题是旧 `_poll` 只读 `data` 包装，忽略新版接口的顶层 completed/failed。修改 JSON 配置无法修复方法内的解析；但同名 Python 服务商插件可以覆盖该方法，无需替换 EXE。

## 实施范围

提供 `provider_patches/julun_result_hotfix.py`，继承宿主内置的 JulunProvider，保持 id=julun，仅覆盖 `_poll`。模型能力、上传、提交、下载等方法仍由旧 EXE 提供，不复制整份当前服务商实现，避免把新版本依赖带入旧版。

查询逻辑与已修复版本一致：兼容新旧响应；完成返回下载地址；失败保留原文和机器码；一般失败沿用重试预算；肖像保护拒绝不原样重发。早期接口模块缺少 RUNNING_STATES，因此插件提供该常量的本地回退。插件内不包含用户 Key，不进行导入时网络请求。

补丁不安装进本机实际数据目录，只生成供用户部署的文件和 ZIP。安装目录依据旧程序启动窗口的实际“数据目录”，不能一概称为 EXE 目录。明确提供移除恢复方法，以及升级已修复 EXE 后应移除旧补丁的说明。

## 验证

90 项专项测试通过，包括同名覆盖、仅影响巨轮、能力与凭据沿用、移除恢复、早期常量缺失兼容，以及新旧响应和调度器失败重试。

旧包 `Respect-Studio-Agent-20260920.zip` 中的 EXE 经原 SHA256 `23c2925a0f72935cec7ed3c8b0a390b4ab4d29813e8cf44ba9b3f14b7b8e12f5` 核对，在隔离数据目录加载补丁并通过本地模拟接口验收：完成下载一次；普通失败提交三次；肖像拒绝只提交一次；全部终态只查询一次。证据：`outputs/julun-frozen-qa/20260921-161518/results.json`。未进行真实付费生成。

全量回归 2632 项全部通过（268.88 秒）。日志：`outputs/julun-hotfix-full-tests-20260921.log`。补丁仅声明支持已内置巨轮且允许同名覆盖的宿主，不声称测试过全部历史 EXE。

## 修完能避免什么

旧版无需整体升级就能识别巨轮的完成和失败终态，不再无谓等待超时；同一旧版上的其他功能和服务商继续沿用原实现。卸载补丁可恢复内置服务商，升级后移除补丁可避免旧外挂长期遮蔽后续内置修复。
