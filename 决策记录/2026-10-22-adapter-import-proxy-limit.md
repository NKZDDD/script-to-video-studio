# 适配包导入被旧 Nginx 请求体上限拒绝

日期：2026-10-22

起因：用户提供“服务商适配包 → 导入版本”截图，底部显示“服务没有返回有效结果，请检查连接后重试”。

## 定性与范围

线上 `/health` 为 1.8.0；未登录的小请求正常返回 401 JSON，同一导入接口提交交付包的 527,243 字节请求则返回 Nginx 413 HTML。未携带管理员凭证，未导入、发布或改变线上状态。

原 `deploy/nginx-location.conf` 仍限制 16 KB，而适配包接口在应用中已放宽至 2 MB。前端统一 `response.json()` 把非 JSON 错误折叠成笼统连接提示。应用测试绕过反向代理，之前未覆盖代理与应用的大小契约。

范围为认证后台共享 API 报错、Nginx 部署模板和升级说明。两套生产体系、客户端与适配器内容均不需要修改。

## 实施

- 代理模板改为 3 MB，应用各接口原限制不变。
- HTML 413 显示大小限制与修复位置，其他非 JSON 响应包含 HTTP 状态码，不回显响应内容。
- 升级说明明确修改已部署代理的原 `location`，避免只改外层 `server` 或误以为解压应用即可更新 Nginx。
- 服务端补丁版 1.8.1，客户端继续使用 2026.10.22.2，原适配包继续有效。

## 修完能避免什么

新部署不会再用 16 KB 代理挡住合法适配包和配置导入。已有站点重载修正后的 Nginx 配置即可重新导入；后续遇到代理拒绝时，页面明确显示 HTTP 413，不再误报为无法判断的连接问题。

## 验证

- 服务端全量 124 项通过；Studio 全量 3475 项通过。
- Node 实跑共享 API helper，覆盖 HTML 413/502、异常 200、应用 JSON 错误与正常响应；不回显响应正文。
- 原交付完整 JSON 在本地服务中成功导入，24 个服务商，未自动发布。
- 1.8.1 部署 ZIP 为 150,044 字节，内部 60 个文件的 SHA-256 全部验证；未打入数据库或本机配置。
- 线上站点配置仍须管理员保存并重载，未修改远端 Nginx、导入适配包或更改发布策略。
