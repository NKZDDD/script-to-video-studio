# Key 库、账号授权和按模型使用 Key

日期：2026-10-16

## 用户确认的最终需求

统一 Key 库，每条可自行命名；账号任意勾选授权，同一 Key 可分配多个账号，同一服务商可有多把 Key。服务商显示 Studio 原有中文名称。用量对账具体到账号和 Key，显示成功、失败等次数。

用户随后明确：多个 Key 是为了不同模型分组，不是主用与备用。客户端需主动刷新服务端最新配置，分别获取每把 Key 的模型，合并展示，按所选模型使用对应 Key。此次最终实现按此纠正执行，不在失败后自动换 Key。同一个模型出现在多把 Key 时，仅按授权列表顺序选择一把。

## 为什么原来不支持

`provider_assignments` 以账号和服务商为唯一键，凭据直接存在账号下，无法复用独立命名的 Key。客户端只解析一份服务商配置，模型目录合并后也没有保存“哪个模型来自哪把 Key”，用量只有分配版本而无稳定的 Key 标识。

## 实施范围和结果

- 新增共享 Key 库与账号授权表，启动时自动迁移旧配置并保留授权；迁移幂等，不按密钥相同自动合并。
- 后台 Key 库支持命名、编辑、停用、模型绑定；账号页勾选授权；内置 24 家服务商名称与 Studio 对齐。
- 客户端登录自动获取配置，顶部和服务商设置增加主动刷新入口，强制在线验证后获取最新授权和各 Key 模型；按模型选 Key，并使用该 Key 的接口地址。
- 无模型接口或目录不区分权限的服务商，可以显式绑定模型。目录部分失败明确报告；不猜测失败 Key 的可用模型，不把名称、Key ID 等元数据作为凭据发送。
- 账号到期、停用和退出沿用登录验证；后台 Key 及模型对应关系仅在客户端内存中。旧批次冻结凭据，新配置用于后续批次。
- 所有图片/视频共用 worker 接入模型对应选择，已有任务按原 Key ID/指纹取回，Key 移除、停用或变更时保留 ID，不重提。模型下架也不拦旧 ID 续查。
- 每次尝试记录稳定 Key ID 与名称；后台按账号、具体 Key 汇总成功、失败、处理中/待取回、结果不明并导出 CSV。旧记录缺少标识时明确显示，不猜测归属。

下次分配另一模型分组的 Key 后，用户主动刷新即可看到两组模型；选择模型 A、B 会分别使用对应 Key，而不再把多个 Key 当作故障切换列表。
