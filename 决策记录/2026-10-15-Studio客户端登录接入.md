# Studio 接入已部署的登录服务

日期：2026-10-15
起因：用户提供 `https://login.respect.chat/` 并回复反向代理“已修改”。延续已确认的登录流程：线上仅校验账号，服务商 Key 和生成均留在客户端。

## 定性与范围

服务器经宝塔 Nginx 终止 HTTPS 后转发到 HTTP 应用，原代理没有传递 X-Forwarded-Proto，导致应用要求 HTTPS。health 不受该检查限制，所以仅检查 health 会漏掉此问题。用户修改后已验证公网 health=200、无凭证 verify=401、空参数 login=422。

旧 Studio HTTP Handler 没有任何登录门控；部署认证服务器不会自动改变本地 EXE。此次在本机 Handler 覆盖所有项目 API、文件读取和生产操作，浏览器新增登录入口。无新的需求歧义，按已确认方案实施。

## 实施

`core/studio_login.py` 连接固定认证域名；凭证仅内存，浏览器只获独立 HttpOnly Cookie，数据目录只保留设备 ID。正常缓存 60 秒；生产、合成、字幕、模型刷新前强制在线校验。多线程串行刷新；不确定的刷新结果要求重新登录，避免复用已轮换凭证。

页面支持登录、退出、断网重试，账号停用/到期后锁定。拒绝跨站请求和非本机 Host。已启动整个批次继续执行；登录模块不改旧任务 ID，不因登录失败自动重发。没有每次生成单独鉴权，也不宣称能防本地代码修改。

数据目录迁移带上设备 ID；打包自检改为离线检验创建项目，再验证未登录 HTTP 请求被拒绝，没有增加生产环境的免登录开关。

## 为什么与避免什么

此前登录服务独立于 Studio，本地接口仍可直接访问，所以后台禁用账号不会影响生产。现在未登录不能读项目或启动生产；认证断网会明确提示重试，停用会在下次校验阻止操作。不会把凭证续期失败误当成生成失败，也不会清掉已付费任务的 ID。

## 验证

公网接口已验证 health=200、无凭证 verify=401、空参数 login=422。隔离的真实 HTTPS 服务和 Chrome 页面完成错误密码、登录、并发续期、断网重试、账号停用、重新启用及退出；未调用生成接口。页面截图及结果位于 `outputs/studio-login-ui-vl5k38ic/`。

登录专项 12 项通过；发布资源、离线创建项目和运行库自检通过。全量首次为 3275 通过、1 失败（524.95 秒）：旧合成用例先观察到 `job.status=done`，再读尚未落盘的 result.json，属于已记录的异步写盘竞争。该用例与登录、时长分类共 18 项复测通过；未扩大范围修改合成逻辑。

代码已接入登录，当前旧 EXE 尚未重新打包，不会自动获得登录入口。
