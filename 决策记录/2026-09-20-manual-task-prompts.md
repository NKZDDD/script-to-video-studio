# 开放任务提示词直接编辑，并保证下次生产使用新版本

日期：2026-09-20
起因：用户先问“现在是不能直接修改提示词了吗”，随后明确要求“把直接编辑也开放”。

## 定性与范围

新版 `web/agent.js` 的任务详情只展示提示词和 Agent 修订入口，`server/agent_api.py` 只有提示词读取接口；`core/agent_projects.py` 接收发布后冻结任务与提示词，`core/agent_runtime.py` 启动批次时再冻结生产快照。此前按 Agent 交付流程验收，未覆盖用户在工作台手改任务提示词的入口。只放开输入框或覆盖原发布文件，都不能保证生产读取新内容，且原输出存在时可能继续复用旧成品。

范围是任务提示词：Agent 项目的资产图、场景状态图、交接板整板、交接板区域图、分段视频，以及旧项目的相应任务（包括已有故事板）。不恢复工作台内的文字模型调用和旧流程提示词模板管理。

## 用户决定

用户已明确授权直接编辑。沿用前一答复给出的行为：任务详情编辑、保存新版本、下次生产生效；运行中批次保留原提示词，旧产物保留。

## 实施

- 任务详情增加“查看 / 编辑提示词”，弹窗展示正文、版本与受影响任务，支持“保存新版本”。保存失败保留输入，不自动发起生产。
- 新增 `core/prompt_edits.py` 和按项目、任务编号寻址的读写接口。Agent 项目生成下一份完整发布并沿用现有校验与接收流程；旧项目保存独立提示词、任务清单版本及修改记录。
- 本任务及沿实际文件引用链受影响的下游更换输出文件名，同步引用路径。无关任务、勾选状态、原发布、旧产物不变；未修改提示词保留原始字节，避免 BOM 或换行符变化误判其他任务修改。
- 保存和生产启动共享锁，已启动批次继续读取自身快照。编辑令牌覆盖任务清单及所编辑的原文；检测到其他编辑或 Agent 新发布时拒绝覆盖。旧项目也提供可比较的修订号，过期生产预览不能启动。
- 空内容拦截；仅换行符规范化或没有实质改动不新建版本。跳过已存在的未完成发布目录。校验失败保留诊断材料，但撤下本次 READY，继续使用原接收版。

## 修完能避免什么

用户可以在工作台直接调整任务提示词，并在下一次生产使用修改后的内容。修改本任务会明确展示受影响的下游，新输出路径使生产不再把旧图或旧视频当成修改后的结果；运行中任务不会因中途修改而混用新旧提示词。过期编辑不能静默覆盖新发布，保存失败的内容仍留在编辑框内供复制和对比。
