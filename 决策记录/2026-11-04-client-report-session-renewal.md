# 主动上报漏接短期登录凭证续期

日期：2026-11-04

起因：用户反馈“另一个账号为什么在这里失效了”，主动日志上报页面显示“登录已失效，请重新登录同一账号后重试”。

用户补充：“这个问题已经是登录一段时间了这个问题没有很重要，保留续期就可以”。按上报时按需续期收尾，不增加日常后台校验，不继续扩展账号排查。

## 定性和范围

`core/client_reports.py::_send` 直接取内存中的 access token 调用上报接口，没有像生产前验证和 R2 签名那样处理 `access_expired`。服务端默认短期凭证 900 秒，到期与账号使用期限到期是两件事。普通本地操作有意只检查本地登录状态，不持续联网续期；因此页面仍可用、手动上报却失败是可复现的情况。

旧上报分支还把所有 HTTP 401/403 合成同一句“登录已失效”，丢掉了服务端的 `access_expired`、`invalid_session`、`account_disabled`、`account_expired` 等错误码差异。截图只能证明上报遇到鉴权拒绝，不能单凭它认定该账号真实到期或停用。

范围为通用的手动日志上报（首次发送和手动重试），与服务商无关，覆盖全部 Studio 生产体系。生产前验证及 R2 签名已有续期；自动基础诊断、用量上报继续其现有策略，不扩大自动联网范围。

## 修正

- 手动上报遇到 `access_expired` 时复用已有验证/续期逻辑，再用新凭证发送同一编号、同一内容，最多重试一次。正常发送不先增加联网校验。
- 与现有登录网络锁协调。其他请求已轮换 token 时复用新 token，避免重复使用 refresh token；等待网络不占本地页面状态锁。
- 切换账号后不会用新账号凭证发送旧报告；网络失败仍保留报告，等用户手动重试。
- 分开显示账号停用、使用期限到期、会话失效和其他访问权限拒绝；不回显服务端原始错误正文。
- 既有续期流程对明确的账号/会话拒绝保留原错误码，同时继续清理无效会话；网络不确定的续期仍要求重新登录，不重用可能已轮换的 refresh token。

## 复现与验证

新增测试在修正前复现 5 项失败：短期凭证到期无法上报，以及 4 类鉴权错误提示混淆。修正后客户端专项 66 项通过。

本地真实服务端联调：账号正常，推进时钟至短期凭证到期后，本地登录状态仍可用；请求依次为上报 401、验证 401、续期 200、验证 200、同一报告上报 200，数据库只有一份报告。账号期限真正到期时，则在续期阶段保留 `account_expired` 拒绝，数据库不写报告、客户端清除过期会话。两项联调均通过。

补充并发 token 轮换、切换账号、续期最多一次和慢续期时本地操作可用的回归测试。完整客户端回归 3869 项通过、1 项跳过（484.09 秒）；完整账号服务回归 226 项通过（397.75 秒）。日志位于 `D:\Studio-checks-20261104-report-session\final-client.log` 和 `final-server.log`。未修改线上账号、未发送真实报告或创建生成任务。

## 交付边界

此前发布的 EXE `2026.11.04.1` 尚不包含本次修正；本次只修源码，不覆盖同版本 R2 安装包。现有服务端 `1.12.0` 已支持所需接口，无需因此修改账号或 Key 配置。

旧 EXE 临时处理：重新登录同一账号后，点击“重试本次上报”。原上报内容保留，不用重新生成视频。

修正后能避免正常凭证到期被误报为账号失效；真正停用或到期仍然拒绝上报，并显示对应原因。用户截图对应的真实服务端错误码仍需该次服务端请求记录确认。
