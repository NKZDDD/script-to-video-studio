# 让参考图标点契约与现有身份校验一致

日期：2026-10-03
用户要求：「按照现有读写方法你这个在契约中能正常修改标点吗？这样我原来项目提示词换上新契约能正常修改吗」「按照此要求修改studio」。

## 问题机制

`core/produce.py::_who_is_named` 的行内身份读取止于换行、中文/英文分号、中文句号。原契约只要求 `Image N = ID 身份描述`，没有解释标点边界，因此 `Image 1 = ID；人物姓名与年龄` 虽然人能理解，程序仍将其视为缺少身份。读取和提交使用完整提示词；这个边界仅用于校验，不会把后半段提示词截掉。

## 已确认的范围

按现有读写方法完善写作契约，不放宽或改写身份校验器，不批量替换项目内已有提示词。涉及新项目本机契约、已有 Agent 项目的契约、定向修订请求、电影级和通用材料契约、导出交接包。

## 实现与兼容

- 共用 `core/reference_contract.py` 的规则，要求 ID 后同一行先写明确身份，再使用分号或句号。给出人物、场景、道具实例，并说明逗号、分号、句号、换行的用途。
- Agent 项目打开时检查规则标记；旧契约按原始字节保留并原子追加规则，仅补一次，不重新生成项目编号、路径、锁定选项或技能包。
- 新项目、交接包及材料契约使用同一规则；定向修订请求也携带规则，因此无 Agent 锁文件的旧项目可以收到修订指导，无需自动迁移。
- 明确修改契约不会自动重写提示词。Agent 发布走新版本及文件散列，Studio 直接编辑走保存新版本；保留旧成品、已接收发布和运行中批次快照。

## 修完能避免什么

Agent 能事先看到标点读取边界，避免把身份放到 ID 后第一个分号/句号/换行之后而被误判为空；修改旧提示词时明确只调整受影响映射，不全篇替换标点或覆盖项目契约的身份信息。规则仍依靠 Agent 遵循，原有缺身份/编号不一致的提示词仍会被校验拦截。
