# 产物逐项删除与视频参考音频

日期：2026-10-07
起因：用户要求“这个是需要可选删除增加一个选择的功能，以及视频生成现在可以增加参考音频”。

## 定性与范围

删除窗口仅按链路生成候选列表，`web/agent.js` 的 `delete-run` 把全部存在文件提交；后端 `core/recycle.py` 已按 keys 精确移动，因此缺的是前端逐项选择与准确计数。

多家视频适配器已经读取 `VideoTask.extra.audio_refs`，但 `core/produce.py` 构造视频任务时没有传入，Agent 任务详情也没有添加入口。需要贯通详情、独立项目配置、生产预览、批次快照、音频上传及视频执行；共同执行层同时兼容旧项目。

## 实施范围

- 删除列表增加逐项勾选、全选、清空，候选链路只决定列表范围，实际只删除勾选文件。未选的下游产物保留。
- 每条视频任务添加本地参考音频，支持试听与移除；对象存储转换为公网 URL，再交给支持参考音频的模型。
- 音频文件按内容保存不覆盖；任务启动后冻结引用，之后移除绑定不影响在跑批次。已有服务商任务仍按原 ID 取回，新引用仅用于下一次新提交。
- 模型不支持或超出声明数量时给出移除音频/更换模型的处理办法，不能静默丢掉音频生成。

## 验证与交付

为什么以前会这样：删除预览里的列表原本只是展示，前端没有保存每一项的选择状态，提交时直接传整份列表，所以后端按 keys 精确删除也无法替用户保留某一项。音频则只有适配器层支持，通用视频任务没有传 `extra.audio_refs`，因此接口支持不会自动变成 Studio 的可用功能。

现在的行为：链路选项列出候选，逐项勾选决定最终 keys；未勾选的下游成品不会移动。音频添加到任务详情，验证为真实可解码音频后保存，通过对象存储独立上传原始音频字节，并按列表顺序传给服务商。模型不支持或超出声明数量时在生产计划说明原因及处理办法，避免静默忽略音频。单文件上传上限为 Studio 侧 25MB，支持 MP3/WAV/M4A/AAC/OGG/FLAC。

生产批次冻结音频引用；移除绑定保留音频文件，避免在跑任务引用失效。已提交任务仍优先取回原 ID，不会因修改音频重复提交。

验证：参考音频及固定任务 ID 重点测试 19 项通过；浏览器使用真实页面事件处理器验证逐项删除、全选/清空、忙碌项拦截、切换范围保留选择、音频上传/移除和 WAV 实际播放，通过。浏览器检查脚本：`py tests/check_delete_audio_ui.py`，所有 API 均模拟，无服务商计费请求。

全量 `py -m pytest -o addopts='' -q` 共执行 3045 项，初次为 3044 通过、1 失败。唯一失败来自旧测试以固定 1400 字符截取参考图校验代码，误包含紧邻的新音频校验 `raise`；改为 AST 精确检查原分支后，该文件 15 项复测全部通过，未改动原参考图生产规则。重点测试 19 项及浏览器检查也已通过。JavaScript 语法检查、`git diff --check` 通过。
