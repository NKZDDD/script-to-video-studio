出图出片优先级 首选挂了自动换下一家，只补没做完的

    

      三类活各排一条队。跑的时候按顺序用：第一家因为余额不足、密钥失效、没这个模型、
      限流、连不上而挂了，自动换下一家补剩下的，日志里会写清换了谁、为什么。

      但提示词被审核挡下、参数不合法、参考图还没生成这几种不会自动换——
      换家也一样，那是内容或流程要改，自动切只会把同一个错误重复几遍还多花钱。

      没填 key 的家会被自动跳过，不会让你白等一轮。
    

    

    

  

  

    
参考图上传（对象存储） 配好之后参考图统一走链接，请求体从几 MB 缩成一行

    

      资产图和故事板都在你本机，而不少接口的参考图只收公网 https 链接
      （零视 sd2-fast、seedance 系都是这类）。填一个 S3 兼容的对象存储，
      程序会自动把图传上去换链接——R2 / 阿里云 OSS / 腾讯云 COS / AWS S3 / MinIO 都是这一套。
      先 pip install boto3。同一张图全剧只传一次（按内容缓存），重跑也不重传。
    

    

      

        

      

      

      

      

      

      

        
        

      

        

    

    

      
      
      
    

    

  

  

    
计价（可选） 填了才显示估算金额；不填只统计用量

    

      各家计价方式不一样，程序猜不出来，所以要你填。不填不影响跑，
      只是「花了多少」那一栏不显示金额。金额一律是估算，账单以服务商后台为准。

      分析引擎按 token 计价：填每 100 万 token 的单价。
      出图出片一般按次：填每次的单价。

      键可以写 服务商/模型（最精确）、模型、或 服务商（兜底）。

服务商插件 丢个 .py 进去就多一家，不用改程序、不用重新打包

    

    

      
      
      
    

    

      插件目录在数据目录下，不在程序目录里 —— 更新程序、换 exe 都不会动它。
      写法照范例改：继承 Provider，给 id / name / supports，
      实现 capabilities() 和 generate_image / generate_video。
      参考图形式一定要声明对，声明错了不报错，只会让参考图被悄悄丢掉。

      ⚠️ 插件是真的会被执行的 Python 代码，只放你自己写的或信得过的。
    

  

  

    
数据与路径 换机器 / 更新程序前先看这里

    

    

      

        
        
      

      
    

    

      更新程序 = 覆盖「程序目录」，只要配置和产物不在里面，覆盖多少次都不会丢。

      换到另一台电脑：把程序目录拷过去（或 git clone），然后
      python run.py --data D:\stv-data，
      或者设环境变量 STV_DATA_DIR=D:\stv-data。
      配置和产物都从那个目录读，两台机器各有一份、互不影响。

      想两台机器共用同一批产物：把产物目录指到同一个网盘/共享盘路径即可
      —— 判断「做过没有」只看磁盘产物，所以另一台能直接接着跑。
      但别让两台同时跑同一个项目，会写同一批文件。
    

  

  

    
同时最多跑几个 同时做几部剧也共用这里的上限，免得把服务商发毛

    

      

      

    

    
「生产」页每一行也有个并发数字，那个只管这一行自己排多少队。
      真正发出去之前还要看两道关卡：这家服务商的上限，和上面这个总上限。
      比如三个项目各填了 5，但总上限是 8，那么同一时刻发出去的最多还是 8 个。
      被服务商拦（提示发得太快）的时候，就是把这里调小。
