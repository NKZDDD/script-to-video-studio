# 1.3.1：Key 库、按模型选 Key 与 config 导入

1.3.1 新增管理后台「Key 库 → 导入 config.json」。已有 1.3.0 客户端无需重打 EXE 即可使用后台导入后的授权；新服务商或新模型的接口适配仍需对应客户端/外挂支持。

服务端与 Studio 客户端都要更新。此前 1.2.0 的 EXE 不具备模型对应多 Key 和主动刷新功能；本目录是服务端部署文件，不是客户端更新。

## 宝塔更新

先按原部署方式备份并停止服务，只复制代码框里的命令：

```bash
cd /www/wwwroot/respect-studio-auth
runuser -u studioauth -- .venv/bin/python -m studio_auth.manage backup "data/auth-before-1.3-$(date +%Y%m%d-%H%M%S).sqlite3"
systemctl stop respect-studio-auth
```

将新 ZIP 内 `respect-studio-auth/` 的内容覆盖到此目录，**保留 `data/`、`.venv/`、`deploy/runtime.env`**，不要删除整个目录，也不要多套一层文件夹。不用重新创建账号或管理员，没有新增 Python 依赖。

```bash
cd /www/wwwroot/respect-studio-auth
systemctl restart respect-studio-auth
systemctl status respect-studio-auth --no-pager -l
curl -s http://127.0.0.1:8781/health
```

应看到版本 `1.3.1`。启动时自动将旧的账号服务商配置迁移为独立 Key 库记录并保留账号授权；迁移可重复执行而不重复创建。不按相同密钥合并，避免误改账号之间的共享关系。若需要回退旧服务端，必须恢复升级前数据库备份。

## 导入已有 config.json

在管理后台点击 **Key 库 → 导入 config.json**，选择不超过 512 KB 的 Studio 配置。预览中勾选条目，点击「导入所选」。导入后可编辑名称，再到账号中分配；客户端点击「刷新后台配置」。

读取顶层 `providers` 中的 `api_key`、`image_1k_api_key`、`image_4k_api_key`、`video_api_key`，每个非空凭据字段独立建条目，并保留 `base_url` 和明确填写的 `models` 数组。不会从生产默认模型猜测完整权限。无 Key 的服务商跳过，不支持的旧密钥字段明确提示；无效条目在预览中提示并跳过；JSON 结构错误整体拒绝。1.10.0 起也导入顶层 `llm` 的明确 `base_url`、`api_key`、`model`，建成“提示词改写 LLM”条目；缺少任一项会提示跳过。项目路径、上传凭据、代理、并发等配置不导入。详见 [LLM 配置升级说明](LLM-CONFIG-UPGRADE.md)。

预览不回显 Key。相同服务商、地址、凭据字段和模型绑定重复时跳过，不重新启用已停用的 Key；同名但不同内容则新建带编号的条目，不覆盖已有记录或账号授权。确认阶段再次校验并整体写入，超过库容量不会写入一部分。

客户端仍允许填写个人 Key：没有后台分配的服务商使用个人配置；已有后台分配时优先使用后台配置，不因失败或停用自动改用个人 Key。导入本身不会自动分配给任何账号。

## 使用步骤

1. 管理后台点击 **Key 库**，新增 Key，自定义中文名称，选择 Studio 原有的服务商中文名称。
2. 每把 Key 建成独立条目。同一个服务商可以建多把，Key 本身不回显；编辑时留空保留。
3. 到账号行点击 **分配 Key**，任意勾选需要的条目。同一条 Key 可以授权给多个账号，改动该条记录会同步影响所有被授权账号。
4. 更新后的客户端登录会自动获取配置和模型。之后随时点击顶部或服务商设置中的 **刷新后台配置**，立即重新验证账号、下载最新授权，再按每把 Key 分别获取模型。
5. 模型下拉框合并显示这些 Key 对应的模型，生产时使用该模型对应的 Key 和接口地址；不会因生成失败自动换另一把 Key。
6. 在账号行打开 **用量对账**，按具体 Key 查看成功、失败、处理中/待取回、结果不明次数，并可筛选导出 CSV。旧记录未包含 Key 标识时明确显示“旧记录 / 未标记 Key”。

## 模型对应规则

客户端 2026.10.22.1 起，已分配服务商的显示名称使用后台 Key 库的名称。同一服务商的多把启用 Key 按账号授权顺序合并名称，以 ` / ` 分隔并去重；模型仍合并显示、按模型选 Key。后台编辑名称并保存后，客户端点击「刷新后台配置」即可同步，不需要修改服务商 ID 或接口地址。未分配、旧后台没有名称、没有启用 Key 时保留客户端内置名称。该功能使用现有下发字段，服务端无须为改名再次升级。

这是显示名称同步，Base URL、接口请求、模型 ID 和已有任务记录不会因此改写。服务商外挂的 Python 适配代码仍需客户端预装或手动导入；下发 Key、名称和模型配置不等于下发或执行外挂代码。

- 默认使用这把 Key 请求服务商模型清单，仅拉取清单，不发起生成。
- 如果服务商没有模型清单接口，或返回的目录不按 Key 权限过滤，在 Key 库填写“绑定模型”，一行一个完整模型 ID。显式绑定优先于自动目录；它表示管理员配置，不表示已经通过服务商付费验证。
- 同一模型若出现在多把授权 Key 中，按账号已选列表中的顺序使用第一把；上移/下移只决定这种重叠情况，不是主备失败切换。
- 某把 Key 刷新失败会显示原因，其未确认的模型不会凭猜测转交其他 Key。其他成功 Key 的模型仍可显示。
- 自定义外挂要先在 Studio 安装，再在 Key 库选择“自定义外挂”并填写其原 provider ID。中文显示名不会替换内部 ID。
- 未分配的服务商仍可用个人配置；已分配但所有 Key 停用时，不偷偷回退个人 Key。

## 旧任务和使用记录

已提交的任务保存具体 Key ID 和凭据指纹。之后更改顺序或模型清单，取回仍使用原 Key；原 Key 被更换、停用或撤销授权时，保留任务 ID，提示恢复原凭据/授权。已经运行的批次保持开始时的配置，新配置用于后续批次。

用量以一次生成尝试为一条，轮询、取回和重复上报不新增生成次数。统计仅覆盖图片/视频，仍是客户端上报的对账线索，不是服务商的实际扣费证明。后台数据库及其备份包含服务商密钥，应保管好；发布 ZIP 不包含这些运行数据。
