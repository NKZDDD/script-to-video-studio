# 服务端 1.7.0：后台 R2 授权与客户端直传

配套 Studio 安装版 **2026.10.21.1**。服务端保存 R2 配置，按账号分配；客户端登录、续期校验或点击「刷新后台配置」后接收。图片和参考音频共用该配置，不需要在每台电脑填写存储密钥。

## 部署服务端

备份现有 `data/`，将升级包内 `respect-studio-auth/` **里面的内容**合并覆盖到 `/www/wwwroot/respect-studio-auth/`。保留 `data/`、`.venv/`、`.env`、`deploy/runtime.env`，不要删除目录后重新解压。

本次增加 boto3 依赖，宝塔终端只复制下面的命令：

```bash
cd /www/wwwroot/respect-studio-auth
.venv/bin/python -m pip install -r requirements.txt
systemctl restart respect-studio-auth
curl --retry 5 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:8781/health
```

应显示版本 `1.7.0`。如果服务由宝塔 Python 项目管理，安装依赖后在原项目入口重启，避免启动第二个进程。启动时自动增加 R2 配置和授权表，保留已有账号、Key 库、用量、版本统计和更新策略。现有账号默认不新增 R2 授权。

## 后台配置与分配

1. 打开 `https://login.respect.chat/admin/`，Ctrl+F5 刷新，点击「R2 对象存储」。
2. 可导入原有 `config.json`。浏览器只提取其中 `upload` 的 R2 字段，点击保存后提交；其他服务商 Key 不会提交。也可手动填写 Endpoint、Bucket、公开域名、目录前缀、Access Key、Secret Key，并启用后台 R2。
3. Endpoint 填 R2 的 S3 API 域名，公开访问域名填可公开读取该桶的自定义域或 `pub-*.r2.dev`，不能把两者混用。前缀使用 1–64 位英文字母、数字、横线或下划线，例如 `studio-references`。
4. 保存后，在账号列表点击对应账号的「R2 授权」，勾选允许并保存。
5. 客户端安装新版，登录后进入「设置 → 参考图上传」，点击「刷新后台配置」，应显示「已获授权」，再点「测试当前上传」。它会上传一个小文本并从公开域名读回，确认后即可生产。

后台已授权的账号优先使用后台 R2；未授权账号继续使用个人存储。个人配置不会被覆盖。后台已授权但存储停用时，需要上传的任务会提示处理，不会暗中换用个人密钥。已保存的后台密钥不会回显，留空保存表示保留。保存配置会生成新修订号，使后续上传缓存切换到新目录。

## 上传与期限

- 长期 Secret Key 留在服务端数据库，不写入客户端 config、批次快照或交付安装包。请沿用数据库目录的服务账号权限和备份保护。
- 客户端向登录服务申请单文件 PUT 授权，再直接向 R2 上传字节，文件不经过登录服务。服务端只处理元数据和签名。
- 每次签发都检查账号有效期、会话、设备、版本政策和 R2 授权。允许参考图片、音频和小型连通性测试，单文件最多 25 MiB；已有图片处理仍遵循 9.5 MB 上传副本预算。
- 签名绑定对象路径、文件长度和 Content-Type，有效期最多 300 秒，且不超过账号和会话期限。签名链接在过期前可重复使用，取消授权不能使已经签发的链接立刻失效。
- 客户端不能自行指定覆盖路径；服务端生成 `前缀/账号ID/配置修订号/内容SHA256.扩展名`。签名 URL 中包含 S3 Access Key ID 标识，但没有 Secret Key，不能据此签发其他请求。
- 图片/音频缓存只保存公开读取地址，不保存临时 PUT URL。换账号、更换存储修订号后重新上传，旧批次的后台存储授权不会跨账号沿用。
- 公开参考文件不会因为账号到期而删除。服务商异步取图需要读取地址保持可用；这与上传授权期限不同。按实际生产保留时间在 R2 设置清理规则。

## 安装包更新仍然独立

后台 R2 上传用于参考图片和参考音频。安装包继续由发布电脑上传，普通客户端只下载更新，不获得发布权限。本次交付 `release.r2.json` 可在「客户端版本 → 测试登记」登记构建，或在「正式发布」设置推荐/最低版本。

上传安装包、登记测试版本和安装此升级包均不会自动改变在线推荐版本、最低版本或版本校验暂停状态。旧客户端不识别本次下发字段，需要安装新客户端后才能使用后台 R2。
