# 1.2.0：服务商配置下发与用量对账

本次需要更新服务端代码与 Studio 客户端。旧版客户端仍能登录，但不会使用后台分配，也不会上报新增用量。源码运行可直接使用更新后的代码；EXE 用户需要重新打包后的客户端。

## 宝塔服务器更新

在终端只复制代码框中的命令，不复制 `[root@...]#`。以下按现有 `/www/wwwroot/respect-studio-auth` 部署目录操作。

先备份数据库并停止服务：

```bash
cd /www/wwwroot/respect-studio-auth
runuser -u studioauth -- .venv/bin/python -m studio_auth.manage backup "data/auth-before-1.2-$(date +%Y%m%d-%H%M%S).sqlite3"
systemctl stop respect-studio-auth
```

将部署 ZIP 中 `respect-studio-auth/` 内的文件覆盖到这个目录。**保留原 `data/`、`.venv/`、`deploy/runtime.env`，不要删除整个目录，也不要多套一层同名目录。** 不需要重新创建管理员或用户。

```bash
cd /www/wwwroot/respect-studio-auth
systemctl restart respect-studio-auth
systemctl status respect-studio-auth --no-pager -l
curl -s http://127.0.0.1:8781/health
```

健康检查应返回版本 `1.2.0`，服务应为 `active (running)`。本次没有新增 Python 依赖，启动时自动新增数据库表，保留已有账号。失败时运行 `journalctl -u respect-studio-auth -n 40 --no-pager -o cat` 查看原因。

## 分配 Key

打开 `https://login.respect.chat/admin/`，用原管理员账号登录。在对应普通用户一行点击“服务商配置”。

- 填服务商 ID，例如 `julun`、`cangyuan`（苍元图片）、`cangyuan_video`（苍元视频）。自定义外挂填其 `Provider.id`。
- 一般服务商填“通用 Key / 多账号凭据”；支持原来的分组字符串和多账号格式。
- 超模按 TH、Native、视频分别填分组 Key。后台分配了该服务商后，缺失分组不会偷偷改用个人 Key。
- Base URL 留空使用客户端该适配器的内置 HTTPS 地址；自定义服务商应填写其正确 HTTPS 地址。后台 Key 不会跟随客户端个人 Base URL 或个人代理设置。
- 已保存 Key 不回显，编辑时留空保留。要完全清除某个分组，先移除整家分配，再填需要的分组重新分配。
- 未分配的服务商继续使用本机个人配置。客户端设置页会标明当前来源；在那里保存的 Key 是个人配置，不能覆盖后台分配。
- 分配或更换后，客户端下次在线校验（通常 60 秒内）或开始新生产时刷新。已开始批次保留当时配置。

这次配置与统计覆盖 Studio 图片、视频生产，包含资产、场景/区域图、故事板和分段视频的共用生成路径。提示词改写 LLM、字幕服务和对象存储仍使用本机配置，不计入本次生成对账。

## 用量核对

在用户一行点击“用量对账”，按服务商、来源、时间筛选并导出 CSV。导出最多 10000 条，更多时缩小日期范围，不会静默截断。

- “后台分配”与“个人配置”分别统计；分配版本标识可区分更换 Key 前后。
- 一次生成尝试一条记录，重试会产生新的尝试记录；重复上报不重复计数，较旧的上报不能覆盖更新状态。
- 已有服务商任务 ID 的查询和下载沿用原记录，不增加生成次数。
- 升级前已经提交的任务没有原始上报信息，取回时标成“旧任务来源未知 / 仅取回”，不要当作新生成量。
- “已完成并落盘”表示客户端拿到了文件；“待取回”不等于服务商生成失败。失败、结果不明的请求也可能被计费，以服务商账单为准。
- 上报不包含 Key、提示词、图片、视频、项目路径或完整结果地址。时间来自客户端，并非可信计费时间。

客户端用 `usage-outbox.sqlite3` 暂存记录，连接恢复且同一账号登录后自动补传。更换账号不会把旧账号记录上报到新账号。页面右上角显示待同步提示；退出/到期期间可能暂未上报，不应将暂时差额直接认定为滥用。通过设置迁移数据目录时会一并迁移该数据库。

## 到期与旧任务

账号到期、停用或撤销后，服务端拒绝继续下发配置；正常客户端在下次校验后锁定新操作。已经运行的批次仍继续执行和取回。

更换 Key 后，原服务商任务可能只允许原 Key 查询。新版任务记录会检测凭据变化并保留原任务 ID，提示恢复原 Key，绝不因此自动重新生成。切换 Studio 账号也不会将旧账号任务归到新账号。

已被提取的服务商 Key 仍可绕过 Studio 直接调用。需要失效时到服务商后台撤销；移除后台分配只停止以后下发，不撤销服务商 Key。客户端上报可以被绕过或伪造，后台数据用于对账，不是可信扣费系统。

服务商 Key 存在服务器 `data/auth.sqlite3` 中，受现有系统账号及文件权限保护，未额外做数据库字段加密；数据库备份同样含 Key，应按密钥文件保管。发布 ZIP 不包含数据库、真实账号或 Key。
