# 服务商状态监测：账号服务 1.11.1 / 适配包 2026.11.02.3

本次补齐自动配置：每家只需选择检测 Key 并启用，接口地址、鉴权方式和响应字段自动读取已发布适配包。**已安装 Studio 2026.11.02.2 无需重复安装 EXE**；本次交付服务端升级包和适配包。

## 本次功能

后台新增“服务商状态”，Studio 设置新增“服务商状态”。服务器和客户端分别直连检测，每家选择 Key 库中的一把检测 Key，约每 5 分钟一次；可手动检测，同一端手动请求至少间隔 30 秒。服务器最多 2 个探测并发，客户端在独立后台线程中逐家执行，不持有登录、配置或生产锁等待外网。

检测仅发送 GET 请求，不创建生成任务。支持模型列表 JSON、健康状态 JSON、仅 HTTP 2xx 连通检查。可区分 DNS、TLS、连接失败、超时、401/403、429、5xx、重定向与响应格式异常。显示最近检测时间、耗时、HTTP 状态、模型数量（模型接口）和探测来源；超过 15 分钟标记结果过期。

模型或健康接口正常不能证明所有模型可以生成。公开接口可能忽略携带的 Key，因此页面只说明是否携带 Key，不宣称所有生成权限已验证。没有客户端记录也不能认定用户断网。

## 升级服务端（宝塔方式）

1. 备份 `/www/wwwroot/respect-studio-auth/`，尤其是数据库和运行配置。
2. 将 `respect-studio-auth-1.11.1.zip` 上传到宝塔，解压目标选择 `/www/wwwroot/`，合并覆盖同名程序文件。ZIP 已包含 `respect-studio-auth/` 顶层目录。
3. 保留原 `.env`、`data/`、`.venv/`、`deploy/runtime.env`。不重新初始化账号，不删除应用目录。
4. 执行：

```bash
cd /www/wwwroot/respect-studio-auth
systemctl restart respect-studio-auth
curl --retry 5 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:8781/health
```

健康检查应返回 `1.11.1`；后台按 Ctrl+F5 刷新。没有新增运行依赖。从监测前版本升级时首次启动自动创建监测相关表；从 1.11.0 升级不需要额外 SQL。原账号、Key 与发布策略不变。

## 配置监测

先在后台“服务商适配包 → 导入版本”导入 `Studio-providers-2026.11.02.3.json`，再在版本历史点击“发布此版本”。仅导入不会改变当前规则。

然后点击“服务商状态”，在“新增 / 编辑监测”中选择服务商及检测 Key，保留“自动读取适配包”，勾选启用并保存。界面会直接显示识别出的检测地址；不需要再填鉴权或 JSON 字段。Key 已配置的 Base URL 优先；未配置时使用适配器默认地址。没有默认地址的章鱼哥仍需要在原 Key 设置里填写自己的网关地址。

自动规则会跟随适配包发布和回退；不同规则的旧结果不混入当前结果。已保存的手动设置不会被覆盖，可编辑后切换为自动。没有监测声明的旧包或自定义服务商会明确提示缺少规则，可选择“手动设置接口”。

本包覆盖 28 个已维护服务商，其中 26 个提供标准 GET 监测规则。XMD 使用动态签名，HVTALD 使用 WebDAV 多项凭据，需要专门适配，界面明确提示；不会用它们的固定模型列表制造“正常”结果。健康状态只代表检测入口。

以下仅供需要手动设置的特殊接口参考；标准服务商无需填写：

- OpenAI 兼容模型列表：常见为 `/v1/models`，类型“模型列表 JSON”，结果路径 `data`，鉴权 `Authorization: Bearer`。
- Gate 公开列表：`/public/model_group/info`，结果路径 `data`。公开接口的连通结果不代表 Key 有效。
- 形如 `{"ok":true}` 的健康响应：类型“健康状态 JSON”，结果路径 `ok`。
- 形如 `{"data":{"status":"healthy"}}`：健康类型，路径 `data.status`。
- 健康接口只返回纯文本或无需解析正文：选择“仅检查 HTTP 2xx”，不需要 Key 时选择“不携带 Key”。此模式不判断正文里的业务错误。

只允许公网 HTTPS 443 地址，不跟随重定向，不使用系统代理。DNS 的所有解析地址必须为公网地址，实际 TLS 连接绑定已检查的地址并校验域名证书。检测地址不能带密钥参数；请使用 Key 字段和请求头配置。使用特殊签名、非 GET 或非标准鉴权的接口需另行适配，不把静态模型表当作成功结果。

保存后自动进入监测，也可点击“立即检测服务器”。编辑配置、Key 密钥或 Key 的服务商归属后，旧结果不再算作新配置的当前状态。坤鸡的独立字段或组合 Key 使用所选 Key 条目内的一把凭据，不检测或分发其他未授权 Key。

## 客户端

安装 Studio `2026.11.02.2` 后登录，打开“设置 → 服务商状态”。只有已经获授权使用指定检测 Key 的账号才参与该家探测；系统不会把检测 Key 下发给其他账号。监测配置通常在 5 分钟内同步，也可点击“立即检测”。

监测使用只允许领取监测配置及上报监测结果的会话凭证，不触发完整账号/版本校验，也不能用于普通登录、生产授权或领取其他配置。凭证仅保存在内存中，随原登录会话撤销、到期或账号停用失效。每次领取配置仍检查 Key 授权。

短时断网时使用内存中的配置继续检测，配置最多有效 15 分钟；随后停止使用未重新确认的配置。结果仅在本机保存无密钥记录，最多 7 天 / 2,000 条，恢复连接后按原账号补报。切换账号不会把旧账号的记录发给新账号。后台最多保存 7 天 / 50,000 条，展示最近 200 个账号设备与服务商的组合；客户端记录明确属于客户端自行上报。

监测结果不会自动停用 Key、切换服务商或阻止生产。已有“请求诊断”继续用于查看真实生成、LLM、登录和本地操作问题。

## 发布范围

本次需要升级服务端并发布带监测规则的适配包。适配包协议仍为 1，生成接口实现保持不变，旧客户端仍可加载。Studio 2026.11.02.2 已支持完整监测配置，无需再安装 EXE；更旧客户端需要先安装该版才能参与双端监测。不需要提高最低可用版本，也不自动改变后台客户端推荐版本。

## 后续维护接口

维护服务商适配器时，可在类的 `monitor` 中声明 `path`、`kind`、`result_path`、`auth`，可选 `key_fields`。默认模型接口沿用基类的 GET `/v1/models`。构建工具将规则与实际 `default_base_url` 一起导出到适配包的 `provider_monitor_catalog` 纯数据模块。服务端使用 AST 字面量解析，不导入或执行适配器 Python；规则格式错误会在导入时明确拒绝。

修改规则后递增适配包版本、重新导出并发布即可。服务端仍只做真实 GET，不使用模型缓存和静态兜底。不同协议或签名需要先实现对应的探测能力。
