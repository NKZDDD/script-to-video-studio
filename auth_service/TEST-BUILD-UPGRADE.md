# 登记测试版本，不向普通用户推送更新（服务端 1.6.3）

原先登记构建只能通过“发布更新设置”完成，同时会改变更新推荐。现在两个动作分开：测试包可通过版本和构建校验，普通用户继续看到原推荐版本。

## 部署

将 `respect-studio-auth-1.6.3.zip` 内 `respect-studio-auth/` 的内容合并到服务器 `/www/wwwroot/respect-studio-auth/`。保留原 `.venv/`、`data/`、`.env` 和 `deploy/runtime.env`，不要先删除目录。无需更改数据库结构，也不会重置版本校验的暂停状态。

宝塔终端只复制命令，不复制终端提示符：

```bash
cd /www/wwwroot/respect-studio-auth &&
systemctl restart respect-studio-auth
```

```bash
curl --retry 5 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:8781/health
```

返回版本应为 `1.6.3`。刷新 `https://login.respect.chat/admin/`，未出现新入口时按 Ctrl+F5。如果原来由宝塔 Python 项目管理进程，在原管理入口重启，不要另外启动第二个进程。

## 测试发版

1. 打包程序时使用新的四段数字版本号，不能仅修改清单中的版本号。测试版本不低于当前最低可用版本。
2. 后台 → 客户端版本 → 切换到 **测试登记**。
3. 导入测试包随附的 `release.json` 或 `release.r2.json`，自动读取体系、版本号和构建校验码。也可手动填写这三项，必须与实际包一致。
4. 点击 **登记测试版本**。在 **构建记录** 中可查看已登记版本；原推荐和最低版本不变。此操作也不会恢复已暂停的版本校验。
5. 把安装包单独发给测试人员安装，仍需正常账号登录。无需为这个步骤填写 R2 下载地址。
6. 测试完成后，若要向所有用户发布，切换到 **正式发布**，导入上传并验证过的 `release.r2.json`，选择最低版本并点 **发布更新设置**。下载地址和校验信息可展开查看。

例如正式推荐为 `2026.10.20.2`，测试登记 `2026.10.20.3`：`.3` 可校验并登录，`.2` 用户不会收到 `.3` 更新提示。若首次还没有任何正式推荐，测试包也能使用，公开接口的 `release` 仍为 `null`。之后正式推荐超过测试版本时，测试客户端也遵循正常更新规则。

测试登记仍检查精确的构建校验码，不绕过最低版本、账号停用/到期、设备和 Key 授权。登记有效不表示客户端代码具备防破解能力。重新编译出不同构建时需增加版本号，同版本不能更换校验码。

本次只需升级服务端；现有 Studio `2026.10.20.2` 更新协议已经支持此流程，无需为新增后台入口重新安装客户端。
