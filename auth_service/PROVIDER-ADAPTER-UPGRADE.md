# 服务端 1.8.0：统一发布服务商适配器

配套客户端：**2026.10.22.2**。客户端安装包只带通用执行框架；现有 24 个服务商实现保存在独立的 `Studio-providers-2026.10.22.2.json` 中。代码包不含本机配置、Key、账号、项目和产物。

## 部署顺序

1. 备份认证数据库。把升级 ZIP 内 `respect-studio-auth/` **里面的文件**合并覆盖到 `/www/wwwroot/respect-studio-auth/`，保留 `data/`、`.venv/`、`.env` 和 `deploy/runtime.env`，不要删除原目录。
2. 宝塔终端执行下面命令（不要复制终端的 `[root@...]#` 提示符）：

```bash
cd /www/wwwroot/respect-studio-auth
.venv/bin/python -m pip install -r requirements.txt
systemctl restart respect-studio-auth
curl --retry 5 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:8781/health
```

健康检查应显示 `1.8.0`。如果由宝塔 Python 项目管理，就在该项目中重启原进程，避免重复启动。新增表自动创建，不修改现有账号、Key、R2 授权、客户端更新策略。

3. 打开 <https://login.respect.chat/admin/>，刷新页面，进入 **服务商适配包 → 导入版本**，选择随交付提供的 `Studio-providers-2026.10.22.2.json`。
4. 导入只登记；在 **版本历史**核对版本和 24 个服务商后，点击 **发布此版本**。
5. 在 Key 库维护名称、接口地址、Key 和模型绑定，再给账号勾选对应 Key。显示名称仍来自 Key 库；同一服务商多个 Key 按模型分配的逻辑保留。
6. 最后分发新客户端。已有客户端更新发布流程不变：安装包上传 R2，导入相应 `release.json` 或 `release.r2.json`，选择登记测试版或发布推荐更新。适配包发布和 EXE 更新是两个独立操作。

如果已经开启客户端版本校验，打开新安装版前，先在“Studio 客户端版本 → 登记测试版本”导入交付目录里的 `release.json`。这样可以先验证新包而不向普通用户推更。`release.json` 中的下载 URL 是占位地址；发布推荐更新前应上传安装包并使用真实 R2 下载地址。

若 Nginx 上传返回 413，请在该站点设置 `client_max_body_size 3m;` 并重载；API 自身限制适配包不超过 2 MB。

## 使用和回退

- 客户端登录、主动点击“刷新后台配置”、在线授权复查时获取包版本；版本未变不重复下载。
- 只下发账号获授权的服务商入口及其依赖。例如超模香蕉依赖超模模块，依赖不会额外显示为可调用的服务商。
- 用内存中的 Key 直接调用服务商；图片和视频不经认证服务器转发。客户端持久缓存只有代码，不含本次下发的 Key。
- 每个内容版本使用独立模块空间。已有 Provider 实例继续完成原调用；后续实例使用新代码。已提交的远端任务仍按原任务 ID 取回，不因适配包更新重新生成。
- 回退：在版本历史重新发布上一个包。客户端刷新后台配置即可领取，必要时重新登录。下载或加载失败会显示错误并阻止新任务，不会静默套用内置旧代码。管理员补齐缺失适配器、回退包后可重新刷新。
- 包在服务器验证格式和语法、存入数据库，**服务器不会执行其中的 Python**。管理员只能发布自己审查过的可信代码；这是可执行代码分发，不是脚本沙箱。HTTPS 登录会话与响应中的 SHA-256 绑定下载内容；哈希不是独立的发布者签名或防破解证明。
- 客户端必须取得在线有效授权才会加载缓存。实际执行的适配器仍在客户端内存/缓存中，不能以此隐藏真实接口地址或防止本机用户读取源码。
- 服务端升级不强迫旧 EXE 自动采用新机制；旧版仍使用其原有内置或外挂。新安装版须先完成步骤 3–4，未发布时会明确提示管理员发布。

## 以后维护代码

在 Studio 源码修改对应 `core/providers/*.py`，完成现有测试后导出新包：

```powershell
py tools/build_provider_bundle.py D:/Studio-providers-2026.10.23.1.json --version 2026.10.23.1
```

这个工具导出源码库的全部适配器，并检查明显的硬编码 Key，不读取 `config.json`。跨服务商依赖使用相对导入，如 `from .chaomo import ChaomoProvider`；通用依赖使用 `core.*`。后台当前按完整版本包发布，更新某一家时也重新导出完整包，防止漏掉其他账号仍在使用的服务商。

新适配器如果使用客户端尚未安装的 Python 库或新的通用框架接口，仍需先升级客户端；普通端点、参数、模型声明、提交/轮询/下载逻辑改动可直接发布适配包。

## 为什么要改

原登录响应只含 Key 和模型绑定，注册表从 EXE 或本地 `providers/` 加载 Python；所以改后台名称能改变显示，不能更新接口实现。现在把代码包纳入后台版本管理，客户端统一按账号同步，避免各电脑手动复制外挂后版本不一致。原账号、模型选 Key 和用量归属不改变。
