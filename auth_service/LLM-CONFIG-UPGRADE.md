# 提示词改写 LLM 配置下发（服务端 1.10.0）

原先媒体生产使用后台 Key 库，改写 LLM 却单独读取本地 `config.json → llm`。因此后台更新 Key 后，改写仍可能用旧的本地凭据。现在改写也通过账号分配获取配置，地址、模型和 Key 一起生效。

## 后台怎么配置

1. 打开管理后台 → **Key 库** → 新增 Key。
2. 服务商选择 **提示词改写 LLM（OpenAI 兼容接口）**，自定义名称。
3. 填写完整 HTTPS Base URL、API Key，并在“绑定模型”里填 **一个完整模型 ID**。Base URL 使用接口根地址，例如 `https://api.example.com`；客户端追加 `/v1/chat/completions`。
4. 保存后在账号 → **分配 Key** 勾选此条目。同一条配置可分配给多个账号。
5. 客户端重新登录，或点击 **刷新后台配置**。在设置 → **提示词改写 LLM** 查看来源、Key 名称、地址、模型与已配置状态；密钥不回显。

多条改写配置按账号分配列表顺序取第一条启用项。上移/下移决定生效项，不在调用失败时自动换 Key。每条必须明确绑定一个模型，不用图片/视频模型发现接口猜选 LLM。

也可通过 **导入 config.json** 预览并导入顶层 `llm` 中的 `base_url`、`api_key`、`model`。三项缺一会提示跳过；不使用本地供应商回退规则猜测缺失配置。预览后勾选导入，再给账号授权，导入不会自动分配。

## 客户端行为

- 配置随已有登录、生产校验和手动刷新流程下发，构建 LLM 和打开设置页只读内存，不新增联网校验。
- 后台 Key 只保存在内存中，不合并写回本地 `config.json`，也不回传到浏览器表单。接口地址和模型同时采用后台值，本地设置不能重定向后台 Key。
- 后台托管版没有分配、分配项均停用、配置不完整时明确显示不可用；不会偷偷使用旧本地 Key。个人配置版未分配改写配置时仍兼容本地设置。
- 改写轮数仍可在客户端保存，填 `0` 关闭自动改写。已配置状态不代表供应商已鉴权成功；实际调用仍可能报超时、余额或模型权限错误。
- 刷新后新建的 LLM 实例使用新配置。已经运行且创建了 LLM 实例的任务保留当时配置，不中断或重提原任务。退出登录和切账号会清空账号内存配置。
- 客户端直接请求 LLM 服务商；登录服务器负责分配配置，不承担推理或传输提示词。已有请求诊断记录 LLM 调用结果；图片/视频用量对账的统计范围不变。

## 升级

需要同时更新服务端代码和包含此次改动的客户端。单独上传媒体适配包不能修复旧 EXE 的 LLM 读取逻辑。已发布的 `2026.10.23.2` 不含本次改动；客户端重新打包发布后才生效。

服务端覆盖升级时保留 `data/`、`.venv/` 和 `deploy/runtime.env`，不要删除原安装目录。先备份数据库、停止服务，再覆盖新版代码。没有新增依赖或数据库字段，无需重建账号和 Key 库。覆盖完成后执行：

```bash
cd /www/wwwroot/respect-studio-auth
systemctl restart respect-studio-auth
systemctl status respect-studio-auth --no-pager -l
curl -s http://127.0.0.1:8781/health
```

健康检查版本应为 `1.10.0`。浏览器强制刷新管理后台后可见新选项。先更新客户端，再给正式账号分配 LLM 条目；不要把旧客户端上的本地配置误认为后台配置已经生效。

## 下发协议

保留现有 Key 库、账号排序和 `verify.provider_config` 结构，使用保留 ID `prompt_rewrite_llm`：

```json
{
  "provider_config": {
    "prompt_rewrite_llm": {
      "keys": [{
        "key_id": "key-id",
        "key_name": "提示词改写",
        "assignment_id": "revision-id",
        "base_url": "https://api.example.com",
        "api_key": "仅通过已认证配置接口下发",
        "models": ["完整模型ID"]
      }]
    }
  }
}
```

此 ID 不进入媒体适配包、图片/视频服务商列表或模型发现循环。管理接口只返回配置状态，不回显 `api_key`。
