# 漫剧老李 AIGC 全流程 Skill · V7.0

2026-09-16 用户确认规则统一版。保留39份专业资料，面向短剧/漫剧的剧本、资产、空间、分镜、提示词与验收。新版名称为v7.0老李，独立安装并保留旧版。

## 〇、项目锁与优先关系
1. 用户要求优先，其次剧情事实与已经确认的空间/交接，再选择专业表达。切镜数、单镜时长、慢镜、招式、开场、收尾均不能变成所有项目必须遵守的套路。人物表演按剧情设计，已移除固定情绪阶段与动作配方。
2. 沿用已知模型、平台、画幅、SEG总时长、音频、字幕、语言、生产范围和交付契约；用户已经提供的不重复问。模型以Seedance 2.5/2.0为主，缺关键选择时才补问，不默认降为2.0或竖屏。即梦仅用户明确要求时适配。
3. 实际接口能力按平台/模型ID/模式核实：时长、参考数量、首尾帧混用、组内多镜、原生音频。未知写待核实，不能引用旧数字当官方上限，不能擅拆用户30秒SEG或删除必要图片。
4. 区分**材料编译**与**执行生成**。前者可交planned任务，后者必须父图实存且上传就绪。交付范围和格式遵从用户：指定JSONL/纯提示词时只交对应材料；图册、情绪曲线、看板及报告按需提供，不因平台流程自动追加。内部必要记录与检查照常执行，不进入生成正文；必要资产任务和引用不能因精简交付而省略。详见asset-first-pipeline“交付范围”。

## 导演理解与表现权限
- 剧本提供剧情事实，skill可自主优化镜头、视点、信息揭示、声音及合乎人物情境的行为细节，不因原稿未写动作就停等确认。保持核心事件、人物关系、关键动机、因果与结果；涉及实质改写时遵守已有授权。具体边界见story-directed-performance。
- P1先理解本段核心冲突、观众情绪变化、信息揭示顺序、关键视觉证据及段尾观看动机，再划分SEG；区分人物情绪与观众感受。P3据此决定观众此刻看谁、镜头任务、进入退出点、动作过程或结果、表演与声音，不逐句机械配画面。细则见cinematic-dramaturgy-rules。
- 这些是内部创作判断，不是每段固定节拍或每镜必填表；不强制15秒/30秒都制造高潮、反转或悬崖。最后转写为可执行画面和声音，不把导演分析放进正文。

## 当前流程与不可遗漏的检查
- 画幅按用途分开：视频及ABC的A/B区遵守成片比例；人物4 View板16:9；场景/道具、ABC容器及C区按信息覆盖和清晰度选比例。不能将所有图片强改成视频尺寸，详见aspect-ratio-adaptation。
- P0锁定 → P1剧情/分段 → P2基础资产 → P3文字分镜/调度/母图/按需ABC → P4封装与生成 → P5分层验收，详见asset-first-pipeline。
- 人物A/B级按4 View资产板（头部特写＋无头正/侧/背全身）、10项五官＋6项服装材质记录。重要程度决定精细度，血缘关系另判；养子女、情侣、反派不因角色梯队继承主角骨相。语言遵从用户，不强制中英双份。
- 场景丰富度采用固定LOC＋按剧情变化的SCSTATE：先设计现场人员、设施和活动，再落成当前母图；连续使用继承，现场变化按需派生，持续损坏不重置，不每SEG重画。ABC和视频继承当前状态，背景群体按区域组织，详见asset-first-pipeline“固定场景底图与剧情现场状态”。
- 场景按复用与空间衔接需求建资产：一次性独立短镜且无需继承空间时可仅文字描述；重复出现或跨独立视频复用时先建同源场景；只出现一次但连续进出已有空间时仍明确连接区域。逐镜核对实际可见区域与动作路线，详见asset-first-pipeline“场景资产启用与覆盖”。
- LOC为无人建筑/地形/陈设底图；含人物的剧情空间母图属于P3状态。调度确定后确认共同母图，每个边界一次生成完整ABC，整板验收后，以同版整板为唯一图片参考分别生成A/B/C独立放大呈现图并逐图核验，禁止先分区创作再合成；C在同次生成中依共同来源呈现后段开场空间，不要求像素复制。ABC是一张三区图：A前尾、B后首（明确切镜）、C后段所属场景空间。
- 无关联天然转场免ABC，也不强制后场人物/声音钩子。有入板时B定首镜、C定所属场景开场；出板只有A定本段结尾。真实前尾核对与planned/verified按abc-handoff-board执行。
- **空间唯一来源按场景＋状态＋镜头范围判定，不按整段限制一张图。** 一段三个场景保留三套必要参考，逐图标明镜头；C不覆盖其他场景。禁止并投同状态竞争SCSTATE，也不能跨场景删图。人物/道具外观图不重定站位。
- 运镜与走位将显露的必要空间须提前由同源参考覆盖；缺失先补上游，不能让视频自行补布局。允许可行拉远显露原本在场的人物，位置与遮挡须成立；材料任务与实图就绪分层核对。
- S0～S4按空间复杂度；复杂走位/多人交叉或用户要求才用顶视图，作为上游检查，不自动成为视频额外空间权威。表演从人物当下目的、阻力与关系设计，动作、视线、呼吸、声音和听者反应按需选择，不套表情组合；面部细节只在关键区别需要时细化。见story-directed-performance。
- 动作按写实/物理/术法等剧情分支设计，不强制近身对招、肘击、11环逐招全写、首帧硬撞或终帧冻结。关键物理击按需要细化受力，纯术法不硬套拳脚。
- 台词按当前剧情作用取舍，不因双方已知、直白或重复就删除；控诉、提醒、试探、誓言和情感表达等有效作用保留。仅在已有改写权限内精简无作用的机械解释，不能强制转为眼神或潜台词；详见dialogue-doctor-7d。
- SEG是一次生成；镜头是其内部单位。P1先按目标时长检查有效内容是否自然充足及能否容纳，分段锁定后才定ABC；不足先重排相邻节拍，不靠慢推/重复反应凑时长。按实际语速档预算；同期对白动作不重复相加，不按24字硬拆镜。视频正文仅[镜头N]与事件顺序，无时间码或精确秒数，总长保留项目/API参数。
- 原生音频在视频任务生成对白/音效，声音层不等于单独后期。说话人、声音、嘴部动作对应；无字幕项目不把对白写成字幕。后期配音仅在用户选择该路线时规划。
- 镜头内画面与人声分行：每次发声绑定角色、音色及对白原文/内心独白原文，另写口型与反应、环境与动作声；只朗读原文字段中的内容，不朗读角色名、标签或说明。无人声不填“台词：无”；多人同镜按发声顺序组织，不因换人强制切镜。唯一细则与示例见model-adapters第5节。
- 材料格式、引用任务、实际文件、实际上传、视觉一致、成片直拼分层检查。只写Image N不算上传，任务存在不算已出图；缺哪张就报哪张及受影响任务，不能静默删引用。依赖执行顺序须由程序真正落实。
- 父图记录后列不作为通用引用错误；默认允许存在且无环的前向引用。仅实际执行器已确认要求按行执行时，用audit_material_refs.py的`--require-parent-first`单查行序适配；实际生成仍需父图先就绪，详见asset-first-pipeline。

## 视频唯一七段式
【画幅风格】→【参考图】→【站位声明】→【时间轴分镜】→【接续状态】→【音效】→【强制禁止项】。
原场景资产与核心人物合并进参考图，接续状态独立成段。唯一模板与完整示例见[model-adapters.md](references/model-adapters.md)第5节。所有可直接投喂示例采用该格式，内部设计片段不得原样提交。
引用按实际上传顺序写`Image N = 资源key，这张图是用途`；视频上传入板B独立图、入板C独立图、出板A独立图（按关联启用），各占一个Image编号，不上传整板，视频不上传SBSHEET故事板。不要用@锚点代替图号。无固定500字门禁，只删除重复，不截断必要信息。
图片和视频生成提示词正文均不含内部信息：分析推导、编码分级、评分、预算、审核记录、任务状态与执行说明留在内部。只输出生成需要的画面、表演、对白、声音、参考用途及连续性要求；必要的Image绑定、站位、持物和衔接状态不得误删。统一边界见model-adapters第5节“正文与内部记录的边界”。

### 非语言人声的边界
呼吸、叹息、抽泣等按剧情需要写在现有“环境与动作声”中，说明声源人物及发生动作，只生成相应声音，不朗读名称；不是新增对白。现场对白对应口型，内心独白不做说话口型；呼吸或哭泣允许自然嘴部动作。语言人声只来自已明确绑定角色的对白/内心独白原文，不新增旁白、解说或未写台词。
