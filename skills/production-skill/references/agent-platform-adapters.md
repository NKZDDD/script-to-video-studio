# 多平台 Agent 架构与国产工作流适配规范 (Multi-Agent Platform Adapters)

本规范专为解决不同 Agent 运行平台（如 **OpenClaw**、**WorkBuddy**、**豆包智能体 / 扣子 Coze**、**Dify**）在交互协议、状态机、文件挂载与上下文长度等方面的差异，提供全平台无缝兼容方案。

---

## 一、 平台差异与核心适配机制

```text
               ┌──> OpenClaw (命令行 / Tool-Call / 完整 Skill 目录挂载)
               ├──> WorkBuddy (卡片式 Action Card / 侧边栏产出册 / 会话状态机)
[导演 Skill 总控] ├──> 豆包智能体 / 扣子 Coze (节点式工作流 / 插件输入输出 / JSON 契约)
               └──> Dify / 通用 LLM (单文件 Prompt 模式 / 标准 Markdown 输出)
```

---

## 二、 平台专属适配规范

所有平台先区分材料编译/执行生成；下述实图与尾帧门禁只在实际生成适用，材料任务标planned。结构示意字段不冒充外部既有契约。
所有平台遵从asset-first-pipeline“交付范围”：阶段产出可为内部记录或所选契约中的合法任务，不代表额外文件。只交用户所需内容；图册、曲线、看板、报告与独立API载荷按需提供。平台不能通过固定阶段清单强制扩充资产、文件或生产范围。

### 1. WorkBuddy 平台专属适配
- **会话状态机驱动（P1 ~ P4 阶段流转）**：
  - `P0 立项锁定阶段`：锁定画幅（16:9/9:16）、风格预设、平台模型、目标时长（见 `aspect-ratio-adaptation.md`）；
  - `P1 剧本门控阶段`：分析剧本前提与实际节拍，明确核心冲突、观众情绪、揭示顺序、视觉证据与段尾观看动机，按dialogue-speed-check检查每段有效内容自然充足且不过载，先定分割点再定ABC，保存必要内部记录；仅用户所需交付包含图册或情绪曲线时生成相应文件，曲线使用真实项目数据；
  - `P2 数字资产包阶段`（本 skill 核心）：
    - P2a 识别生产范围内所需CHR/SCN/PRP/AUD实体及已知复用关系，按asset-first-pipeline判定必要资产，不因提取到实体就一律出图；
    - P2b 内部核对资产完整性（适用角色的10项五官＋6项服装材质＋独立血缘关系），按所选交付格式承载必要内容，已有授权不重复确认；
    - P2c 材料模式编译必要图片任务及依赖；执行模式按依赖分批生成所需角色、场景和道具图并核验，用户要求逐批确认时才停等；
    - P2d 仅请求图册时交付图册；内部记录必要资产、引用与状态，已生成才附真实图片，材料模式不伪造实图。@短锚点仅供内部索引；
  - `P3 空间调度与分镜阶段`：按导演判断编译文字分镜，确定视觉中心、镜头任务和进出点，人物表演从剧情设计；复杂走位/多人交叉或用户要求时才增加上游顶视图；逐镜检查必要参考的覆盖与绑定，不强制每镜新增资产图。按asset-first-pipeline将现场人员、设施与活动落成当前SCSTATE，并核对复用及持续变化；先写SEG文字时间轴，判定边界关联，有关联再联合设计单图三区ABC，无关联天然转场免板（见 `abc-handoff-board.md`）；视频按Image N绑定实际必要参考；
  - `P4 批量投喂与成片阶段`：按所选契约封装提示词与引用（只绑定按需入板B/C、出板A独立图及必要资产，整板验收后才参考生图派生三区，无SBSHEET）；材料模式到此交付材料，不自动执行生成或追加API文件。执行模式组装真实请求，有关联边界先核对前段实际尾帧与入板A，再生成后段，不能把有依赖的任务无条件并行；
  - `P5 质检与交付阶段`：P0/P1/P2 门禁 + 资产一致性检查（脸型/服装与资产图一致；画幅按视频、各资产及ABC区内各自配置验收）+ 启用ABC边界的端点核对与原段直拼实测；无成片不宣称衔接通过。
- **文件交互与侧边栏渲染**：
  - 仅为已选交付物命名；`剧组_资产图册.md`、`剧组_全片情绪曲线_v1.png`等是可选文件名示例，不是每次必交清单；
  - 支持 WorkBuddy 在线预览、一键复制与本地 Download 自动归档。

### 2. 豆包智能体 / 扣子 (Coze) 工作流专属适配
- **节点化入参与出参契约（Node Payload Contract）**：
  - 仅需要该工作流节点载荷时按实际接口映射；已有用户指定JSONL等契约时优先遵从，不追加另一份JSON或把内部字段塞入导入材料。以下仅为节点结构示意，内部语速检查不得进入positive_prompt：
    ```json
    {
      "episode_id": "EP01",
      "shot_index": "U01",
      "duration": "<项目SEG总时长，映射为接口要求类型>",
      "model": "<已锁定平台模型ID>",
      "positive_prompt": "<model-adapters第5节完整七段式>",
      "negative_prompt": "blurry, low quality, distorted",
      "character_ids": ["CHR-楚灵风-战损", "CHR-厉绝-幽冥"],
      "camera_id": "CAM1",
      "speech_speed_check": {
        "word_count": 0,
        "status": "待核算"
      }
    }
    ```
- **上下文分块与长文本流式防护（Chunking Protocol）**：
  - 遇到长篇剧本时，自动启用分集分块处理（Chunking），根据实际通道容量保序分块，不能截断必要材料或把分块上限当提示词字数门禁，避免豆包对话上下文截断。

### 3. OpenClaw 平台适配
- **标准 Skill 规范**：完整保留 `SKILL.md`、`references/` 规则库与 `scripts/` 校验脚本；
- **部署路径**：使用当前独立v7.0老李目录；命令与路由按实际平台能力映射并核实，不从历史short-drama-director名称推断当前安装命令，不覆盖保留的旧版。

### 4. Dify / FastGPT / 通用大模型适配
- **免依赖单文件 Prompt 模式**：
  - 用户明确要求导出独立Prompt时，读取并整合本任务必需的references规则，去除内部路径依赖后检查完整性。仅复制SKILL.md不会自动内嵌引用文件；未完成整合不得宣称可独立运行。

## 三、 全平台通用指令路由一览

无论在哪个 Agent 平台，以下指令均可统一触发：
- `/写剧本` / `初始化项目`：启动门控编剧与台账初始化
- `/剧组产出册`：按用户指定格式输出台账；未指定格式时可选Markdown，兼容WorkBuddy挂载，不额外强制看板或曲线
- `/情绪曲线`：按指定范围输出实际剧情节拍张力分析，数量不固定；绘图必须使用实际数据，示例显式标记
- `/顶视图`：输出机位调度与 180° 轴线方案
- `/生成视频提示词`：输出 Seedance 2.5 / 2.0 / 即梦解耦提示词
- `/导出工作流参数`：输出豆包工作流 / API 标准 JSON 载荷
