# 模型适配、参考图封装与唯一视频模板

## 〇、项目锁与能力记录
- 沿用用户已经确定的模型、平台、画幅、SEG时长、音频、字幕及交付要求，不重复询问。缺模型或画幅且确实影响当前生产时才补问，不能静默默认2.0或9:16。
- 本包主路线为Seedance 2.5 / 2.0；即梦仅用户明确指定时适配。
- 模型名称不等于接口能力。记录实际平台、模型ID、任务模式，以及单次时长、参考数量、首尾帧混用、组内多镜、原生音频的已核实能力与来源。未知写待核实，不能把旧示例的30图、4～30秒等数字当通用官方上限。
- 用户锁定30秒时按30秒编译、预算、验收；实际接口若不支持，明确报告冲突与可选方案，不擅拆SEG、不删参考、不切换模型。创作材料可先完成，实际提交等待能力核实。
- 音效括号等是本包提示词组织约定，不宣称为跨平台通用API语法。服务商字段和值以实际已核实接口为准。
- 交付遵循用户指定的内容与格式：JSONL契约/纯提示词/图册/曲线/看板等；未指定格式时只为所需产物选择适当形式，不自动追加MD、HTML、PNG或报告。必要内部记录与检查照常执行，详见asset-first-pipeline“交付范围”。

画幅按aspect-ratio-adaptation分项管理：视频用成片比例，图片请求用整张资产或ABC容器的比例；A/B区内用成片比例，C以空间完整为先。不同用途允许不同尺寸，禁止将整板当视频首帧整体裁切；实际接口若裁掉必要信息需先适配。

## 一、任务模式与素材权限
默认推荐全能参考路线；用户已选择则沿用。
- **全能参考**：按需入板B独立图＋入板C独立图＋出板A独立图＋必要场景/人物/道具图，整板不上传视频，每张实际图片占一个Image编号。参考数量取实际平台能力；未知不写虚假已满足。
- **首尾帧路线**：使用按剧情设计的起止画面；不能将整张ABC或角色4 View板当first_frame。是否允许额外角色参考、仅首帧、双帧等，按实际接口确认。接口互斥时，角色板用于上游造帧，不进入视频请求。
- **视频编辑**：按用户明确请求及接口能力单独封装，不自动混入生成任务。
- 用户选择ABC全能参考流程时，“开头/结尾”只描述镜头，不能据此偷偷切为首尾帧API。
- 不固定首帧为全身近景；景别、构图、慢镜与收尾由用户要求、剧情、已确认空间和交接决定。

## 二、时长与音频
SEG是一次生成的视频；镜头是SEG内部镜头。总时长由项目参数和实际请求承载，不能用生成最短时长限制每个镜头。
- 镜头数量、切镜频率、停顿、慢镜、对招均不固定。段内多镜是否可执行需核实，不能用“所有模型只能连续运镜”的旧假设改写剧情。
- P1按dialogue-speed-check先核算有效内容能否自然覆盖SEG，再定段界与ABC。内部核算对白、动作与停顿，同期发生的对白和动作不简单相加；按选定语速档和表演核算，不按固定字数硬拆镜。
- 原生音频：对白、音效随视频任务生成，声音层表示信息组织，不表示另做配音；保持说话人、嘴部动作与声音一致。
- 用户选择后期配音时才规划独立声音任务；实际接口不支持用户选择时报告冲突，不能静默改模式。
- 无字幕项目不输出屏幕对白文字。镜头内将画面、发声角色、对白原文、口型与反应、环境与动作声分行写；内心声用内心独白原文。具体格式见第5节，不再用角色名加大括号与尖括号音效混写。这些是文字组织约定，不是平台专用语法或防误读保证；实际成片仍须试听核对。

## 三、参考图绑定与空间
唯一绑定写法：`Image N = 资源key，这张图是用途`。按实际上传顺序连续编号，同一图片去重；角色身份与场景镜头范围明确。
- 先判断边界是否需要关联承接，无关联天然转场不生产ABC，也不强制预埋后段人物、道具或声音。
- 入板B定首镜，C定所属场景的开场空间；出板仅A定本段末镜。C不是第三镜，也不冻结后续动作。
- 同一场景、状态、镜头范围一个空间控制来源；有入板C不重复投同状态完整SCSTATE。ABC引用共同母图与必要资产，一次生成三区；C表达后段空间，A/B表达交接取景，整板验收后以同版整板为唯一图片参考生成独立A/B/C并对原区核验，不先分区创作再合成，详见 `abc-handoff-board.md` §1.1。
- **多场景保留各自必要参考**，逐图标明适用镜头。三个场景可以有三张对应空间图，不跨场景删图；角色、道具图仅控制身份外观。分屏按区域区分来源。
- 当前场景/状态/镜头范围未被入板C覆盖且需要参考时使用对应场景开场母图；无人镜头可用LOC。按asset-first-pipeline场景启用规则，符合一次性独立短镜豁免时可仅文字描述，不伪造图片绑定；重复使用或连续连接空间仍须有足够覆盖。必要建筑细节补图必须与主空间一致，不能以“只管材质”掩盖结构矛盾。
- 视频不上传SBSHEET故事板；`@CHR/@SCN/@PRP`仅作内部台账锚点，不代替Image绑定。
- 材料编译核对每张图有对应生产任务和版本；执行生成核对实际父图；提交时核对请求确实携带素材。仅写Image N不算上传。

现场丰富度继承asset-first-pipeline定义的当前SCSTATE。背景人员、设施、物件和活动区域先在母图中成立，视频只安排可达活动与状态演进；特写不要求全员入画，切回全景不无因丢人。新时刻或事件不照搬旧群众与布置，持续损坏和遗留物不得自动恢复；必要新增配置先补上游。

## 四、站位与镜头
站位声明写清实际到场角色的位置、朝向、持物与需要的轴线。复杂度按S等级，单人不强写双人轴线。
- 逐场标明镜头范围；画面左右是投影，不等于世界坐标。人物移动须有动作原因与路径，不能为了取景挪动建筑/车辆。
- 视频提交前检查整条运镜和人物移动将显露的必要空间是否已由实际同源参考覆盖；缺失先补上游，不用“保持一致”代替空间依据。允许拉远显露原本在场人物，不能凭空补人或搬动地标。
- 简单对话不强制位移，合法越轴须有可理解的镜头过渡。顶视图仅在复杂走位、多人交叉或用户要求时用于上游检查，不自动追加为竞争空间参考。
- 首镜服从入板B，末镜服从出板A；无板时按剧情。不得用固定开场、爆点定格或黑场覆盖交接。

## 五、唯一投喂主格式：七段式
**2026-09-16用户确认的新格式**：`【画幅风格】→【参考图】→【站位声明】→【时间轴分镜】→【接续状态】→【音效】→【强制禁止项】`。
原【场景资产】与【核心人物】统一收入【参考图】；【接续状态】独立成段。七段式是唯一名称，禁用“八段式/六栏/九栏”等旧别名。所有可直接投喂示例按本节；内部设计资料不得原样提交。

- 镜头采用分行块：`[镜头N]`后依次写`画面：`、按实际发声填写的`发声角色：`与`对白原文：`或`内心独白原文：`、`口型与反应：`、`环境与动作声：`。原文使用中文双引号，只放实际要说的内容；表演要求、角色名、语气、审核说明不得夹进引号。
- 无对白或内心独白的镜头省略发声角色及对白/内心独白原文字段，不填“台词：无”、空引号或占位台词。口型与反应、环境与动作声按实际需要写，不为填字段增加动作或声音。
- 每次发声独立绑定角色、当前音色和发声方式。多人同镜轮流说话时，按事件顺序重复“发声角色→原文→口型与反应”块；不把多人的原文合在一个字段，不因换说话人强制切镜。音色按已锁角色及年龄状态保持一致。
- 现场对白与口型对应；内心独白明确角色且画内不做说话口型，画外现场对白说明声源及人在画外。仅写当前需要的发声角色，不把未出现角色的声音清单塞进每段。默认轮流对白完整落口；剧情需要抢话、重叠或合说时明确参与者、各自原文及事件关系，不强制所有项目互不重叠。
- 【音效】设置人声范围：仅将已列出的对白原文与内心独白原文字段中引号内的内容生成语言人声，由对应角色说出。角色名、字段名称、画面、参考图、动作及音效名称不朗读；不增加未列出的语言人声。环境与动作声生成实际非语言声音。配乐需求另作自然语言描述，不与对白混写。
- “时间轴”表示事件先后；不写镜头时间码、秒数、精确完成时点。总SEG时长、语速预算与实际尾帧时点仅在项目/API参数、内部QC中记录。
- AU编号、内部强度码、English kernel不入视频正文；按story-directed-performance设计实际行为，面部细节仅在镜头需要时描述，不调用情绪配方。
- 不固定镜头数、机位、动作套路或声音电平。负面项按用户需求和具体风险设置，不把无关题材禁令搬到所有项目。
- 防意外分身与人数错误按当前镜头、区域及剧情状态表达，不强制固定长句或整段固定人数；合法分屏、倒影、回忆及剧情分身另明范围。表情幅度与起落依剧情，不设百分比上限、不强制跟随台词结束；对白完整性另查声音与口型。
- 提示词不设500字等固定长度门禁，不截断必要信息；实际接口返回限制时再针对处理。
- 不使用末尾【参数契约】、ASCII站位图、`跟随@谁`或未上传图的假绑定。

### 正文与内部记录的边界（图片、视频通用）
- 所有内部信息均不进入生成提示词正文：分析与推导过程、方案比较、情绪评分、AU/强度等内部编码、角色或空间或动作的内部等级、English kernel、时长与语速预算、QC检查与结论、planned/verified状态、缺项报告、任务调度、文件核查与上传操作说明。语言为中文或英文时均适用，无全英文例外。
- 将内部设计转为可执行的画面和声音描述。人物目的、观众情绪、镜头任务及方案比较只用于内部决策，正文写本场最终选定的行为、视线和声音，不能把内部情绪标签机械替换成固定动作。自然英文表演描述可按用户语言要求使用，但不携带kernel标题、配方代码或内部注释。
- 保留生成所需的模型/媒介/画幅/风格、Image N与真实资源key及用途、镜头范围、人物身份与外观、空间位置、持物、动作、表演、对白、声音、起止状态和区域权限。这些是生成指令，不是内部分析；不能以清理正文为由删掉一致性依据。
- 接续状态只写画面与声音如何结束、如何承接；“生成后核对”“素材待上传”“检查通过”等执行或审核说明留在内部。ABC的A/B/C区域定义和必要板面标签属于图像设计，可按其模板保留。
- 内部记录与提示词字段分开保存，不附在正文末尾，不藏进括号、注释或负面提示词。外部契约必需的结构化字段照常保留；不为存内部记录擅增导入字段或说明行。仅当用户要求说明/审核报告时另行提供，不混入可复制投喂正文。

### 5.1 完整示例（占位资源，交付前必须换为实际任务/文件）
本例只展示七段式及引用、发声格式，不提供可套用的表演模板。人物行为须依据实际项目重新设计，本例不代表所有项目的镜头数、画风或时长。

【画幅风格】

Image 5 = PRJ__CHAR__JIANGYUNYAO_R01，这张图是姜云窈当前身份与服装参考，不改变空间站位。
【站位声明】
午门：温明澜跪在左侧，姜云窈站在右侧，位置、距离与朝向依据Image 2，首镜取景依据Image 1；后续动作保持已建立的轴线。
【时间轴分镜】
[镜头1]
画面：中近景，温明澜左前侧缓慢推近。从Image 1的单幅构图与动作状态开始，温明澜手掌压住湿石，抬眼看向姜云窈，说到最后压住哭腔。

口型与反应：仅姜云窈开口，说完闭口；温明澜听着，没有接话。
环境与动作声：衣袖拂动声。
【接续状态】

【音效】
对白清晰居前，火把与衣料声不遮盖人声；环境声按交接设计连续。
本段轮流对白，上一句完整结束再开始下一句。仅将对白原文及内心独白原文字段中引号内的内容生成语言人声，由对应发声角色说出，保持各自音色，不交换台词。角色名、字段名称、画面、参考图与动作说明均不朗读。环境与动作声只生成相应声音，不读出声音名称。不添加未列出的旁白、解说或对白。
【强制禁止项】

### 5.2 多人同镜与内心声格式片段（须放入完整七段式）
以下台词仅为格式演示，不替换项目原稿，不规定镜头数量或SEG时长。同镜内每个发声块各自绑定角色；不将本片段单独当完整投喂稿。

## 六、实际提交：正文、文件与载荷一一对应
提交时确认整段画面提示词进入实际平台的画面/视频提示词输入；若平台存在且已核实独立台词/配音字段，只按其真实接口承载对应人声原文，不把整段七段式塞进朗读字段，不凭本skill字段名臆造API参数。仍沿用用户选择的原生音频路线。未实际试听时不声称已解决模型误读。
以下为**接口结构示意**，字段须由实际服务商文档核实；不能当作已验证的官方请求直接发送。Image 1必须对应第一张真正上传的图像。所有占位值提交前替换并验证。
```json
{
  "model": "<已核实的平台模型ID>",
  "content": [
    {"type": "text", "text": "<完整七段式正文，含Image 1的资源绑定>"},
    {"type": "image_url", "image_url": {"url": "<已上传且服务端可访问的实际图像地址>"}, "role": "reference_image"}
  ],
  "duration": "<项目锁定SEG秒数，按接口要求转为正确类型>",
  "ratio": "<项目锁定画幅，按接口要求映射字段>",
  "generate_audio": "<按音频模式映射为接口支持的值>"
}
```
- 本地文件存在不等于服务端可读；上传失败应报缺失素材，不删除Image行后照常生成。
- 每条记录对应：资源key/版本→可读文件→上传素材标识→实际请求中的位置→正文Image编号。
- 提交前比较完整清单及用途。参考容量不足、模式互斥、模型能力未知时明确阻断实际提交并报告，不改用户方案。
- 实际请求缺图不能靠提示词补救。脚本文件检查与请求清单检查分开报告，详见 `quality-gate-review.md`。
- 真人素材、内容限制及其他服务商要求按当前平台核实；本项目2.5D角色按用户设定生成，不能把未核实的旧“官方红线”推广到所有平台。

🗄️ **LEGACY·可灵**：不属于本包当前支持路线，历史能力不作为当前契约。

### 非语言人声的边界
呼吸、叹息、抽泣等按剧情需要写在现有“环境与动作声”中，说明声源人物及发生动作，只生成相应声音，不朗读名称；不是新增对白。现场对白对应口型，内心独白不做说话口型；呼吸或哭泣允许自然嘴部动作。语言人声只来自已明确绑定角色的对白/内心独白原文，不新增旁白、解说或未写台词。
