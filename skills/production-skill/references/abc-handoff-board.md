# ABC 单图三区交接板（段间直连权威规则）

## 1. 目的与边界

让需要关联承接的相邻独立生成视频按原始段顺序直接拼接，拼接点呈现明确、连续的切镜，不依赖人工裁切、补帧、叠化、变速或音频修补。本文件只替换段间交接及视频参考图来源逻辑；剧本、美术、模型选择、段时长、角色资产规格和七段式正文结构继续按原规则及用户锁定执行。

ABC母板是**一次生成的一张图片内三个区域**，不是分别创作三幅后拼合，也不是本段“开场—中段—结尾”。验收母板后再以它为参考生成独立区域图供视频使用：
- **A区＝前段结尾**：记录前段最后可见画面及动作相位。
- **B区＝后段开头**：后段从此开始；针对A调整景别、机位或构图，形成明确切镜，并承接事件、视线与动作进度。
- **C区＝后段整体空间继承**：呈现后段开场时的整体空间与关系，供后段后续镜头继承。它不是第三个时间点、第三个镜头或后段尾帧。
A→B的切镜发生在两个视频文件的拼接处，禁止在后段重播A、把A变形成B、拍摄整张板或依次播放A/B/C。

视频文字分镜按 `[镜头N]` 顺序描述，不输出镜头起止时间码、秒数或精确完成时点。ABC的首尾状态通过动作事件对应；实际视频尾帧时间点仍属于内部来源记录。

## 1.1 唯一空间来源（2026-09-16 · 本文件空间权威）

本文实图存在、整板一致性及实际尾帧核对门禁用于执行生成。仅编译材料时先交planned母图/ABC任务与依赖，缺实图明确待生产，不阻止完整材料规划，也不能声称图像或视频验收已通过。

**同一场景、同一剧情状态、同一镜头作用范围只指定一个空间控制来源。不同场景分别指定来源，整段视频不限制为一张场景参考图。** 不把“多张参考都写保持一致”当作空间已经一致。

### 一段包含多个场景时
- 必须保留各场景所需参考，不能因为“单一来源”删除其他场景图。先登记“镜头范围→场景/状态→空间来源”，再仅对同一作用范围内重复、冲突的控制图处理。
- 例如同一SEG依次出现午门、漠北、侯府：`Image 1 = <入板B独立图key>`控制午门首镜；`Image 2 = <入板C独立图key>`控制午门[镜头1]至[镜头2]空间；`Image 3 = <漠北空间图key>`用于[镜头3]；`Image 4 = <侯府空间图key>`用于[镜头4]至[镜头5]。三份必要空间参考均保留，角色/道具另按需连续编号。不使用镜头秒数标范围。
- 没有入板时，三个场景可以分别使用三张经确认的场景/空间状态图；无人环境镜头可用LOC。某场ABC的C不能控制其他场景，也不能据此删除其他场景的母图。分屏同时出现多场景时，按画面区域分别指定来源。
- 返回同一场景时复用相应来源和合法状态版本，不默认重置人物；参考数量超过实际接口容量时报告容量问题并讨论生产方案，不静默删掉必要场景图。

### 一次生成整板与共同来源
- LOC是无人场景底图，提供建筑、地形和固定结构；人物/道具资产提供身份、服饰、外形。P3在文字分镜与调度已确定后，由这些基础资产形成一张经过确认的空间母图，统一人物位置、朝向、距离、牵手/持物、道具摆放、遮挡、通路与光源。空间母图不是另一个独立想象的场景。
- 空间母图按场景和剧情状态版本登记。已有合格SCSTATE可以承担该角色，不为同一状态重复出图；已验收C区可作为空间核对证据记录，注明所属整板key/版本与区域；它供视频继承及验收核对，不作为新整板或新母图的图片上游。后续整板仍从共同基础资产和当前合格SCSTATE生成，避免区域图逐板传递偏差。C独立图在整板之后参考生成并核验，整板不能直接或间接依赖任何区域派生图，未生成时不伪装实图。具体图片文件及其可追溯来源必须存在，文字站位记录不能冒充已确认的空间母图。
- **一个交接边界先安排一个ABC整板生成任务**：A、B、C在同一次生成中共同完成。整板验收后，再以同版整板为唯一图片参考，分别调用图像模型生成A、B、C独立呈现图，并对照母板对应区域验收。每边界形成一张整板和三张区域派生图；禁止先独立设计三区再合成整板。该派生通过参考生图实现，不采用人工或程序裁切，不把区域派生冒充整板同次调用。人物、场景、道具与按需母图仍为共同上游资产。
- C依据共同空间母图及后段开场状态，在本次整板生成中呈现完整空间关系；要求结构、站位、持物、光向一致，不要求或宣称像素级复制母图。A/B是同次生成中的交接取景，不单独裁切出图后再喂给ABC生成器。
- 一次请求同时提供共同母图、必要人物/造型/道具参考及明确的三区说明；参考逐项绑定Image N，说明母图管空间、外观资产管身份。后续ABC继续绑定同源空间资产和已发生的合法状态变化，不逐板重新布置场景。
- 明确三区的世界位置、朝向、距离、左右手/持物、固定地标、光源和可通行区域。A/B换景别或机位时可改变画面投影左右，但不能移动人物/建筑/车辆迁就构图。未覆盖的新区域先补足同源上游空间；不仅检查A/B端点，也检查后段拉远、跟拍、过门等沿途将显露的必要区域。C或按需同源补图须足够支撑这些镜头，不能让视频自行推测布局。同次生成不是空间正确的证据。
- A→B可通过足够明显的景别差形成切镜，不强制过肩镜头或反打；保留用户要求的明确切镜，避免只有轻微缩放的跳切。空间不允许的机位应调整镜头设计，不能移动建筑/人物来迁就构图。
- 同场连续边界的A/B/C来自同一空间状态，动作相位按交接进度继承；若A使用前段真实尾帧，则先核对尾帧与空间母图。可兼容偏差登记新状态版本，必要时统一重生成整板并核对三区，不兼容则回修有关段。不能为了适配C篡改真实尾帧。合法换场时A依据前场，B/C依据后场，不强迫两场共用空间母图。

当前共同母图须按asset-first-pipeline建立完整现场：主要人物、背景群体、临时设施、通路及当前状态。同场A/B/C继承相同现场，不为近景或切镜删掉画外群体；换时换场按各自状态，不能携带不该在新场出现的旧人员和布置。丰富度按剧情，不要求每区都画满人。

### 视频中谁控制空间

下表中的入板B、入板C、出板A，均指以对应整板为参考生成并核验的独立区域图。整板本身留在上游，不作为视频参考；A/B只控制端点画面，C控制所属场景开场空间。
| 情况 | 当前时间窗的空间控制来源 | 其他图的权限 |
|---|---|---|
| 有入板 | 入板B定首镜、入板C定开场空间状态 | 不再并投相同状态的完整SCSTATE/空间母图；角色、道具只补身份/服饰/外形 |
| 无入板或无ABC | 需要空间参考时使用经确认的本场开场母图；无人镜头可用LOC；符合asset-first-pipeline一次性独立场景豁免时可仅文字 | 不伪造入板，不同时上传第二张独立站位图；无ABC不等于可忽略连续空间 |
| 只有出板 | 当前范围需要空间参考时以本场开场母图控制开场；独立短镜豁免仍按场景规则；出板A仅控制结束时刻 | 出板B/C属于下一段，不能反向改写本段空间 |
| 同时有入板与出板 | 入板C→文字动作与位移→出板A | 两者对应不同时刻，必须同源可达；出板C不能成为本段第二个控制源 |
| SEG内部合法换场 | 按镜头范围分别指定各场唯一来源 | 不把不同场景/时刻误当竞争，也不把前场来源延伸到后场 |

- 无人LOC主要用于上游母图制作；视频只有在补充必要且不冲突的建筑细节时才额外引用。它不得重定布局或人物位置，完全重复则不上传；实际结构矛盾不能靠“仅管材质”掩盖，须先修图或移除该补图。
- 角色/道具图中的白底、站姿、展示视角不得改写C的站位、持物或物体摆放。每张补图都说明身份与作用，避免笼统的“锁定空间”。
- C锁定开场状态，不冻结整段人物。之后由文字分镜明确动作和位移，登记新的结束状态；下一交接边的C采用后段实际开场状态，不把人物重置回旧C。
- 图板版本或镜头调整后，同时复核两端视频镜头文字、参考清单、站位、接续状态、来源版本。B改为侧向多人画面时，旧“过肩开场”文字必须同步去掉；A换取景时同理。

### 放行条件
先确认每边界仅一个整板生成任务且所有必要父参考齐全。逐区检查A能否在C空间成立、B能否在C空间成立、A→B事件和动作是否连续；合法换场时A按前场核对，B/C按后场核对。核对脸、服装、牵手、持物、门窗、车位、脚下落点、遮挡、光向与通路，三区细节必须足够辨认。多个ABC还须核对共同建筑和中间段状态演进，不能只验单板。
发现一区不一致时依据同一来源统一修订整板，复核所有区域及两端引用；不回退到分区出图再合成，也不把“同次生成”标为自动通过。已有经核对一致的旧板可以继续作为派生母板，不仅因旧制作方式而强制重做。派生图若偏离母板，只以原已验收整板重新派生对应区域；不把偏离图继续当父图迭代。若母板本身需修改，则升版并重新派生全部三区、复核两端引用。
能指出A/B机位在母空间中的关系；背景投影与遮挡可解释；无偷偷移人/移车/移门；A/B与C身份、状态、光向一致；视频同一时间窗无第二空间控制来源；所有源图实存。任何不符先修复，不把矛盾图一同交给视频模型裁决。图板验收通过仍不等于成片直拼通过。

## 2. 关联判定与上游来源

先对每个相邻边界判断是否有需要继承的动作、对话、视线、人物/道具状态或整体空间，登记 `use_abc=true/false` 及一句原因：
- **有关联且需要承接**：制作ABC交接板。
- **无关联、天然转场**：`use_abc=false`，不制作、不引用ABC；两段各按本段资产与文字时间轴生成，不强行匹配机位、人物或空间。没有ABC不视为缺项。
- 不只凭场景名判断：换场仍可能有同一动作/道具或叙事承接；同场也可能是明确的时间跳跃。以剧情实际关系及用户决定为准。天然转场无需视觉状态继承，但仍检查对白是否完整、边界是否有意外黑帧和杂音。

1. P1/P2：按dialogue-speed-check同时检查每段有效内容能否自然覆盖时长以及是否超载，先确定节拍与分割点，再登记并锁定必要资产；普通分镜设计保留。
2. P3：沿用P1已核算的SEG分段，先写动态文字时间轴并复核自然充足性，再为需要关联承接的相邻SEG联合设计交接点；无关联边界只登记自然转场。先定前段末镜和后段首镜的叙事关系，再定机位；不得先生成ABC图再反推剧情。
3. 同场承接：锁定人物身份/服装、真实位置、朝向、视线、左右手、持物、动作相位、门窗/地标、光源。B必须有能看出的切镜变化（如近景→过肩中景），不能仅微缩放形成跳切。遵守180°轴线；镜头变动可以改变投影位置，不得让真实空间发生无因变化。
4. 换场/时间跳跃：只在剧情明确需要时采用蒙太奇。A属于前场，B和C属于后场；C不强行继承前场布局，记录合法变化及持续的人物/道具状态。普通同场对白优先连贯切镜，不默认制造时空跳跃。
5. 声音按同一交接点安排：句子/音节和关键动作声不切断、不重复；默认完整对白落在单段内。环境声、音量、音乐相位应可直接接续；难以保证音乐连续时，在规划中选择适合自然停顿的边界或无配乐方案，不把混音补救留给人工。
6. 根据文字交接记录与基础资产确认共同空间母图，以单个任务一次生成包含A/B/C的完整交接板，再按§1.1核对三区与共同来源。整板通过后按§4.1派生并核验独立A/B/C图；视频参考只包含对应入板B/C、出板A独立图与必要补充资产；入板C已承担空间时，不再并投相同状态的SCSTATE母图。**故事板图不再是必需产物，不上传SBSHEET故事板图**。镜头序列由文字分镜承担。

## 3. 台账与来源

每条交接记录至少登记：
| 字段 | 含义 |
|---|---|
| boundary_id / from_seg / to_seg | 唯一交接边及两端SEG，例如 EP01_SEG01_TO_SEG02 |
| use_abc / reason | 是否需要ABC及关联/天然转场的判定原因；无关联时后续板字段不适用 |
| board_key / revision / image_path | 一张ABC图的资源key、版本与实际文件；示例 PRJ_HOUFU__ABC_EP01_SEG01_TO_SEG02_R01 |
| status | planned（规划）或 verified（与实际尾帧核对）；只有提示词没有图片时写待出图 |
| a_source | 前段末镜计划；有成片后记录完整视频文件、实际最后帧时间点及尾帧文件；尾部若有黑帧或无效画面则验收失败，不能跳过尾部选一帧后声称无需裁切 |
| A / B / C | A终态；B首态与切镜变化；C后段空间关系及来源资产 |

| region_derivation | 每区独立key、region=A/B/C、确切parent board_key/版本、参考生图任务、实际文件、与原区对照结果；三区同版 |

## 4. 交接板出图模板

一张参考板，上排A/B两个独立成片构图窗，下排C整体空间窗；A/B按项目成片画幅构图，C按足够交代空间的广角构图。整板容器比例按排版与清晰度选择，不必与成片相同；A/B各自遵守成片比例，C按完整空间覆盖选择比例，不为凑比例裁掉地标、站位或路径。三区不同画幅仍在同次生成内完成。A/B/C小标签与必要说明放边框，不进入镜头图像。不得把确认案例中的午门、人物、16:9和配色固定到其他项目。

模板只承载图像生成需要的信息。整板key、交接边、来源追溯、planned/verified、文件就绪、整板单次调用、验收后区域派生及依赖执行规则在任务结构及内部台账中管理，不抄入提示词；参考绑定按实际输入展开，占位说明在交付前替换。有实际尾帧输入时为它分配Image编号，并说明仅供A区状态参考。其余边界遵从model-adapters第5节。

```text
生成一张完整ABC交接板：上排A/B两个独立画面，下排C整体空间窗。小标签置于边框，不进入镜头图像。
输入参考：<逐行展开Image N = 资源key，这张图是共同空间/人物身份与服装/道具外观等实际用途，注明所属场景和区域范围>。
共同空间事实：<固定地标、人物世界位置/距离/朝向、左右手与持物、车辆位置、遮挡、光源方向、动作通道>。三区共同遵守；只改变取景，不为构图搬动物体。
视觉：<项目锁定媒介、画风、色调、光源>；整板容器画幅=<按排版清晰度选择的比例>；A/B各自构图画幅=<成片画幅>；C区画幅=<完整展示空间的比例>，不拉伸，不误裁关键区域。
A区｜前段结尾：<人物状态、动作相位、视线、持物、景别、机位、构图；若有实际尾帧输入则明确其Image编号及状态用途>。
B区｜后段开头：<承接A的剧情状态>；改为<明确不同的景别/机位/构图>；<轴线与视线匹配>。不重播已经完成的动作。
C区｜后段空间继承：依据<共同空间参考的Image编号>和<后段开场状态>呈现空间总览。<后段开场整体空间、人物真实站位与朝向、道具位置、地标/出入口、光源、后续运动可用区域>。同场时与A/B同源；换场时与B同属后场。
A/B是交接两端画面，C只是空间参考。相同实体保持身份和未声明变化的外观/状态一致；<如有换场或时间跳跃，明确实际空间与状态变化>，B/C空间必须一致；不画第四格、不把C画成后续剧情。各区的人脸、手部、持物与关键地标保持可辨，不因分区过小丢失衔接信息。
```

已生成前段时，以实际尾帧的面部、持物、动作与背景事实核对A；A仍属整板生成结果，不能把它冒充提取的实际尾帧，也不能只替换A而免验其余区域。图版文字与边框只属于参考板。

## 4.1 以整板为参考生成独立区域图

每区各一条图像任务，唯一图片输入是同一已验收ABC整板，不补投会重定空间或外观的其他图片。上游人物和母图已在整板中落实。派生目标是将指定区单独放大呈现，不重新导演、不补全画外；这是模型参考生成，不宣称像素复制。

以下A区模板换成B或C时，所有区域指向与“其他区域”同步替换。输出比例继承所选原区；A/B为成片比例，C保留完整空间比例，不把C硬改成A/B构图。已丢失或看不清的细节不能靠派生猜出，先修母板清晰度再派生。

```text
Image 1 = <同版ABC整板key>，这张图是ABC交接板。
仅将Image 1中的A区呈现为一张独立完整画面，视觉效果相当于把A区单独放大展示。
完整保留A区原有画面边界、景别、机位、透视和构图。人物在画面中的位置、大小、朝向、视线、表情、姿态、左右手及持物全部保持一致。建筑、车辆、道具的位置、比例、遮挡关系，以及光线方向、色调保持一致。
B区和C区仅辅助核对身份与空间，不采用它们的取景，不将其中A区原本不可见的内容加入画面。
去除分区标签和外围边框，画面内部不删减、不新增、不重新构图、不改变动作状态、不扩展画外空间。
输出一张单幅画面，画幅与原A区一致，不含其他区域、分格或文字标签。
```

逐图对照原区核验：画面边界、景别、机位、人物相对尺寸/位置、手与持物、车位、门窗、地标、遮挡、光向、表情和动作相位。A/B仍须保留母板设计的明显切镜差，C仍能解释A/B空间；不因“参考了同一板”自动放行。偏差图不进入视频；回到原母板重派生对应区，重复失败时说明问题，不无限尝试或改用其他方案绕过用户选择。

## 5. 入板、出板与生成顺序

交接板归属于**一对相邻SEG的边界**。两端共享确切board_key/版本作为区域图来源，各自上传不同用途的区域图；Image编号由本段真实清单决定，A/B/C语义不能互换。
- 首段无入板，不伪造“上一段”；与后段有关联时引用出板的A约束结尾。
- 中间段：逐边判断关联；需要入板时用B约束开头、C约束空间，需要出板时用A约束结尾。可涉及零个、一个或两个交接边界；两个边界都启用时，本段上传入板B、入板C、出板A三张区域图。出板B/C属于下一段，不上传至本段。
- 末段：仅在与前段有关联时使用入板B/C，不虚构下一段；独立单段无交接边，不制作ABC。
- N个段只为有关联且需承接的边界制作板，数量为0至N−1；不是每段固定一张或三张图。无关联边界不留空白占位板。

允许联合规划所有启用ABC边界的planned板。先备齐共同上游，一次生成每张整板并核对图内空间，再以各自整板为唯一图片参考派生A/B/C并逐图核验，用出板A独立图指导前段结尾。取得前段后核对实际尾帧与A；满足交接要求时保留原板，无须强制替换A。存在偏差则按实际状态和共同空间统一修订整板并复核两端，或回修前段；不篡改真实尾帧，不把planned自动标verified。后段准备好已核对的入板B/C独立图后生成；“独立生成”不等于无依赖并行生成。

板版本变化要重新派生全部三区并检查其两端SEG提示词、引用清单、C空间、声音与已有成片；旧成片记录保留实际使用版本，不事后伪改历史绑定。

## 6. 视频投喂与验收

先按§1.1确定每个镜头范围的唯一空间来源并排除竞争图，再排上传顺序：入板B独立图→入板C独立图→出板A独立图（均按边界关联启用）→当前场景/状态/镜头范围未被入板C覆盖且需要参考时的对应母图，或确有必要的同源细节补图→人物→道具及其他必要参考。同一图只上传一次、只占一个Image编号；每张实际区域图各占一个Image编号，不上传整板、入板A或出板B/C；不能给一个整板文件编三个号冒充独立图。未知上传上限保持未知，不用删除关键参考来假装符合；超限时检查实际平台能力和依赖，提出具体适配。

七段式按model-adapters第5节新格式：所有实际使用的ABC区域派生图、场景、人物和道具统一列在【参考图】，其后依次为【站位声明】【时间轴分镜】【接续状态】【音效】【强制禁止项】，之前为【画幅风格】。每张图逐行写 `Image N = 资源 key，这张图是……`，用途明确入板或出板、镜头范围与区域权限。
有入板时，时间轴首镜明确从入板B开始并继承C；有出板时，末镜明确达到出板A；无板边界按文字时间轴直接开始或结束，不虚构A/B/C。【接续状态】记录实际终态；有出板时用本段已上传A独立图的Image编号说明终态，并以自然语言写下一段的切镜关系；未上传的母板key或下一段B图不写成可读取的本段参考，无关联时写“自然转场，无ABC，下一段独立开场”，末段写无下一段。负面项加：禁整板入镜、非剧情要求的板面分屏、边框、ABC标签、重播入板A、把C演成第三镜、跨区变形过渡。

先检查关联判定：use_abc=false且理由成立的天然转场免ABC检查；以下ABC检查仅适用于启用边界。验收分三层：
1. **文本与参考图**：A/B/C语义正确、单图三区、共同空间母图可追溯、单次整板生成后才派生三区，无反向依赖或二次合成；区域图对照母板通过、同版来源闭合、A/B机位与C空间可解释、三区及跨板一致性已核对且细节清晰、边界key一致、Image编号与实际上传一致、无SBSHEET、无同时间窗第二空间控制图、资产状态闭合；图板与文字版本同步。
2. **实际段端点**：前段最后帧与A、后段第一帧与B对应，B后镜头空间继承C；切镜明显，事件/动作相位/视线/轴线一致，无重复动作或漏动作。
3. **原段直接拼接播放**：按顺序播放未经裁切、补帧、叠化、变速或音频修补的两段；检查黑帧、冻结尾巴、参考板露出、对白截断/重复与声音突变。编码/帧率/尺寸/音频规格在生成前统一，必要的自动封装不改变镜头和音频内容。

以“无需人工剪辑修补直接衔接”为验收目标，不承诺提示词能保证模型每次成功。只有图或提示词时只能报告相应设计检查通过，视频衔接仍待实测。动作段“高潮终帧”不得另加冻结停留或黑场而破坏已定交接；终篇的戏剧性收尾按原规则执行。

## 7. ABC材料自动检查（内部使用）

视频材料交付前，在通用引用检查之外运行 `scripts/audit_abc_flow.py`。它核对已复核的任务分类和引用拓扑，不读取图片内容，不自动理解剧情；没有内部台账或判定不全时返回待核查，不能凭没有报错宣布通过。不修改材料、不自动删图或补板。

```text
python scripts/audit_abc_flow.py 生产材料.jsonl --ledger 内部ABC审计台账.json
python scripts/test_audit_abc_flow.py
```

### 内部台账准备
先逐条阅读图片任务的用途、提示词与依赖，以及全部相邻视频的关联关系。将每张图片归为基础/状态资产、完整ABC、独立ABC区图或二次合成任务；不能只凭key含ABC或_A/_B来分类。台账是本skill内部检查输入，不是V3.0字段，不进入生成正文，也不作为默认交付物。

内部JSON形状示例（资源名仅展示格式，不是可导入生产材料）：
```json
{
  "version": 2,
  "reviewed": true,
  "material_sha256": "由material_digest(rows)计算的当前材料摘要",
  "video_order": ["EP01-SEG01", "EP01-SEG02", "EP01-SEG03"],
  "images": {
    "母图_R01": {"role": "asset", "method": "generate_once"},
    "交接板_R01": {"role": "abc_board", "method": "generate_once", "boundary": "边界1"},
    "交接A_R01": {"role": "abc_panel", "method": "generate_once", "boundary": "边界1", "board_key": "交接板_R01", "region": "A"},
    "交接B_R01": {"role": "abc_panel", "method": "generate_once", "boundary": "边界1", "board_key": "交接板_R01", "region": "B"},
    "交接C_R01": {"role": "abc_panel", "method": "generate_once", "boundary": "边界1", "board_key": "交接板_R01", "region": "C"},
    "后场_R01": {"role": "asset", "method": "generate_once"}
  },
  "boundaries": [
    {"id": "边界1", "from_seg": "EP01-SEG01", "to_seg": "EP01-SEG02", "use_abc": true, "reason": "同场对白承接", "board_key": "交接板_R01", "region_keys": {"A": "交接A_R01", "B": "交接B_R01", "C": "交接C_R01"}},
    {"id": "边界2", "from_seg": "EP01-SEG02", "to_seg": "EP01-SEG03", "use_abc": false, "reason": "无关联天然转场"}
  ]
}
```

- `video_order`按实际生产范围与播放顺序包含材料中每条视频且仅一次；每个相邻边界均登记启用与原因，不能以漏登记代替免ABC。截取范围之外的边界需另明确审计范围，不伪造不存在的视频。
- `images`覆盖每张图片任务。`role`只能为`asset`、`abc_board`、`abc_panel`、`abc_composite`；后三者声明所属`boundary`。母图、人物或道具图是`asset`，不因带A/B字样误判为分区任务。正文出现明确ABC区图描述却登记asset时，会要求复核用途并记录`classification_note`，不能为消除警告随意填理由。
- `method=generate_once`表示当前材料要执行的图片任务；每边界有一条整板任务和三条以它为父图的区域派生任务。abc_panel必须记录board_key与region，实际唯一图片引用必须为该整板；abc_composite只用于识别并拒绝旧合成流程，不能改名伪装asset。
- 复用已核对的旧整板或区域图可用`method=reuse`，提供实际绝对`path`、文件字节`sha256`及`reuse_reviewed=true`。检查文件存在、非空和哈希相符，仅证明字节匹配；身份、版本和图内一致性仍须实际核对。复用区域图另提供确切board_key、region和lineage_reviewed=true以证明已复核来源，不能仅凭文件名推断。同版来源仍须闭合。历史制作过程不因此变成新的分区任务，不为旧工艺本身要求重做。
- 外部已有资源在本检查器中可以由上述复用记录提供来源，但不豁免外部导入契约。V3.0仍须按其规则保留合法图片记录；实际执行器是否能复用、是否会重新出图另行确认，内部`reuse`不会自动让程序跳过任务。
- `reviewed=true`只能在完成实际用途与关联复核后填写。`material_sha256`用脚本导出的`material_digest(rows)`计算，rows为按文件顺序解析的全部JSONL对象；材料改动后复核受影响项再更新摘要，旧台账不能用于新材料放行。

### 自动检查及放行范围
- 每个启用边界恰好一个当前完整ABC资源及A/B/C三个区域资源；整板不得直接或间接依赖区域图，派生图只能直接引用该版整板；不允许二次合成，保留必要母图与基础资产。
- 前后两段结构化引用与正文Image绑定一致，前段仅绑定该边界A独立图、后段绑定该边界B/C独立图，三区追溯同一board_key（含版本），视频不绑定整板；检查漏引、错边界、缺任务/复用实物、重复引用及循环依赖。
- 无关联边界不要求ABC，也不允许挂着该边界的冗余ABC任务；其他关联边界的板可以继续作为同段的入板或出板。多场景各自必要资产不受“一边界一板”约束。
- 返回`declared_flow_checked`只表示所声明流程的机械关系通过；`incomplete`表示分类、关联、复用审核或摘要等仍需核查；`failed`列明任务及错误。命令退出码依次为0、2、1，待核查不能当作通过。
- **仍需人工/代理语义复核**：分类是否真实、天然转场是否成立、正文是否正确使用入板B/C与出板A、必要空间覆盖是否充分。**仍需执行与视觉验收**：整板真实单次调用、区域派生调用及对原区保真、实图内容、上传、两段端点与未经修补的直接拼接。不能用脚本结果代替这些证据。

### 外部程序阶段依赖检查

父图在JSONL中后列不等于引用缺失；存在且无环的前向引用可通过关系检查。只有执行器已确认要求按行执行时，才用`audit_material_refs.py --require-parent-first`检查行序兼容性。此项不改变“一次整板生成”和实际父图先就绪的要求，也不把未知调度能力视为已支持。

导出ABC前同时检查图片依赖拓扑和执行阶段。实际引用的共同母图及必要资产必须先完成，再调用一次生图生成整张ABC；每个启用边界导出一条ABC整板任务及三条区域派生任务，共四个输出key；实际执行须先验收整板，再把该整板作为唯一图片参考分别生成A/B/C并核验，最后按用途上传给视频。不导出先分区后合成的旧流程，不以程序裁切替代参考生图。所需基础资产与状态母图保持独立任务，不能误删。若ABC映射为CT固定资产而其母图映射为后生成的SCSTATE，实际调度必须支持先完成父图，或另行明确分阶段执行方案；未支持时指出阻塞和可选适配，不凭JSONL行序宣称可自动执行，不把SCSTATE伪装成SBSHEET。内部母图记录不自动成为外部程序字段，也不强制每个边界新增一张母图任务。基础资产的身份派生关系同样按依赖生成，任务定义齐全不等于图片文件齐全。
