# 轻量离线分镜看板（Storyboard Board Lite）

> ⭐ **定位**：把项目 md（唯一真相）一键编译成**单文件离线 HTML 看板**——双击浏览器即开，零依赖、零数据库、零端口。形态与 6.8.3 完整版（模块 K）**同构**：创作蓝图层 + 分镜生产层双层区块全保留；**只砍** N1~N11 深度检查层、`validate_prompt.py` 依赖与 board_state.json 快照。
>
> 🔗 配套脚本：`scripts/build_board_lite.py`

仅用户需要看板时启用本模块，不因运行生产流程而自动追加HTML或Markdown。这里的“md唯一真相”仅指所选MD看板路线的输入，不覆盖用户指定的JSONL等交付契约。看板保留所提供内容，不为凑版块新增资产任务或内部报告；内部记录不得混入可复制的生成提示词。

---

## 一、 六条轻量铁律（K-lite 1~6）

| 编号 | 铁律 | 说明 |
|---|---|---|
| **K-lite-1** | **md 是唯一真相，看板只读** | 看板是产物不是工作面。⛔ 禁止"在网页里改分镜再同步回 md"；改稿改 md，然后**重编译**看板。 |
| **K-lite-2** | **缺字段降级不中断** | md 是用户手改的文件。任何章节缺失 → 该区块显示"未解析到"并记 **WARN**，**看板永远出得来**，绝不因一处格式不标准整板崩掉。 |
| **K-lite-3** | **拆解视图与原文并存** | 每段同时给逐镜拆解和围栏原文。围栏逐块按源文件顺序保留，复制全部时块间用空行连接，不只挑最长一块。段落按解析时归属，禁止用段名的字符串前缀匹配（段1不能取段10）。 |
| **K-lite-4** | **已有出图词与投喂词完整呈现** | 输入同时包含资产出图词与视频投喂词时，两者都保留。只有视频词或资产复用时，不因没有P2.5章节判缺项、不强迫新增出图任务；必要引用完整性另按生产检查核对。 |
| **K-lite-5** | **宽容识别，不为看板改写 md** | 章节名 / 段标题 / 资产表列序 / 镜行时间码一律按关键词宽容匹配（见 §三）。遇到不识别的新格式，**优先扩编译器**，不许要求用户把 md 改成契约标题——那会制造"为出看板而生的第二份 md"，直接违反 K-lite-1。 |
| **K-lite-6** | **信息零丢失** | md 里写下的每一样东西都必须出现在看板上：剧本区收**正文 + 表格**（表头/数据按 markdown 分隔行切表、保持原文顺序）；未被归区的章节（双锁表 / 内部 QC / API 模板 / 生成顺序等）原文照录进「⑦ 其他章节」。看板出现"未解析到"仅限该章节在 md 里本来就不存在。 |

---

## 二、 用法

```bash
python scripts/build_board_lite.py <项目.md>              # 输出 <项目名>_分镜看板.html（同目录）
python scripts/build_board_lite.py <项目.md> --out 看板.html
```

## 三、 输入 md 契约（章节名与 6.8.3 对齐，存量项目档可直接编译）

```markdown
# 项目标题                      ← 一级标题 = 看板标题
【画幅】：16:9                  ← A/B 双锁回显（未声明 → WARN"未锁定"）
【模型版本】：2.5

## P0A · 创作基准               ← 表格: 项 | 内容 → Ⅰ 区
## P1 · 剧本                    ← 正文照录 → Ⅱ 区
## P1 · 视听圣经                ← 表格或正文 → Ⅲ 区
## P2 · 资产清单                ← 表格: 编码|名字|视图|@图片N → ④ 区（自动算引用段）
## P2.5 · 资产出图提示词        → ⑤ 区（按输入提供，有则完整保留）
### CHR-001 · 林越 · 主角 4 View 资产板
```text
（资产图出图提示词——生成人物/场景/道具图用，不是视频投喂词）
```
## P3 · ABC交接记录           → ⑦ 区（记录关联判定、两端SEG与版本；无关联写天然转场）
## P3 · ABC交接板出图提示词   → ⑤ 区（有需要才存在；在P3生产，不前置到P2）
### PRJ__ABC_EP01_SEG01_TO_SEG02_R01 · SEG01→SEG02 · 单图三区
```text
（展开本项目的Image N绑定、A前段结尾、B后段开头、C后段整体空间及三区共同地标关系）
```
## P4 · 投喂提示词             → ③ 区
### 段1
【时长】：30秒                 ← 可选段级参数，不是逐镜时间码
```text
【画幅风格】…
【参考图】…
【站位声明】…
【时间轴分镜】
[镜头1]
画面：…
发声角色：…
对白原文：“…”
口型与反应：…
环境与动作声：…
【接续状态】…
【音效】…
【强制禁止项】…
```
[镜头1] 逐镜拆解行             → ① 泳道 + ② 镜头卡
## P6 · 发布文案               ← 可选：【标题】【封面文案】【正文】【话题标签】→ ⑥ 区
```

**解析规则（宽容识别 · K-lite-5）**：上面是**推荐契约**，不是硬性要求。编译器按关键词归区，自定义标题照样能编译：

| 维度 | 宽容规则 |
|---|---|
| 章节名 | 按关键词归区，**不要求照抄标题**：`资产清单/资产表/P2`→④、`出图提示词/资产出图/P2.5/P2c`→⑤、`投喂提示词/分镜提示词/P4`→③、`剧本/故事/梗概`→Ⅱ、`视听圣经/风格圣经`→Ⅲ、`创作基准/P0A`→Ⅰ、`发布文案/P6`→⑥。所以 `## 二、 资产清单（P2b）`、`## 三、 P2c 出图提示词`、`## 四、 P4 投喂提示词组` 都能直接编译 |
| 段标题 | `### 段1` / `### U01 · …` / `### 第1段` 都认 |
| 资产出图子标题 | `### 1. \`@CHR-沈砚\` · 4 View 资产板` —— 自动去前导序号与反引号，按 `·` 拆成 编码 / 名字 / 说明 |
| 资产表列序 | 按**表头名**映射（编码·名字·视图/出图·@图片N），兼容 `类\|编码\|类型\|出图\|复用单元` 这类自定义列序；未映射的列收进「附加信息」，信息不丢 |
| 镜行时间码 | 当前优先识别无时间码的 `[镜头N]`；兼容历史三种时间码： `00:00-00:05 [镜头1] …`、`[00:00-00:05] …`、`[0-3秒] …`；段外无拆解行时自动从围栏原文兜底提取；检测时间码回跳 |
| A/B 双锁 | 除 `【画幅】：` / `【模型版本】：` 行外，**还能从任意表格兜底**（如双锁表里 `**B · 画幅** \| **16:9 横屏**`、`**A · 模型版本** \| **Seedance 2.0**`） |
| 时间轴 | 各段独立计时（每段都从 0 起）时，泳道按累计偏移铺成整片时间轴（15+15+12+15 → 标尺到 57s），总时长＝**累加**而非取最大值 |

## 四、 看板区块（自上而下 · 双层结构）

| 层 | 区块 | 内容 |
|---|---|---|
| **创作蓝图层** | Ⅰ 创作基准 | P0A 表格项 |
| | Ⅱ 剧本层 | P1 正文照录 |
| | Ⅲ 视听圣经 | P1 锁定项（一次锁定全片继承） |
| **分镜生产层** | ① 镜头顺序/历史时间轴 | 无时间码按镜号顺序展示；历史实际时间码才显示秒级泳道 |
| | ② 镜头卡矩阵 | 逐镜卡（段/镜号/内容），无时间码不编造时长 |
| | ③ 投喂提示词原文 | 每段折叠框 + **复制投喂原文**按钮 + 段级栏标签——成品视图 |
| | ④ 资产总表 | P2 表 + @图片N 徽标 + **自动算出每个资产被哪些段引用** |
| | ⑤ 资产出图提示词 | 每资产折叠框 + **复制出图提示词**按钮（按本次输入提供，有则完整保留） |
| | ⑥ 发布文案 | P6 四件套（可选） |
| 顶部 | 统计条 + 段筛选 | 模型/画幅/段数/镜数/总时长 + 按段过滤 + **只看告警**开关 |

## 六、 ABC交接看板展示
“分镜看板”是文字分镜与生产信息的查看工具，不是要上传给视频模型的故事板图。按 `abc-handoff-board.md`，视频参考只有按需入板B/C、出板A独立图与必要资产；整板先一次生成并验收，再参考整板生成这些区域图。
- 关联判定及板来源放“P3 · ABC交接记录”，进入⑦其他章节；每张ABC以边界key为标题放“P3 · ABC交接板出图提示词”，现有编译器按“出图提示词”进入⑤，并与③视频原文同板展示。
- ABC实际图片路径、状态、版本与两端SEG放在交接记录。④引用段仅统计视频正文的完整Image N绑定；整板是区域图的上游，不因视频引用其A/B/C派生图就显示成直接视频参考。普通提及、@锚点与key前缀不计入直接参考；此统计也不证明实际已上传。
- 无关联边界不生成ABC出图条目、不报缺板；看板WARN=0只代表文档解析状态，不代表图板内容正确或视频已实测可直接拼接。

## 视频分镜无时间码（2026-09-16）
新投喂正文按[镜头N]组织。看板解析镜头编号并按顺序展示，不因没有时间码告警，也不以均分方式伪造镜头秒数。旧文档的时间码解析保留用于读取历史资料。SEG总时长可单独写为段级 `【时长】：30秒`，未提供时显示未知；只有真实提供的内部时间预算才用于秒级泳道。正文复制仍保持原文。

## 当前解析与核查边界

- 当前七栏目按 `【画幅风格】→【参考图】→【站位声明】→【时间轴分镜】→【接续状态】→【音效】→【强制禁止项】` 识别；接续状态是独立栏目。解析结果保留栏目内容，但不重写原始投喂词。历史栏目允许照录，不能据此称符合现行模板。
- API模板、内部QC等普通章节中的代码围栏也保留在⑦其他章节；同一资产或段的多块围栏保序保留。未闭合围栏保留正文并告警。未归入结构化卡片的普通文字仍进其他章节。
- 看板负责展示和复制，不判断引用图片是否已生成、实际请求是否上传、图片空间是否一致或成片能否直拼。
- `scripts/audit_material_refs.py 材料.jsonl` 仅检查基础字段和引用；空材料、非法kind、缺必填字段不能通过。它不是完整V3.0 schema或真实导入器；集段对账、图片形状路由、参考身份描述等尚须独立核查。
- `--files 图片路径映射.json` 检查引用父图的绝对路径和图片可读性，不能证明人物身份、版本或任务日志成功。
- `--uploads 实际请求素材清单.json` 对照真正装配请求中的图片顺序，格式为 `{ "任务key": [{ "image_n": 1, "key": "图片key", "source": "实际请求中的图片地址或文件源" }] }`。该清单从请求提取，不能从计划引用表复制来充当实测。省略任务明确标为未验；对比通过不代表网络发送成功、服务商收到图片或图片身份正确。
- `check_package.py` 的PASS仅代表列出的静态包检查与局部回归；不等于完整生产验收。

空间来源记录同时在P3章节保留：场景状态版本、唯一母图、一次整板生成记录、A/B与C的空间关系核对、每段空间控制范围和图文同步结果。看板展示多张图不意味着允许同时投喂多个空间控制来源；当前脚本不自动判定这些图像是否一致，需按 `abc-handoff-board.md` §1.1验收。

引用脚本按所选契约运行：V3.0使用默认v3模式，其他格式只在内部归一后使用internal模式，适配和检查边界见asset-first-pipeline“检查输入与契约适配”；不要为通过脚本擅改用户交付格式。
