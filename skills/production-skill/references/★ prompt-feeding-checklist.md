# 投喂生成检查清单
基础项始终检查；面部细节、顶视图、动作细化按镜头需要启用，不因清单存在而强制全部模块。

## 1. 项目与格式
- 沿用已锁定模型、画幅、SEG时长、语言、音频、字幕、交付模式；缺关键项再问，不静默回落。
- 唯一七段式：画幅风格、参考图、站位声明、时间轴分镜、接续状态、音效、强制禁止项，完整定义见 `model-adapters.md` §5。
- [镜头N]按先后描述，无时间码、镜头秒数、精确完成时点；总长与容量留项目参数/QC。提示词无500字门禁。
- 图片与视频正文均无内部分析、编码分级、评分、预算、QC记录、任务状态、调度/上传说明及English kernel；任何语言同样检查，详见model-adapters第5节。不得把这些信息移入括号、负面项或正文附注。
- 清理后必要Image绑定与用途、镜头范围、人物外观、空间位置、持物、动作和接续状态仍完整；无旧@图号、末尾参数行；无字幕时不能用屏幕文字表现台词。

## 2. 时长与创作
- 按项目SEG时长核算，30秒项目不套15秒阻断。没有固定每镜下限、固定切镜数量或24字强制拆镜。
- 对白按实际语速档、停顿与情绪核算；同期动作与台词不简单相加。
- 首尾镜头符合剧情与启用的ABC。慢镜、对招、肘击、终结技、切黑、定格按用户和剧情，不是通用必选。
- 人物表演按story-directed-performance由剧情与当下目的设计，不套情绪阶段或动作配方；仅必要面部细节才核对可见形态与连续性。
- 表情强度与时序依人物、剧情和画风，不固定百分比或要求每镜完成起落；中途改变或跨镜保持允许，核对状态承接和对白完整性。负面项只写适用风险，不按固定长句验收。
- 复杂走位/多人交叉或用户要求时才启用顶视图；它是上游工具，不自动加入视频作为另一空间权威。

- 导演意图已落实：观众注意力、情绪变化、揭示顺序与关键视觉证据明确；每镜有实际任务和合适进出点，不默认谁说话拍谁，不平均分时长。段尾有合理观看动机，不强制反转或截断句子。
- 补充行为服务人物与情境，不擅改核心事实、不为凑时长堆动作；分析理由留内部，不进入正文。

## 3. 参考任务、文件与实际上传
- 材料：正文Image编号、结构化引用、图片任务/复用资源、版本完整一致，无循环、自引用、漏任务。
- 行序：父图记录后列默认只作排序信息，引用存在且无环不因此报错；执行器已确认要求父图先列时才用`--require-parent-first`单独检查。实际执行依赖和父图就绪仍必须落实，不能把材料行序当生成成功证据。
- 文件：执行生成前每张父图真实可读，生产状态与路径有据；仅任务存在不算已出图。
- 请求：实际上传素材的数量、顺序、key版本与正文一致；服务端可访问，不能只写Image行。
- 任一层缺失写清具体图和受影响任务，不静默删图。未检查层写未验证。引用审计不替代契约schema或实际请求检查。
- 能力：时长、参考容量、模式组合、音频、组内多镜按实际平台核实，未知不猜；超限不偷偷拆段、降模或删场景。

## 4. ABC与多场景空间
- 逐边判关联；有关联才出ABC，无关联天然转场免板，不强制埋后段钩子。
- 材料交付前按abc-handoff-board第7节完成内部分类与边界复核，运行audit_abc_flow.py；检查一边界一整板、整板先于三张区域派生图、前尾A与后首B/空间C分别绑定、三区同版来源及引用闭合。禁止先分区后合成或视频上传整板。缺台账、判定不全或摘要过期须先复核，不当作通过；内部台账不进入正文或交付契约。
- 共同母图和身份/道具来源明确，每边界一次生成整板，整板验收后参考同版整板生成独立A/B/C并逐图对原区核验，不先分区后合成；C依共同来源呈现，A/B摄影视角能在同空间解释，无偷偷移人/车/门。逐区核对结构、持物、光向、通路和清晰度，并核对多个ABC之间的状态演进。
- P1已核对SEG有效内容自然充足且不过载，分割点不是为迁就已画ABC或凑时长；详见dialogue-speed-check。
- 视频仅投所需区域独立图，不投整板；入板B首镜、所属场景C开场；出板只用A收尾。当前场景、状态及镜头范围未被入板C覆盖且需要空间参考时用本场母图；一次性独立场景按asset-first-pipeline可仅文字，不并投同状态竞争SCSTATE。
- 逐镜核对拉远、转身、跟拍、环绕或过门从起镜到落镜的显露区域、遮挡、脚下落点、通行路线与必要图覆盖；空间信息必须在上游提前提供，缺失时先补同源任务/实图，不让视频自行补布局；复用场景先建资产，一次性独立短镜可豁免，连续连接空间不能因只出现一次而省略。
- 每场分别登记镜头范围。一段三个场景保留三套必要参考，不跨场景去重；分屏按区域。
- 可见人数与身份按取景、遮挡、入画/出画核对，防意外复制与旧位残留；合法分屏、倒影、回忆或剧情分身明确作用范围，不误用整段单实例或固定人数禁令。
- C不是冻结整段位置；动作推进终态，返回场景不无因重置。图板改版同步两端正文/引用/接续。
- 无SBSHEET故事板进视频，无整板入镜；后段真实执行前核对前段实际尾帧。详见 `abc-handoff-board.md`。

## 现场丰富度与状态继承检查
- 人员职能、设施、物件和活动是否支撑场所用途与事件规模；不以空旷或人少本身判失败，也不按固定人数/道具数量验收。
- LOC无人但环境完整；SCSTATE落实当前现场，必要群体与临时配置在生成视频前已有可用来源，未靠视频临时补齐。
- 复用时区分同场延续、状态变化与持续损坏，旧群众不串场、旧布置不强留、损坏不无因恢复；合格现有图可复用，不每段重复出图。
- 逐镜核对可见人员与画外关系、群体区域、通路和背景活动；背景不抢主戏，特写后返回全景仍合理。材料检查不证明实际画面已达标。

## 5. 音频与验收
- 镜头以分行块区分画面、发声角色、对白原文/内心独白原文、口型与反应、环境与动作声；每次发声单独绑定角色，原文引号内只有应说的话，无台词时省略原文字段。多人同镜的顺序或剧情抢话关系明确，不能默认换人就切镜。
- 【音效】限定只有已列原文可生成语言人声；标签、角色名、画面/参考图/动作说明与音效名称均不朗读。内心独白画内嘴闭，现场对白按可见性核对口型；不同角色及同角色各镜音色匹配。只有实际试听才能确认无串词、错人或说明被朗读。
- 原生音频由视频任务生成，说话人与声音/嘴部动作对应；选择后期才规划独立配音。
- 对白完整清晰，音效和音乐不遮盖；固定电平不是所有镜头的硬要求。
- 图文通过不等于成片通过，无视频不声称原段直拼已验。按 `quality-gate-review.md` 分层报告。

### 非语言人声的边界
呼吸、叹息、抽泣等按剧情需要写在现有“环境与动作声”中，说明声源人物及发生动作，只生成相应声音，不朗读名称；不是新增对白。现场对白对应口型，内心独白不做说话口型；呼吸或哭泣允许自然嘴部动作。语言人声只来自已明确绑定角色的对白/内心独白原文，不新增旁白、解说或未写台词。

引用脚本按所选契约运行：V3.0使用默认v3模式，其他格式只在内部归一后使用internal模式，适配和检查边界见asset-first-pipeline“检查输入与契约适配”；不要为通过脚本擅改用户交付格式。
