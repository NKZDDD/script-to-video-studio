# Asset-First 六阶段生产管线
本文件定义材料编译与实际生成的依赖关系。阶段名称相同，完成标准按模式区分；文字任务不得冒充已生产图片。

## 〇、模式与共用锁
- **材料编译**：用户要提示词、JSONL或生产计划时，允许先完成全套planned任务与依赖，不要求先生成全部实图。交付前验证每个引用均有对应任务或明确已有资源、key与版本一致、无循环。状态写待生产/待验证。
- **执行生成**：用户要求生成图片/视频时，按父任务就绪关系执行；所需图片成功输出且可读后才能提交下游。已有可复用资产先核对版本和用途，不重复生成。
- 项目模型、平台、画幅、时长、音频、字幕及用户约束沿用已知值。用户指定外部JSONL契约时遵守其字段与交付形态，不强加MD/HTML或发明导入字段。
- 资产依赖A0～A3：A0纯文字或无一致性需求无需资产链；A1单角色单镜按需；A2跨镜复用启用有关资产；A3多人多场景连续生产完整规划。分级不免模型/画幅锁、不免已经引用的素材完整性。
- 用户已有授权与偏好持续有效。分批生成后进行质量核验；仅当用户要求逐批确认或确有待决创意问题时请求确认，不把每批固定停等当默认流程。

### 交付范围
- 先沿用用户指定的交付内容、格式和生产范围。只要JSONL就交合法JSONL，只要提示词就交对应提示词；平台不能自行追加MD图册、HTML看板、曲线PNG、诊断报告或API载荷文件。
- 用户请求图册、曲线、看板或报告时才交相应产物；未指定其文件格式时按用途选择合适格式，不自动打包全部形式。用户请求多个产物时按请求组合交付。
- 必要内部分析、台账、预算与质量检查继续执行，和生成提示词及对外交付分开。编译所需工作文件不自动成为用户交付物；内部信息不进入提示词正文。
- 精简交付不等于省略一致性所需资产：契约内必要图片任务、复用资源及引用必须完整；是否执行出图由材料/生成模式决定，不为填满图册给所有实体一律建图。
- 所有平台适配仅改变已选内容的传输、显示和合法字段映射，不能扩大生产范围、更改契约或增加必交文件。

## 一、P0～P5
1. **P0项目锁定**：记录用户要求、交付模式、实际接口能力。未知能力不伪装已确认，制作材料与真实提交分别判断是否受阻。
2. **P1剧本与分段**：理解剧情、人物关系、对白与节奏；按cinematic-dramaturgy-rules明确各段核心任务、观众情绪、信息揭示、视觉证据与观看动机；按锁定SEG总时长检查有效剧情、对白、动作及有意义留白是否自然充足且不过载，再定分割点；依据dialogue-speed-check，不为凑满而拖镜头或重复反应。动作与镜头按用户/剧情决定，不套固定切镜数。结合场所用途和事件规模，先设计需要的现场人员、设施、物件和背景活动，交给P2/P3落成参考；不临到视频才补现场。
3. **P2基础资产**：提取人物、按下述场景启用规则选择无人LOC、道具、声音身份；角色按既有4 View规格与10项五官＋6项服装材质记录。角色重要程度决定精细度，血缘关系单独记录；非血亲不遗传主角骨相。材料模式写任务，生成模式产出实图。
4. **P3文字分镜与空间**：先落实P1导演判断：镜头任务、视觉中心、进入退出、动作过程或结果与剧情驱动表演，再明确调度及相邻边界关联，按场景启用规则确认必要的对应状态母图，将当前现场人员、临时布置、活动区域及持续变化落实到图像；既有状态适用时复用，不每SEG重画。已有合格SCSTATE可复用；每个边界以共同母图及必要资产为参考，一次生成完整ABC并验收，再以同版整板为唯一图片参考生成独立A/B/C并对原区核验，不先分区后合成；C在同次生成中呈现后段开场空间。有关联才做ABC；无关联天然转场不用，也不硬塞后段伏笔。复杂走位/用户要求时增加上游顶视图，普通对话不强制。
5. **P4封装与生成**：按model-adapters第5节唯一七段式装配。启用空间参考的每个场景/状态/镜头范围一个空间来源，多场景保留各自必要参考。材料可planned；真实后段执行须核对前段实际尾帧与ABC，不能无依赖并行。
6. **P5分层验收**：材料格式、引用图、实图、实际上传、视觉空间、视频及原段直拼分别报告。哪层未执行就标未验证，不笼统声称全通过。

## 二、资产记录
- CHR：A/B级核心/常驻按4 View；群众或剪影按实际可见与复用需求。不把文字剪影伪装成已上传图。
- LOC：建筑、地形、固定陈设、材质和合理使用痕迹，记录固定光源位置与基准照明；无人不等于空旷。无人物、人物剪影、人形占位或人物倒影，允许环境本身的正常反射。含人物的剧情空间母图归SCSTATE/P3，不回灌为无人LOC。
- PRP：关键物证、反复出现或需精确交互的道具按需独立出图；外观图不重新决定场景摆放。
- AUD：对白身份、OS、音效、音乐按用户音频模式记录。原生音频不自动派生后期配音任务。
- 图册记录key、版本、用途、生产状态、依赖；生成后才登记真实文件与验收结果。文字索引和图像证据分开。

### 场景资产启用与覆盖
目标是保持镜头间与段间的空间一致性；出现次数是判断线索，不能代替一致性需求判断。
以已提供剧情和已知后续规划判断复用，不能只因本次截取片段出现一次就认定全剧不复用；未提供后续时说明判断范围，不虚构后续，也不一律强制建图。
- **一次性独立场景**：只出现一次、独立短镜、后续不复用且不需要与已有空间衔接，可不单独制作LOC或SCSTATE，由视频文字交代环境；不伪造Image引用。该豁免仅针对场景，不免人物、关键道具等必要参考。
- **复用场景**：后续重复出现，或多个独立视频段需要呈现同一空间，先构建可复用场景资产，后续从同一来源派生。场次计数不等于镜头计数，不以“跨两镜”单独触发强制建图；同段多镜也要逐镜检查重复可见的建筑、固定物件及人物通行关系；若需要保持这些空间事实，必须使用足够覆盖的同源场景参考，不能以“只在一段出现”豁免。已由合格母图或ABC C覆盖时直接复用，不额外重复建图。
- **一次性但空间连续**：如从已建立的门外走进门内，即使门内只出现一次，也须明确门洞、门槛、连接区域与动作路径。优先扩充原空间或制作同源补充视角，不一定新增独立场景资产；镜头始终不展示的区域无需无目的补全。
- **稳定结构与剧情状态分开**：建筑、门窗、道路及固定陈设复用；人物站位、持物、门扇开合与昼夜光照按剧情派生状态。不能把复用理解为冻结全部状态，也不能独立重造矛盾建筑。
- **必要空间前置**：对拉远、跟拍、转身、环绕、过门等镜头，提前列明从起镜到落镜将显露的必要区域、遮挡、脚下落点与路线。凡影响一致性的空间关系须由同源上游参考覆盖，不能让视频自行想象补布局；缺失时材料先补生产任务与引用，执行先补实图并核验，未就绪不提交该视频。已由母图或ABC C覆盖时不重复加图；一次性独立无继承需求的短镜仍可按上条豁免。
- **逐镜覆盖审核**：镜头实际展示哪些区域、脚下落点、通行路线及交互面 → 是否需要资产 → 已有图是否覆盖 → 必要补图是否同源 → 视频是否引用正确的图及作用范围。母图或ABC C已覆盖时不重复上传LOC；独立一次性场景符合豁免时不误报缺图。动作起态/终态与图不一致另作调度修复，不靠增加场景图掩盖。
以上判断记入内部资产/镜头记录，遵守既定外部契约，不新增强制JSONL字段。

### 固定场景底图与剧情现场状态（场景丰富度权威）

沿用LOC与SCSTATE两种已有职责，不增设第三种重复“丰富场景资产”。现场是否可信依据场所用途、事件规模、时代与剧情，不按人数、道具数量或画面填满程度评分；独处、封闭或空旷场面可以成立。

- **固定环境LOC**：建立建筑、道路、门窗、固定陈设、材料、使用痕迹与固定光源位置。只补镜头需要的合理环境，不凭空堆尘土、旗帜、器物或标语；本场临时人群和布置不固化为地点永久配置。
- **当前现场SCSTATE**：在共同LOC结构上，按剧情加入主要人物、必要执行/服务/等待/旁观人员、临时设施、道具摆放，以及当前天气、照明、门扇和损坏状态。每张图表达一个明确时刻，不将巡视前后或人群移动过程同时画成多个同一人物。活动区域与后续通行路线须可解释。
- **人物与群体**：有对白、关键交互、特写或需辨认复用的个体按必要身份资产绑定；远景群体可在母图内按职能、外观、区域和活动状态设计，不给每个群众单做角色板。关键数量必须明确；其余按可见规模与分布表达，不能每镜随机换规模、服装或阵营。人物转为前景或关键交互时，先补足对应身份依据。
- **表现权限**：可补合乎情境的背景人员、物件及活动，不因原稿没逐个列出就只画主角；但不能新增改变剧情的证人、救援者、关键物证、对白或事件结果。原稿明确无人、秘密行动、人员隔离等条件优先。
- **复用判断**：同场连续动作继承已有现场及状态演进；再次回到同地且状态适用时复用；时间、人员、布置或天气已变化时，从同一固定场景资产与已确认持续变化派生对应状态。不要照搬旧群众和布置，也不能回到干净LOC就抹掉剧情留下的损坏、遗留物；清理、修复或离场须有剧情或合理时序依据。
- **按需版本**：不每镜、每SEG新建母图。只有当前参考不能可靠支撑新的关键配置、空间覆盖或状态时才补图/升版；普通动作由视频推进。持久结构变化记录为场景状态或按需新基准版本，旧版及旧成片绑定保留。新状态的图片输入以当前一致的空间母图或固定环境为权威，不并投两张互相竞争的现场图。
- **ABC与视频**：参考当前合格母图一次生成完整ABC，随后参考同版整板生成独立三区；视频通过入板B/C和出板A继承对应时刻的完整现场。未被入板C覆盖且需要参考的其他场景/状态/镜头范围，直接绑定相应母图。C覆盖的同状态不再重复上传完整母图。新整板始终依共同基础资产和当前母图，不依赖ABC区域派生图逐板传递；旧C仅作空间核对证据。
- **动态与取景**：视频文字描述已建立人员、物件的活动和合法状态变化；背景活动不抢主戏、不阻塞已锁通道、不随机增删关键实体。特写可以只见主角，切回全景时现场仍应成立。必要新增人员、设施或新显露区域先回补上游参考，不能只在视频正文临时加一句。
- **豁免仍有效**：符合一次性独立短镜豁免时不为“丰富度”强制新增LOC/SCSTATE；其环境仍按剧情设计。有重复空间、复杂交互、群体关系或关键设施需要稳定继承时，按实际一致性需求建图，不借一次性名义免除。

内部记录地点基准、当前状态版本、沿用/变化/持续的事实、个体与群体所在区域、适用镜头及引用。正式图片和视频正文只写可见现场、必要绑定、动作与声音，不写丰富度分析或验收说明。执行时分开验收“现场是否支撑剧情”“跨镜状态是否延续”和“主要视觉中心是否清楚”，不能把出图任务完整当作画面已经丰富。

## 三、执行门禁
|阶段|材料编译|实际生成|
|---|---|---|
|基础资产|定义完整任务与复用资源|父参考实图可读、版本用途正确|
|母图与ABC|规划明确同源依赖与镜头范围|先备齐母图与资产，一次生成整板并验收，再参考整板派生A/B/C独立图并核验；视频使用入板B/C与出板A，禁止反向依赖或二次合成|
|视频|正文、结构化引用、生产任务一致|实图就绪、实际上传清单匹配、实际接口支持|
|直拼|仅可验设计|完整视频顺序播放验证端点、空间、对白及声音|
缺项报告具体资源及受影响任务，补产或回修；不得以静默删引用代替修复。任务的JSONL行顺序不等于程序执行顺序；按家族批处理若破坏依赖须修调度或明确分阶段计划，不绕过母图。
引用是否合法与行序是否适配执行器分开：父图记录列在后面，只要引用存在、无自引用/循环且其他字段合法，不因此判材料引用错误。`audit_material_refs.py`默认只记录前向引用；只有已确认实际执行器要求按行依次执行时才启用`--require-parent-first`，将行序不兼容作为执行适配问题处理。实际执行仍须等待父任务成功、正确版本实图可读及上传就绪；文件排在前面不代表已经出图。检查器不自动重排材料，不擅改参考图的Image编号或上传顺序。

### 检查输入与契约适配
audit_abc_flow.py同样接收上述内部任务记录，并按abc-handoff-board第7节建立独立的已复核ABC台账、区域角色和边界关系；不能直接把普通提示词文本交给它。台账摘要绑定实际送检记录，转换后重新计算，不混进用户交付字段。
用户选择V3.0时，audit_material_refs.py使用默认--profile v3：检查首行唯一manifest、EPxx-SEGxx及该契约必要引用字段。其他交付格式先转换成仅供内部核查的任务记录，再使用--profile internal；这不是新增交付格式，不把V3字段强加给用户正文。
内部记录使用kind=image/video、非空key/filename/prompt，以storyboard_refs与reference_images两数组按实际上传顺序表达Image编号和key；可没有manifest、可用项目原key。无需参考的合法任务允许空引用，必要性仍须逐镜语义检查。已有可复用图片也登记为image来源，但不因此重新生成。外部格式另按所选契约验收。若提供manifest仍须唯一首行并核对数量；两模式均检查重复、漏图、环依赖与绑定一致，未知profile报错。实际文件、请求上传及视觉验证不能由材料通过代替。
