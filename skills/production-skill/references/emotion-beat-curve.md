# 按剧情节拍的情绪张力与可视化曲线引擎 (Emotion Beat Curve Engine)

本引擎按用户分析范围，对实际剧情中使观众感受、人物处境或关系发生变化的节点作主观张力标注。先注明范围（全剧、某集、前90秒或指定场次），再按剧情确定有效节拍数量；不要求每集或每段12个，节拍不等于镜头或SEG。曲线只辅助理解，不据此强制增加反转、高潮、反杀或改写原剧情。先用自然语言判断观众此刻知道什么、期待什么、感受如何变化；这与角色表面情绪可能不同。将有效判断传递给信息揭示、视觉证据和镜头选择，不用一个张力分值代替导演决策，也不由分值派发表情。

---

## 二、 剧本含金量判定法则

1. **波峰波谷法则**：按故事类型检查张力变化与观众理解空间，不固定波峰数量或分值；分数是内部比较工具，不代表客观质量。
2. **黄金 3 秒开局**：开场应有可理解的观看动机，不要求固定3秒或固定得分。
3. **9 节拍大反转**：反转仅在原稿与授权范围内安排，不强制第9拍最高分或每集反杀。

---

## 三、 可视化与输出形式

当用户输入 `/情绪曲线` 或 `/情绪节拍` 时，系统将：
1. 分析实际节拍对应的情节与内部情绪标注；12点图仅在该框架适用时使用；
2. 按用户指定格式输出节拍分析；未指定时可用Markdown表格，不附加未要求的图册、看板或图像文件；
3. 需要图像时用 `scripts/generate_emotion_curve.py` 绘制实际数据，标题、横轴随范围和节点数变化；不把分值区间固定解释为反杀或动作戏。

### 绘图输入与执行

脚本需要matplotlib。输入UTF-8 JSON对象，`scope`为分析范围，`beats`为按剧情先后排列的非空列表；每项包含`label`与0至10之间的有限数值`score`。例如下面只是格式示例，不是本项目的分析数据：

```json
{"scope":"格式示例：某场戏", "beats":[{"label":"发现异常", "score":3}, {"label":"选择面对", "score":6}]}
```

```text
python scripts/generate_emotion_curve.py 项目情绪曲线.png --input 实际节拍.json
python scripts/generate_emotion_curve.py 示例曲线.png --demo
```

没有实际输入且未显式选择`--demo`时停止绘图，不自动用内置示例顶替。示例图标题标注“示例数据·非项目分析”。Python调用`plot_emotion_curve(beats, output_png, scope="前90秒")`同样需要实际节拍与范围。支持一个或多个节点，保留输入顺序，不补点、不凑12个；分值只表示内部主观比较。
