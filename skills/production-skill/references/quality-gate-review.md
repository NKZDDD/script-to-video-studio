# 分层质量审查与改动复验

## 一、检查范围与等级
用户要求与已锁定项目值是验收依据。材料编译和实物生成分开，未执行层标未验证。

|等级|拦截依据|处理|
|---|---|---|
|P0 阻断当前阶段|擅改模型/画幅/SEG总长/对白核心；当前阶段必要引用缺失；实际提交未上传父图；角色身份漂移或空间无因改变；混入板面/乱码；接口能力不支持实际提交|指出具体问题、受影响任务，回补或报告方案冲突，不静默删图或拆段|
|P1 需修复|动作因果不清、实际选用物理重击缺接触反馈、镜头无法实现、人物行为与剧情目的矛盾或可见动作互相冲突、对白容量不够、有效内容不足而硬拖时长、交接动作重复或声音断裂|按用户/剧情回修受影响内容，不追加无关武打套路|
|P2 优化建议|画面信息不清、无任务空镜、表演过于抽象、声音层次不足|根据剧情提出优化，不覆盖用户风格|

30秒项目按30秒验收，不以15秒判失败；每镜无固定最低时长/数量。R3术法无需肘击，人物表演不使用情绪配方或固定阶段，顶视图只对需要的镜头启用。慢镜、定格、收尾方式依据用户与剧情。
对白取舍按dialogue-doctor-7d核查：是否仅因双方已知、直白或重复而误删有效台词；删改是否在授权内，是否保留原句意图、事实、立场与必要理解信息。不以“潜台词更高级”为由强改控诉、提醒、试探或誓言；诊断记录留在内部。
人数与复制按当前镜头、区域、取景变化和剧情状态检查；区分意外分身与合法倒影、分屏、回忆或剧情分身，不以缺固定负面句式判失败。表情按人物、剧情和画风验收，不用固定百分比、重音对齐、句尾回落或完整起落作门禁；跨镜状态须连续。表情先结束不等于吞词，声音与口型另验。

## 导演与表演复核（内部）
- 核心任务、观众情绪变化、信息揭示、关键视觉证据及段尾观看理由是否已落实到具体镜头；不以填齐术语证明完成。
- 当前视觉中心是否清楚，切镜是否有信息或情绪依据，进入退出是否合适；反应镜头和重复信息是否仍有作用，动作过程或结果是否保留必要因果。
- 人物行为是否来自当下处境、目的与关系，听者反应是否承接对方；有没有反复套用下颌、握拳、冷眼等无依据的动作，或为了去重复而抹去有意义的角色习惯。
- 表演不按动作数量、固定心理阶段、真假笑配方或克制程度验收；关键细节应在镜头中可辨，声音和身体行动不互相争抢。
- 表现补充是否在授权内、是否改变核心事实或重要人物背景；是否同步时长、空间资产与ABC。15秒或30秒不强制一个高潮，充足也不等于有效。
- 所有导演判断留内部，不进入提示词正文或擅增契约字段。机械脚本不能证明上述语义与创作质量，实际图像与视频另验。

## 二、六层验证结果分别报告
1. **材料格式**：指定契约schema、必需字段、非空任务与类型、唯一key。逐条检查图片/视频提示词正文没有内部分析、编码分级、评分、预算、审核记录、任务状态及执行说明；按model-adapters第5节转写或移出，必要参考与连续性信息保留。检查结果留在内部，用户要求时另行报告，不污染正文或擅增契约字段。引用脚本不是完整契约校验器，也不代替这项语义检查。
2. **引用关系**：正文Image、结构化引用、图片任务或复用资源及版本闭合，无自引用/循环；每个父图有可执行来源。
   父图任务在材料后面不构成引用错误；默认记录前向引用，不升级为通用V3.0硬门禁。仅对已确认要求按行执行的程序启用`audit_material_refs.py --require-parent-first`，单独查看`layers.execution_order`；该层失败不把本来合法的引用改称缺图。即使行序通过，也不能据此声称调度、父图生成或上传已验证。
   另做语义覆盖检查：逐镜核对需复用的空间、连续连接区域与动作路线是否由同源图覆盖，并正确绑定；符合asset-first-pipeline一次性独立场景豁免时不判漏图。区分任务缺失、图内区域覆盖不足、状态/动作冲突、实际上传缺失，不能仅凭key闭合宣称一致性通过。
3. **实图就绪**：实际任务已成功、文件路径存在可读、版本正确；可读不等于内容正确。
4. **实际提交**：对照最终请求/上传回执，逐图核对Image与实际素材顺序、数量、key版本、服务端可访问性。只有本地文件不代表已经上传；未取得请求证据则未验证。
5. **视觉一致**：检查运镜与走位沿途将显露的必要空间已经由同源实图覆盖，缺失则先回补；文本任务存在不等于视觉覆盖。允许可行的拉远展示全员，禁止无因补人或挪动地标。角色外形、母图、ABC与参考作用范围；同场同状态同镜头范围无竞争空间图。多场景分别保留必要图，不能删掉其他场景。
6. **成片与原段直拼**：真实起止帧、动作、对白、声音及完整文件顺序播放验收。没有成片只能验设计；图板通过不等于视频通过。

画幅分项验收：视频及ABC的A/B区按成片比例；人物4 View板按16:9或用户明确要求；场景、道具、母图、ABC容器与C区按各自记录配置核对。比例不同本身不构成错误；检查实际信息覆盖、变形及接口裁切，不能为统一尺寸丢掉必要区域。

## 现场丰富度与状态继承检查
- 人员职能、设施、物件和活动是否支撑场所用途与事件规模；不以空旷或人少本身判失败，也不按固定人数/道具数量验收。
- LOC无人但环境完整；SCSTATE落实当前现场，必要群体与临时配置在生成视频前已有可用来源，未靠视频临时补齐。
- 复用时区分同场延续、状态变化与持续损坏，旧群众不串场、旧布置不强留、损坏不无因恢复；合格现有图可复用，不每段重复出图。
- 逐镜核对可见人员与画外关系、群体区域、通路和背景活动；背景不抢主戏，特写后返回全景仍合理。材料检查不证明实际画面已达标。

## 三、ABC专项
依据 `abc-handoff-board.md` §1.1。有关联才检查板，无关联天然转场不强制ABC/后段伏笔。
- 按该文第7节运行audit_abc_flow.py并核对其检查范围：只证明已复核分类下的任务与引用拓扑，不证明分类本身、实际一次调用、图内空间或成片衔接。`incomplete`不能按通过放行，不能往外部契约添加内部审计字段。
- A表达前段尾态（与实际尾帧另核对）、B后段首镜、C该场开场空间；每边界一次生成完整ABC，共同参考可追溯，整板验收后参考同版整板生成独立A/B/C并核验，禁止先分区后合成。C在同次生成中呈现，A/B机位与C空间可解释，不宣称像素复制。
- 逐张区域图核对母板原区构图、边界、景别、机位、状态及空间；三区必须同版，偏离则不进入视频。视频不上传整板。
- 入板B/C与出板A独立图分时分域使用，出板B/C不反向控制本段。C不冻结后续动作。
- 逐区比较人物身份、左右手、持物、地标车位、脚下通路、遮挡及光向，细节必须可辨；跨板核对共同场景和合法状态演进。一次生成不等于自动通过；失败统一回修整板并同步两端，母板错误不能只改派生图掩盖；仅派生偏离时以原整板重新派生该区并核验。
- 不因镜头变更偷偷移人/车/门；不能仅用优先级文字掩盖图像矛盾。
- 无重复动作、无意外黑帧/冻结、无板面与ABC标签、无断字/重复对白、无需人工裁切补帧或混音才能成立。
- 变更同步两端视频文字、图号、版本、终态与已有成片使用记录；历史绑定不伪改。

## 四、声音
按model-adapters第5节检查发声块：每句原文有唯一明确的发声角色或剧情明确的合说者，画面、音效与原文分开，无对白或内心独白的镜头省略原文字段。实际试听逐句核对角色、内容、音色与口型；旁白误增、角色串词、朗读字段名/说明/音效名称均须修复。仅文字格式通过不能声称原生音频误读已消除；提交时核对实际输入字段，不能把整段提示词送入朗读栏。
对白清晰且说话人正确，动作音效与事件对应。0/-6/-14dB仅可作为相对混音参考，不能宣称生成器精确执行或强制所有项目一致。
原生音频选择不自动增加后期配音。字幕关闭时台词不能写成屏幕字幕。停顿、抽空和音乐按剧情与边界设计。

## 五、改动复验
局部验证→联动检查（角色/因果/资产/时长/画幅/空间/声音）→适用范围全量审核。仅做过的检查才能写通过。
内部保留实际复验结论；仅用户要求审核报告时另行交付，指定单文件JSONL时不自动追加报告，也不塞入未定义说明行。按asset-first-pipeline“交付范围”核对最终文件清单，删去未要求的附加交付物，但保留契约内必要资产任务与引用。
静态包检查只验文件/规则信号，不证明整套规则无冲突；引用审计不证明真实上传；视觉/视频需单独验收。

### 非语言人声的边界
呼吸、叹息、抽泣等按剧情需要写在现有“环境与动作声”中，说明声源人物及发生动作，只生成相应声音，不朗读名称；不是新增对白。现场对白对应口型，内心独白不做说话口型；呼吸或哭泣允许自然嘴部动作。语言人声只来自已明确绑定角色的对白/内心独白原文，不新增旁白、解说或未写台词。

引用脚本按所选契约运行：V3.0使用默认v3模式，其他格式只在内部归一后使用internal模式，适配和检查边界见asset-first-pipeline“检查输入与契约适配”；不要为通过脚本擅改用户交付格式。
