# 剧本转 AI 视频自动化生产体系 V6.1｜通用版

**本体系不绑定风格**——真人短剧、3D漫剧、二维动画都适用。视觉风格是**项目输入变量**，不是从剧本推导的结论。

```
输入：一份完整剧本 ＋ 目标视觉风格 ＋ 视频生成平台与限制
输出：可直接进入 AI 视频生产的完整项目包
```

## 何时用

用户给了剧本要做成 AI 视频；要拆段/提资产/做分镜/做故事板/写提示词；要按 segment_id 定点修订某段。

不适用：单张图片提示词、无剧情的纯素材生成。

## 最小生产单位

```
一个 15 秒段落
= 一个完整叙事单元
= 进入状态 + 剧情过程 + 退出状态 + 资产绑定
+ 正式分镜 + 故事板提示词 + 视频提示词 + 固定故事板 + 固定视频
```

段落不是随意截取的 15 秒，**必须完成一个明确任务**（角色发现秘密 / 系统完成绑定 / 关键道具出现 / 人物遭遇危机 / 能力觉醒 / 阵营关系改变）。

## 十五条全局固定原则

1. 保持原剧本的故事、人物关系、因果、结局和重要剧情点不变
2. 允许优化节奏、镜头语言、段落边界和 AI 生成适配方式
3. 不为了凑时长删除关键剧情
4. 不为了画面方便改变施动者、动作目标或动作结果
5. 人物动作和对白保持自然速度
6. 节奏通过增加信息密度和镜头切换推进，不使用机械快进
7. 默认使用有明确锚点的直接硬切
8. 不使用无意义淡入、淡出、叠化或镜头融合
9. 同一段落原则上生成一条完整视频，不强制拆成多条
10. 一个生产任务只输出一份完整、独立、可直接复制的提示词内容块
11. 提示词内部允许标题、分区、列表、换行和时间轴
12. **不把同一任务拆成主提示词/补充提示词/负面提示词让用户再组合**
13. 已成功并通过检查的资产、故事板和视频立即固定
14. 不进行自动审美重做
15. 只对技术失败、结构性错误和连续性错误进行定向修订

## 生产执行是可替换模块（环节 9-10）

出图出片只是**生产工具的运用**，不属于流程逻辑。模块契约：

- **进** = `tasks.json` + 提示词文件 + 固定资产/故事板
- **出** = 约定路径的文件 + 注册表登记

满足契约的执行器即插即用。已有实现：本仓库 `production_runner/`（本地 Web 程序，服务商可插拔、多线程）。

两个适配层不要混淆：

| 换什么 | 改哪里 | 影响 |
| --- | --- | --- |
| 换**执行器**（程序/ComfyUI/手动） | 环节 9-10 的执行方式 | 流程逻辑零影响 |
| 换**生成模型** | 环节 8 的提示词编译模板 | 仅环节 8 |

## 唯一人工确认点

**环节 1 结束后停一次**，确认：全局解析 + 视觉风格 + 解析范围标记。

- 完整系列 → `full_series + canonical`（项目级定论）
- 只有单集 → `full_episode + provisional`（暂定，后续集数到位需复核）
- 测试片段 → `test_sample + local_only`（只在测试命名空间生效）

确认后 2-8 连续跑完，不逐步问。例外：用户说「只做环节 N」。

## 十条禁止自动执行

```
禁止因为审美偏好自动重做
禁止自动修改原剧本剧情
禁止自动删除关键剧情
禁止自动改变人物关系
禁止自动更换角色身份
禁止无理由恢复不可逆状态
禁止一个错误导致整集全部重做
禁止将同一任务拆成多个需要再次组合的提示词
禁止在视频执行环节重新改写提示词
禁止用剪辑掩盖结构性剧情错误
```

## 常见错误

- ❌ 只看一集就把资产定成 canonical → ✅ 单集只能 provisional
- ❌ 把动作/表情/临时站位做成资产 → ✅ 那是状态，进状态时间线
- ❌ 段记录里写人物名调资产 → ✅ 必须用 asset_id（名称只给人看）
- ❌ 上段退出状态与下段进入状态对不上 → ✅ 段间衔接的唯一机制，必须逐对核对
- ❌ 连续性锚点重新设计来源资产的五官/服装 → ✅ 锚点只固定跨段状态或关系
- ❌ 故事板格数硬等于镜头数 → ✅ 分镜 5-8 镜、故事板 4-6 格，是采样关系
- ❌ 视频生成时把资产四视图和故事板一起传 → ✅ 默认只传故事板
