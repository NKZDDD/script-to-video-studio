# 环节 7-8：高密度正式分镜 → 故事板与视频提示词编译

# 环节 7｜高密度正式分镜

## 单段规格

```
故事板关键帧：4—6 个
正式视频镜头：5—8 个
单镜头主要信息：1 个
复杂动作：拆分为准备、结果或多个短镜头
```

> **关键帧数 ≠ 镜头数。** 分镜是视频的时间轴（5-8 镜），故事板是分镜的关键帧采样（4-6 格）。不要强行 1:1。
> 镜头时长加总必须等于段时长。

## 每个镜头必须明确（16 项）

```
镜头编号  时间范围  景别      机位      摄影机运动
画面主体  人物位置  人物动作  微表情    视线方向
道具持有人  环境变化  对白或声音
进入状态  退出状态  硬切锚点
```

## 空间连续性规则（强制）

```
保持 180 度轴线
固定阵营左右位置
固定人物进出方向
固定视线关系
固定动作运动方向
固定重要道具位置
固定人物与场景的相对关系
```

这一层是环节 11「第六层：空间轴线」检查的依据。段落开头要先写明本段的轴线与左右阵营约定。

## 七类硬切锚点

| 类型 | 例 |
| --- | --- |
| 动作锚点 | 抬手 → 下一镜完成动作 |
| 声音锚点 | 马蹄声 → 下一镜人物进入 |
| 视线锚点 | 人物看向道具 → 下一镜道具特写 |
| 物体锚点 | 刀出鞘 → 下一镜刀尖指向人物 |
| 运动方向锚点 | 人物向右冲 → 下一镜继续向右 |
| 环境锚点 | 雷声响起 → 下一镜雷云形成 |
| 状态锚点 | 视野变黑 → 下一镜黑暗空间 |

每个镜头的 `硬切锚点` 字段必须属于以上七类之一。

## AI 易错动作处理

```
复杂身体接触   多人扭打     骑乘上下动作   开门上车
递交小型道具   器物碎裂     人物被击飞     多人同时精确动作
```

统一优先改为：**动作准备 → 直接硬切 → 动作结果**

**不能因此删除动作因果。**

# 环节 8｜故事板与视频提示词编译

文本生产阶段的最终输出。**只编译不创作**——内容全部来自上游产物的拼装。

## 每个 SEG 输出三部分

```
一、参考图上传顺序
二、完整故事板提示词
三、完整视频提示词
```

## 故事板提示词固定结构（十节）

```
创建项目名称、集数、段落编号的有序多关键帧故事板。
一、输出结构        六、关键帧顺序
二、参考图角色映射   七、进入状态
三、身份与资产绑定   八、退出状态
四、视觉风格        九、连续性限制
五、空间与轴线      十、输出限制
```

**第三节的人物/场景描述必须从资产注册表原样复制**，禁止重新组织语言——重写就漂移。
第六节的首格 = 段落进入状态，末格 = 段落退出状态。
第十节含技术避错句 + 禁止画面文字（格内镜头编号除外，故事板是中间参考物）。

## 视频提示词固定结构（七节）

```
使用固定故事板作为唯一主视觉参考。
一、基础输出          五、动作和穿模控制
二、人物、场景和状态连续性  六、段落边界
三、完整时间轴        七、禁止内容
四、镜头与硬切规则
```

写法要点：

- 第二节**点名具体特征**（"左脸颊 2.5 厘米浅褐色疤痕全程可见"），不写"保持人物一致"这类空话
- 第三节用**自然语言连续叙述**，不用字段式；对白写进时间轴并标说话人
- 第六节：末尾画面必须停在 exit_state（下一段衔接的依据）
- 第七节含 `forbidden_future` 的防剧透项 + 画面文字禁令

## 视频参考原则

故事板固定后，生成视频时**默认只上传** `Image 1 = 当前 SEG 固定故事板`。

不重复上传基础资产（四视图/九视图/道具/连续状态图）——身份、空间、道具、状态信息已整合进固定故事板。多传反而造成：人物身份重新混合、故事板构图被资产图覆盖、模型把四视图误当视频画面、场景空间重构、关键帧顺序失效。

只有**系统文字、商品包装或微小关键道具**无法从故事板稳定读取时，才增加**一张**辅助参考图，并在提示词开头写明：

```
Image 1 控制：人物、场景、构图、镜头顺序、动作顺序和状态。
Image 2 只控制：指定文字或关键细节。
Image 1 优先级高于 Image 2。
```

## 执行任务清单（tasks.json）

三种提示词是给模型看的；再产出一份**机器可读**的任务清单，让任何执行器消费同一套输入：

```json
{
  "asset_tasks":      [{"key","prompt_ref","reference_images":[{"image_n","asset_id","file_ref"}],"params","output"}],
  "storyboard_tasks": [{"key","prompt_ref","reference_images":[...],"params","output"}],
  "video_tasks":      [{"key","prompt_ref","storyboard_ref","aux_reference","params","output"}]
}
```

`reference_images` 的 `image_n` 顺序 = 提示词 ROLE MAP 的 Image 编号，执行器按此顺序上传即自动满足逐张核对要求。
