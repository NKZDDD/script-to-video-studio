# 环节 4-6：资产提取与生产判断 → 资产生产与固定 → 段落资产绑定

---

# 环节 4｜资产提取与生产判断

决定哪些视觉内容需要成为独立固定资产。**核心是过滤，不是全都做。**

## 五类资产

| 类 | 固定什么 | 包含 |
| --- | --- | --- |
| **1 身份资产** | 这个对象是谁 | 主要人物、重要配角、固定群体、特殊生物、长期坐骑或召唤物 |
| **2 环境资产** | 故事发生在哪里 | 长期场景、反复出现的房间、村庄、街道、公司、宫殿、战场、系统空间 |
| **3 固定剧情道具** | 重要物品长什么样 | 武器、文件、信物、产品、车辆、容器、系统界面、特殊标志 |
| **4 连续性状态资产** | 同一对象当前是什么状态 | 人物倒地/受伤/被控制、群体站位、场景破坏、道具破碎、角色觉醒 |
| **5 动态元素** | 通常不生产，提示词控制 | 普通尘土、烟雾、临时光线、雨水、短暂火花、衣摆/头发摆动 |

## 动态元素升级为连续状态资产的六个条件（满足任一即升级）

```
会跨越多个段落持续
后续剧情依赖该状态
状态不可逆
容易被模型错误恢复
需要固定精确位置
会影响人物、道具或场景关系
```

## 输出：资产生产任务队列

```
asset_id          asset_type          parent_asset_id
identity_anchors  inherited_attributes  changed_attributes
locked_attributes output_spec_id      dependency_order
```

**第 4 环节内部保留决策过程，但不传给第 5 环节**——环节 5 只接任务队列。配角、群演、临时道具应判为不生产并记录理由。

# 环节 5｜资产生产与固定

## 生产顺序（五批）

```
第一批：主要人物与固定群体
第二批：特殊生物与坐骑
第三批：基础场景
第四批：固定剧情道具
第五批：连续性状态资产
```

**必须先生产父资产，再生产状态资产。**

## 父资产与状态资产关系

```
人物身份资产 → 受伤状态 → 昏迷状态 → 觉醒状态
基础场景     → 雨天状态 → 雷暴状态 → 破坏后状态
完整道具     → 开启状态 → 空置状态 → 破碎状态
```

> **状态资产不得重新设计父资产。** 写状态资产时先原样复述父资产的 `identity_anchors`，再描述本状态的差异。这是防"换脸"的关键机制。

## 资产提示词输出原则

每个资产**单独输出一份完整提示词**，内部包括：

```
资产名称    输出结构    参考图角色映射    身份绑定
外观与结构  材质        基础状态或剧情状态
允许改变内容  禁止改变内容  使用场景  输出限制
```

## 输出规格

| 规格 | 内容（默认约定，可在项目参数覆盖） |
| --- | --- |
| 人物/生物四视图 | 一张竖版图 2×2：左上正面全身、右上侧面全身、左下背面全身、右下正面半身特写；纯浅灰摄影棚背景、均匀柔光；四视图脸型发型服装体态完全一致 |
| 场景 | 空镜定场图，无人物 |
| 立体道具 | 正/侧/45° 三视图，纯色背景 |
| 平面道具 | 正面 + 使用状态 |
| 附属特征 | 特写 + 在人物身上的位置示意 |

## 强制收尾句

每份资产提示词末尾必带：
`超高清，细节清晰，避免手部畸形、多余手指、多余肢体、模糊面部。画面内不得出现任何文字、字母、数字、标注、水印。`

## 固定机制

每个资产只生成 **1 个结果**；不生成候选组；asset_id 绑定唯一文件；生成后直接 `fixed`；不自动覆盖（要改走环节 11 的定向修订）。

# 环节 6｜段落资产绑定

**本环节不生产新资产**，只决定每个 SEG 使用哪些资产、以什么顺序上传。

## 每段绑定内容

```
段落编号：            参考图上传顺序：
Image 1：  Image 2：  Image 3：  …
各参考图控制范围：     基础资产与状态资产的优先级：
进入状态使用资产：     退出状态使用资产：
不应上传的无关资产：
```

## 参考图五级优先级

```
第一优先级：人物或对象身份资产
第二优先级：连续状态资产
第三优先级：场景资产
第四优先级：道具资产
第五优先级：提示词控制的临时动态
```

## 冲突处理（强制规则）

| 冲突 | 以谁为准 |
| --- | --- |
| 身份资产与状态资产的**脸**不一致 | 身份资产 |
| 身份资产与状态资产的**姿态**不一致 | 状态资产 |
| 场景参考与状态图中的**建筑**不一致 | 基础场景资产 |
| 道具父资产与本段状态不一致 | 本段指定状态 |

## 编号规则

**每个 SEG 重新从 Image 1 开始编号。** 不建立整集永久 Image 编号，避免上传大量无关资产。单段参考图控制在 5 张以内为宜——过多会导致人物身份混合。

## 强制

名称只用于人工查看，**真正调用资产必须使用 asset_id**。引用的 asset_id 必须在注册表中真实存在且 `status: fixed`；找不到就回环节 4 补，不要临时编造。
